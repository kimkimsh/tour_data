# 01 — 공공데이터포털 API 키 받기 (한국관광공사 + 기상청)

> **키는 이미 있다.** 이 문서를 다시 보는 경우는 **키가 만료됐거나, 데이터셋을 새로 신청할 때**다. 평소 운영은 [`05_operations.md`](./05_operations.md)에 있다.
>
> **끝나면:** `.env.local` 파일에 키 한 줄이 들어가고, `pnpm probe`가 돌아간다.
> **걸리는 시간:** 신청 30분 + 승인 대기 (자동승인이면 즉시, 아니면 1–2일)
> **돈:** 무료

---

## 무엇을 받는 것인가

**공공데이터포털**(data.go.kr)에서 발급하는 인증키 하나다. 정부가 운영하는 사이트이고, 한국관광공사와 기상청이 거기에 데이터를 올려 두었다.

키는 **하나**인데, **쓰려는 서비스마다 따로 신청**해야 한다. 이 서비스는 11개를 쓰므로 신청을 11번 하고, 승인되면 그 11개를 **같은 키 하나로** 부른다.

> **키가 동작하는데 어떤 API만 안 되는 경우가 정상이다.** 게이트웨이는 경로를 먼저 보고 키를 나중에 본다. 그래서 `resultCode 12`는 「그 주소에 서비스가 없다」(코드 문제)이고, `resultCode 30`은 「주소는 맞는데 그 키에 그 서비스 권한이 없다」(신청 문제)다. 둘 다 「등록되지 않은…」처럼 읽히지만 해야 할 일이 정반대다.

**신청 단위는 「서비스」이지 「오퍼레이션」이 아니다.** 신청 화면에 오퍼레이션 목록이 체크박스로 나오는데 **전부 체크된 상태가 기본이다. 아무것도 체크 해제하지 말 것** — 체크한 것마다 하루 호출 한도가 따로 붙으므로, 체크를 유지하는 데 드는 비용이 없다.

---

## 1단계 — 회원가입

1. https://www.data.go.kr 접속
2. 오른쪽 위 **회원가입**
3. **일반 회원**으로 가입 (기업/개인 구분이 나오면 개인)
4. 이메일 인증까지 마친다

---

## 2단계 — API 11개 신청

**신청은 API 하나씩 따로 한다.** 아래 11개를 순서대로 하면 된다.

각 API마다 하는 일은 똑같다:

1. 검색창에 **아래 표의 검색어**를 넣는다
2. 결과에서 **「오픈API」** 탭을 고른다 (「파일데이터」가 아니다 — 이건 엑셀 다운로드고 우리가 쓸 게 아니다)
3. 목록에서 해당 API를 클릭
4. 오른쪽 위 **[활용신청]** 버튼
5. **활용목적**: `개인 프로젝트 / 무장애 관광 정보 서비스 개발` 정도로 적으면 된다
6. **[신청]**

### 한국관광공사 8개

**데이터셋 번호로 바로 가는 게 가장 빠르다** — `https://www.data.go.kr/data/{번호}/openapi.do`. 검색어는 이름이 비슷한 「파일데이터」가 섞여 나와서 헷갈린다.

| # | 데이터셋 | 포털에 뜨는 이름 | 코드가 부르는 서비스ID | 이게 없으면 |
|---|---|---|---|---|
| 1 | `15101897` | **한국관광공사_무장애 여행 정보** | `KorWithService2` | ★★★ **무장애 항목 24개 전부가 안 온다.** 이 서비스의 존재 이유 |
| 2 | `15101578` | **한국관광공사_국문 관광정보 서비스_GW** | `KorService2` | 관광지 이름·주소·소개글·사진이 안 온다 |
| 3 | `15101753` | **한국관광공사_영문 관광정보서비스_GW** | `EngService2` | 영어 화면의 제목이 안 온다 (한글 이름으로 대체됨) |
| 4 | `15101971` | **한국관광공사_관광지 오디오 가이드정보_GW** (=오디/Odii) | `Odii` | 도슨트(음성 안내) 화면이 빈다 |
| 5 | `15128555` | **한국관광공사_관광지 집중률 방문자 추이 예측 정보** | `TatsCnctrRateService` | 혼잡도 예측이 「정보 없음」이 된다 |
| 6 | `15101972` | **한국관광공사_빅데이터_지역별 방문자수_GW** | `DataLabService` | 갭 리포트의 방문자 수 절이 빈다 |
| 7 | `15128560` | **한국관광공사_관광지별 연관 관광지 정보** | `TarRlteTarService1` | 「관련 관광지」 절이 통째로 빈다 |
| 8 | `15101914` | **한국관광공사_관광사진 정보_GW** (=관광사진갤러리) | `PhotoGalleryService1` | 갤러리 사진이 안 붙는다 |

> **일문·중문은 신청하지 않는다.** 앞선 판은 `15101760`(일문)과 `15101764`(중문간체)를 9·10번으로 올려 두었다. 화면도 데이터도 한/영 2종으로 확정되면서 코드에서 뺐다 ([`docs/spec/01_scope.md`](../spec/01_scope.md) §4.2). 나중에 되살리려면 그 두 개를 신청하고 `src/lib/kto/services.ts`의 상수 두 곳에 넣으면 된다.

**1번이 압도적으로 중요하다.** 나머지는 화면 일부가 비는 정도이고, 1번이 없으면 이 서비스가 할 말이 없어진다.

**5번의 이름에 속지 말 것.** 「집중률 방문자 추이 예측」과 6번 「지역별 방문자수」는 **다른 데이터셋이다.** 5번은 관광지 한 곳 단위의 **향후 30일 예측 지수**이고, 6번은 시군구 단위의 **실측 일별 방문자 수**다. 서로 대체되지 않는다.

**지역 코드 체계가 두 가지다.** 1·2·3번(관광정보 계열)은 한국관광공사 자체 코드를 쓰고, 5·6·7번은 **행정표준코드**를 쓴다. 충청남도가 전자에서는 `34`, 후자에서는 `44`다. 공주시 `44150`, 부여군 `44760`. 섞어 넣으면 오류가 아니라 **빈 목록**이 온다.

### 9~11번 — 기상청 3종

| # | 데이터셋 | 서비스 이름 | 코드가 부르는 서비스ID | 이게 없으면 |
|---|---|---|---|---|
| 9 | `15000415` | **기상청_기상특보 조회서비스** | `WthrWrnInfoService` | 「기상 특보」 항목이 영원히 빈다 |
| 10 | `15084084` | **기상청_단기예보 조회서비스** | `VilageFcstInfoService_2.0` | 「당일 기상 예보」 항목이 빈다 |
| 11 | `15059468` | **기상청_중기예보 조회서비스** | `MidFcstInfoService` | 4~10일 뒤 날씨 안내가 빈다 (점수에는 안 들어간다) |

**한국관광공사 것과 신청 방법이 똑같다.** 세 개 모두 개발계정 자동승인이고, 다른 점은 이것들이다:

- 코드가 실제로 부르는 오퍼레이션은 셋뿐이다 — 기상특보의 **`getPwnStatus`**(`src/lib/kma/warnings.ts:20`), 단기예보의 **`getVilageFcst`**, 중기예보의 **`getMidLandFcst`·`getMidTa`** (`src/lib/kma/forecast.ts`). 나머지는 체크된 채로 두면 된다
- **하루 한도가 오퍼레이션당 10,000건**이다 (한국관광공사 개발계정은 1,000건). 하루 한 번 도는 이 서비스에는 남아돈다
- **이용허락범위가 공공누리 제1유형(출처표시)**이다. 한국관광공사 것은 제한 없음이라 화면에 「기상청」 출처를 반드시 적어야 하는 쪽은 이 셋뿐이다
- **10·11번은 지역 지정 방식이 또 다르다.** 단기예보는 5km 격자 번호(공주 `63,102` · 부여 `59,99`), 중기예보는 예보구역 코드(육상 `11C20000` = 대전·세종·충남, 기온은 공주 `11C20402` · 부여 `11C20501`). 전부 `src/lib/kma/forecast.ts`에 상수로 박혀 있다
- **파라미터 규칙이 한국관광공사와 다르다.** `MobileOS`·`MobileApp`이 없고, JSON을 받으려면 `_type=json`이 아니라 **`dataType=JSON`**이다. 코드가 알아서 갈라 보낸다 (`src/lib/kto/transport.ts:231`)

> **왜 「특보현황조회」인가 — 이게 함정이다.** 이름만 보면 `특보코드조회`가 구조화된 데이터라 더 좋아 보이는데, **기상청이 직접 「현재 발효 중인 특보를 주는 API가 아니다」라고 답했다** (data.go.kr Q&A). 게다가 **조회 창이 6일로 막혀 있고 7일 뒤 자료가 삭제된다.**
>
> 그래서 **폭염경보가 6일 넘게 이어지면 마치 특보가 없었던 것처럼 나온다.** 공주·부여의 7~8월에는 그게 예외가 아니라 정상이다. 무장애 서비스에서 거짓 「특보 없음」은 안전 실패라, 이 코드는 확인에 실패하면 「없음」이 아니라 **「모름」**으로 남긴다.

> **한 번 신청하면 여러 개가 같이 열린다는 말은 사실이 아니다.** 앞선 판은 관광사진갤러리와 관련관광지가 「국문 관광정보 계정으로 함께 열리는 경우가 많다」고 적어 두었는데, 2026-09-13에 같은 키로 재봤더니 그 둘은 `30 SERVICE_KEY_IS_NOT_REGISTERED_ERROR`였다. **11개 전부 따로 신청해야 한다.** 그래서 위 표에 7·8번으로 올려 두었다.

### 승인까지

- 대부분 **자동승인**이라 신청 즉시 쓸 수 있다
- 일부는 **1–2일** 걸린다
- **마이페이지 → 오픈API → 개발계정** 에서 상태를 볼 수 있다

---

## 3단계 — 키 복사 ★ 여기가 함정이다

1. **마이페이지 → 오픈API → 개발계정** 으로 간다
2. 신청한 API 아무거나 하나 클릭
3. 화면에 **인증키가 두 줄** 보인다:

```
일반 인증키(Encoding)   aBcD%2FeFgH%2BiJkL...
일반 인증키(Decoding)   aBcD/eFgH+iJkL...
```

**반드시 아래쪽 「Decoding」을 복사한다.**

### 왜 이게 함정인가

두 줄은 **같은 키의 다른 표기**다. Encoding 쪽은 `/`를 `%2F`로, `+`를 `%2B`로 미리 바꿔 놓은 것이다.

그런데 이 코드는 키를 URL에 넣을 때 **자기가 알아서 그 변환을 한다.** 그래서 이미 변환된 Encoding 키를 넣으면 **두 번 변환**된다:

```
%2F  →  %252F      ← '%'가 다시 '%25'로 바뀐다
```

서버는 이걸 못 알아보고 이렇게 답한다:

```
resultCode 30  등록되지 않은 서비스키
```

**이 메시지가 사람을 속인다.** 「등록되지 않은」이라고 하니 신청이 안 됐거나 키가 잘못된 줄 알고 다시 발급받으러 가게 되는데, 키는 멀쩡하고 **형태만 틀린 것**이다.

> 이 프로젝트에서 환경변수 이름을 `KTO_SERVICE_KEY_DECODING`이라고 길게 지은 것도 그 때문이다. 이름 자체가 어느 쪽을 넣어야 하는지 말하게 했다.

## 4단계 — 키를 파일에 넣기

프로젝트 폴더 맨 위에서:

```bash
cp .env.example .env.local
```

`.env.local`을 열고 이 줄을 찾아 `=` 뒤에 붙여넣는다:

```
KTO_SERVICE_KEY_DECODING=여기에_Decoding_키를_붙여넣는다
```

**주의할 것 세 가지:**

- **따옴표를 붙이지 않는다.** `KTO_SERVICE_KEY_DECODING="aBcD..."` ← 따옴표까지 키의 일부로 읽힌다
- **`=` 앞뒤에 띄어쓰기를 넣지 않는다**
- **키 끝에 공백이나 줄바꿈이 딸려 오지 않았는지 본다.** 웹에서 복사하면 자주 딸려 온다

`.env.local`은 `.gitignore`에 들어 있어서 **git에 절대 올라가지 않는다.** 키가 실수로 공개될 걱정은 안 해도 된다.

## 5단계 — 확인

```bash
pnpm probe
```

### 잘 됐을 때

체크 9개가 순서대로 돌고, 결과가 `docs/spec/_probe-results.md`에 쓰인다. 각 줄이 `pass` / `partial` / `fail` 중 하나로 나온다.

**`fail`이 나와도 키 문제가 아닐 수 있다.** 예를 들어 「이 관광지가 무장애 데이터셋에 없다」는 것도 하나의 답이고, probe는 그걸 정상적으로 보고한 것이다. 다음 문서에서 그 결과를 어떻게 읽는지 나온다.

### 키가 없을 때

```
ingest: KTO_SERVICE_KEY_DECODING is not set. Put the DECODING form of the key
in .env.local — the ENCODING form is re-encoded by URLSearchParams and the
gateway answers resultCode 30.
```

→ 4단계를 안 했거나 파일 이름이 `.env.local`이 아니다. `.env`나 `.env.example`이 아니라 **`.env.local`**이어야 한다.

### `resultCode 30`이 나올 때

**원인이 두 가지고, 구별하는 방법이 있다.**

**(a) 전부 30이면 — Encoding 키를 넣었다.** 3단계로 돌아가 Decoding 쪽을 복사한다.

**(b) 일부만 30이면 — 그 서비스를 신청하지 않았다.** 키는 멀쩡하다. 2단계 표에서 그 서비스만 신청하면 된다. 승인·동기화에 30분쯤 걸린다.

한 줄로 확인하는 방법 — `KorService2`가 `0000`이고 문제의 서비스만 `30`이면 (b)다:

```bash
set -a; . ./.env.local; set +a
curl -s -G "https://apis.data.go.kr/B551011/KorService2/areaCode2" \
  --data-urlencode "serviceKey=$KTO_SERVICE_KEY_DECODING" \
  -d MobileOS=ETC -d MobileApp=ModuBaekje -d _type=json -d numOfRows=1
```

`pnpm ingest`의 경고 줄에도 어느 서비스가 막혔는지 서비스ID까지 그대로 찍힌다:

```
warn  gongsanseong: gallerySearchList1 failed — PhotoGalleryService1/gallerySearchList1?…:
      gateway fault envelope — SERVICE_KEY_IS_NOT_REGISTERED_ERROR / 등록되지 않은 서비스키
```

### `resultCode 22`가 나올 때

→ 하루 호출 한도(오퍼레이션당 1,000건)를 넘었다. **내일 다시 하면 된다.** 개발계정 기본 한도이고, 이 프로젝트는 하루 한 번 도는 것을 전제로 만들어져 있어서 정상 사용에서는 안 걸린다.

### `resultCode 12`가 나올 때

→ 그 API가 없어졌다는 뜻이다. **사람이 봐야 하는 상황이다** — 나한테 알려 달라. (이 코드는 이 경우 재시도하지 않는다. 자동으로 처리하면 안 되는 종류의 실패라서.)
