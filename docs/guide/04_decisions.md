# 04 — 결정해야 할 5가지 → **전부 결정됨 (2026-09-07)**

> **결과: 1-B · 2-A · 3-B · 4-B · 5-B.** 다섯 개 다 코드에 반영됐다. 무엇이 어떻게 바뀌었는지는 [`../work_log/04_open_items.md`](../work_log/04_open_items.md) §4에 있다.
>
> **2번만 내 의견과 다르게 결정됐다** — 나는 기상 특보를 항목에서 빼자고 했는데(점수가 최대 1점밖에 안 움직여서), 실제 날씨를 붙이는 쪽으로 정해졌다. 붙였다.
>
> 아래는 결정할 때 본 자료 그대로 남긴다. 왜 그렇게 정했는지 나중에 되짚을 때 쓴다.

> **이 문서가 무엇인가**
> 내가 혼자 정할 수 없는 것 5개다. 기술 문제가 아니라 **「방문자에게 무엇이 정직한가」** 또는 **「어디까지 만들 것인가」**의 문제라서 그렇다.
>
> **각 항목마다 실제 숫자를 계산해서 붙였다.** 어림짐작이 아니라 지금 데이터로 돌려 본 값이다. 읽고 A/B 중 하나만 골라 주면 된다.

**급한 순서:** 1번 → 2번 → 4번 → 3번 → 5번. 1번만 정해도 화면이 바뀐다.

## 1. 부소산성의 엘리베이터를 어떻게 적을 것인가 ★ 제일 급함

### 상황

부여군 공식 편의시설 표에 「장애인 전용 엘리베이터: 없음」이라고 적혀 있다. 이걸 그대로 **「없음」**으로 넣어 두었다.

그런데 **부소산성은 야외 산성이다.** 산에 엘리베이터가 없는 건 「시설을 안 갖춘 것」이라기보다 「원래 그런 지형」에 가깝다.

### 실제로 계산해 본 차이 (휠체어 이용자 기준)

| | 라벨 | 점수 | 막힌 항목 |
|---|---|---|---|
| **A. 지금 그대로 (「없음」)** | **대체추천** = 「다른 곳 권장」 | 39점 | 엘리베이터 |
| **B. 「해당 없음」으로 바꾸면** | **주의** = 「확인하고 가세요」 | 42점 | 없음 |

**점수 3점 차이는 중요하지 않다. 라벨이 바뀌는 게 중요하다.**

- **A**를 고르면 휠체어 이용자에게 부소산성은 **「가지 마세요」** 목록에 들어간다
- **B**를 고르면 **「가도 되는데 몇 가지 확인하세요」**가 된다

### 판단 근거

**A(지금)를 고를 이유:** 이유가 무엇이든 **휠체어로 산 위까지 못 올라가는 건 사실**이다. 「해당 없음」으로 빼면 그 사실이 점수에서 사라지고, 방문자는 왜 못 가는지 모른 채 「주의」만 보게 된다.

**B를 고를 이유:** 부소산성은 **입구 쪽(부소산문 → 삼충사 방향)은 휠체어로 갈 수 있다.** 경로 안내에도 그렇게 적혀 있고, 낙화암 갈림길에서 되돌아 나오는 코스다. 엘리베이터 하나 때문에 **갈 수 있는 부분까지 통째로 「가지 마세요」가 되는 것**은 과한 판정일 수 있다.

### 내 의견

**B(해당 없음)를 권한다.** 다만 조건이 하나 있다 — **「왜 해당 없음인지」를 문장으로 남긴다.** 예를 들면:

> 「야외 산성으로 건물이 없어 엘리베이터가 해당되지 않습니다. 낙화암·고란사 방향은 경사가 심한 돌길이라 휠체어·유아차로는 갈 수 없습니다.」

이러면 **못 가는 구간이 있다는 사실은 그대로 남고**, 엘리베이터라는 엉뚱한 이유로 전체가 막히는 것만 없어진다. 실제로 못 가는 구간은 경로 안내가 이미 정확히 짚고 있다.

> **B를 고르면 다른 야외 유적도 같이 봐야 한다.** 정림사지·공산성도 같은 상황일 수 있다. 원칙을 하나 정하면 6곳에 일관되게 적용하겠다.

**→ 결정: A / B**

## 2. 기상 특보를 어떻게 할 것인가

### 상황

무장애 항목 32개 중 **「기상 특보」 하나가 영원히 비어 있다.** 기상청 API를 붙인 데가 없어서다.

이걸 그냥 두면 6곳 전부 그 항목이 「정보 없음」으로 남는다.

### 실제로 계산해 본 차이

기상 특보 항목을 아예 뺐을 때 점수 변화:

```
공산성        41점 → 41점   (변화 없음)
무령왕릉      54점 → 55점   (+1)
공주박물관    53점 → 53점   (변화 없음)
부소산성      39점 → 39점   (변화 없음)
정림사지      49점 → 49점   (변화 없음)
부여박물관    44점 → 44점   (변화 없음)
```

**거의 아무 차이가 없다.** 「상황」 축의 가중치가 0.10이고 그 안에 항목이 4개라, 하나가 빠져도 전체에 미치는 영향이 미미하다.

### 두 선택

**A. 기상청 API를 붙인다**
- 외부 의존이 하나 늘어난다 (API 신청 하나 더, 코드 한 벌 더, 실패 처리 하나 더)
- 얻는 것: 위 표에서 보듯 **점수는 거의 안 바뀐다.** 대신 「오늘 태풍 특보가 있다」를 화면에 띄울 수 있다

**B. 항목에서 뺀다 (32개 → 31개)**
- 스펙 §4.1이 32를 못 박고 있어서 **스펙을 고쳐야 한다**
- 「정보 없음」이 하나 줄어서 화면이 조금 더 깨끗해진다

### 내 의견

**B(빼기)를 권한다.** 이유는 점수가 아니라 **정직함** 쪽이다.

지금 상태는 「우리가 이 항목을 본다」고 화면에서 말해 놓고 **한 번도 채운 적이 없는** 것이다. 32개 중 31개는 실제로 값이 오는데 하나만 구조적으로 안 온다면, 그 하나는 항목 목록에 있으면 안 된다.

**다만 A가 매력적인 경우가 하나 있다** — 심사에서 「실시간성」을 보여주고 싶을 때. 나머지 데이터가 전부 하루 한 번 수집인데 기상 특보만 실시간이면 그게 눈에 띈다. **그게 목적이라면 A가 맞다.**

**→ 결정: A / B**

## 3. 무장애 인증(Layer C)을 어떻게 할 것인가

### 상황

스펙에 **「무장애 인증을 받은 곳은 점수를 조금 올려 준다」**는 규칙이 있다. 그런데 **6곳 중 1곳에만 적용된다.**

```
공산성        인증 없음
무령왕릉      열린관광지 (2023년 지정)   ← 유일
공주박물관    인증 없음
부소산성      인증 없음
정림사지      인증 없음
부여박물관    인증 없음
```

무령왕릉의 실제 효과: **54점 → 57점** (보정 1.04배)

### 왜 하나뿐인가

인증을 못 찾은 게 아니라 **찾았는데 안 넣었다.** 두 가지 이유다:

**첫째, 등급이 안 맞는다.** 공개된 자료는 「예비 인증 / 본 인증」 둘로만 구분하는데, 스펙은 「예비 / 일반 / 우수」 셋을 원한다. 「본 인증」이 일반인지 우수인지 알 수가 없다.

**둘째, 이게 더 중요한데 — 인증이 건물에 붙어 있다.** 확인된 인증은 전부 **방문자센터, 화장실** 같은 부속 건물에 대한 것이다. 그걸 그대로 넣으면 **「화장실이 인증받았으니 이 관광지 점수를 올려 준다」**가 된다. 이 서비스가 하지 말자고 만든 종류의 일이다.

### 두 선택

**A. 인증 데이터를 제대로 채운다**
- 각 인증이 **어느 건물**에 대한 것인지 확인하고, 관광지 전체에 대한 것만 넣는다
- 등급 문제는 국가유산청이나 보건복지부에 문의해서 확인한다
- **시간이 꽤 든다.** 6곳 × 확인 작업이고, 답이 「전부 부속 건물」로 끝날 수도 있다

**B. Layer C를 스펙에서 내린다**
- 점수 계산이 **A × B** 두 층으로 단순해진다 (지금은 A × B × C)
- 무령왕릉이 57점 → 54점이 된다. 라벨은 안 바뀐다(둘 다 「주의」)

### 내 의견

**B(내리기)를 권한다.**

지금 상태가 제일 나쁘다 — **규칙은 살아 있는데 6곳 중 1곳에만, 그것도 「열린관광지」 하나로만 작동한다.** 심사위원이 「이 인증 보정은 무슨 기준입니까」라고 물으면 답할 게 없다.

**A를 고를 만한 경우:** 6곳을 넘어 관광지를 늘릴 계획이 있다면 인증 데이터는 나중에 값을 한다. **지금 6곳으로 심사만 볼 거면 B다.**

**→ 결정: A / B**

## 4. 제보 신고 기능을 누구에게 열 것인가

### 상황

방문자 제보 옆에 **「신고」** 버튼이 있다. 욕설이나 허위 제보를 운영자에게 알리는 버튼이다.

지금은 **로그인 없이 아무나** 누를 수 있다.

### 무엇이 문제인가

**한 사람이 모든 제보를 전부 신고하면 신고 기능이 무의미해진다.**

관리자 화면은 기본으로 「신고된 것 먼저」 순서로 보여준다. 전부 신고되면 그 정렬이 아무것도 구분하지 못한다.

**그리고 이게 계산해 보니 생각보다 나빴다.** 관리자 화면은 한 번에 200건까지만 보여주고 페이지 넘기기가 없다. 신고가 264건이면:

```
상위 200건 = 전부 신고된 것
신고 안 된 제보가 나타나는 위치 = 없음
```

**운영자가 「최신순」으로 바꾸지 않는 한 새 제보를 하나도 못 본다.**

### 세 선택

**A. 그대로 둔다**
- 실제 심사 기간에 이런 공격이 올 가능성은 낮다
- 아무것도 안 해도 된다

**B. 로그인한 사람만 신고할 수 있게 한다** ← 권함
- 제보를 **올리려면** 어차피 익명 세션이 필요하다. 신고만 세션 없이 되는 게 오히려 일관성이 없다
- 「로그인」이라고 했지만 회원가입이 아니다 — 버튼을 누르면 자동으로 이름 없는 세션이 생긴다. **방문자 입장에서 달라지는 게 없다**
- 스펙에 `anon, authenticated`라고 적혀 있어서 **스펙을 한 줄 고쳐야 한다**

**C. 신고에도 「하루 한 번」 제한을 건다**
- 제일 확실하지만 **테이블이 하나 늘어난다.** 4주 범위에서는 과하다

### 내 의견

**B.** 방문자가 느끼는 차이는 없고, 고칠 것은 SQL 한 줄과 스펙 한 줄이다.

**→ 결정: A / B / C**

## 5. 영어 라벨 32개를 검토해 줄 사람이 있는가

### 상황

무장애 항목 32개에 영어 이름을 붙였다. **스펙에 없던 것을 내가 추가한 것이고, 원어민이나 이 분야 전문가가 검토하지 않았다.**

국제적으로 통용되는 표현을 고르려고 했지만 확인받지 않았다:

| 한국어 | 내가 붙인 영어 | 확신도 |
|---|---|---|
| 점자블록 | Tactile paving | 높음 — 국제 표준 용어 |
| 객실(청각) | Room for deaf guests | **낮음** — 「hearing-accessible room」이 더 맞을 수도 |
| 유도 안내 설비 | Wayfinding system | 중간 |
| 보조견 동반 | Guide dog access | **낮음** — 「service animal」이 더 넓은 표현 |

같은 문제가 갭 리포트의 상태 표시에도 있다 (`Partly available`, `Structural constraint (confirmed)`).

### 두 선택

**A. 검토받는다** — 장애인 관련 단체나 영어 사용자에게 목록을 보여주고 확인받는다. 30분이면 되는 일이다

**B. 그대로 간다** — 영어 화면은 심사 대상이 아닐 수도 있다

### 내 의견

**심사에 영어 화면이 포함되면 A, 아니면 B.**

**그 자체로는 급하지 않다.** 다만 이 서비스가 「정확한 정보」를 주장하는데 영어 라벨이 틀려 있으면 그 주장에 흠이 간다. 특히 `Room for deaf guests`는 영어권에서 어색하게 들릴 가능성이 있다.

**→ 결정: A / B**

## 정리 — 한 줄씩

| # | 무엇 | 내 의견 | 고르면 걸리는 시간 |
|---|---|---|---|
| 1 | 부소산성 엘리베이터 | **B** (해당 없음 + 이유 문장) | 10분 |
| 2 | 기상 특보 | **B** (항목에서 빼기) | 30분 |
| 3 | 무장애 인증 | **B** (Layer C 내리기) | 1시간 |
| 4 | 신고 권한 | **B** (로그인한 사람만) | 20분 |
| 5 | 영어 라벨 | 심사 범위에 따라 | 30분 |

**다섯 개 다 「B」를 권하는 게 우연이 아니다.** 전부 같은 이유다 — **작동하지 않는 기능을 켜 둔 채로 두는 것보다, 없다고 말하는 편이 정직하다.** 이 서비스가 정보를 다루는 방식과 같은 원칙이다.

## 답을 주는 방법

이렇게만 적어 주면 된다:

```
1: B (이유 문장은 네가 초안 써 줘)
2: B
3: A — 관광지를 늘릴 계획이 있음
4: B
5: B — 심사는 한국어만
```

**반대해도 된다.** 위는 내 판단이고, 특히 1번과 3번은 「이 서비스가 무엇을 주장하는 서비스인가」에 달린 문제라 네가 정하는 게 맞다.

한 가지만 확인하고 싶다 — **1번을 읽고 A와 B가 방문자에게 각각 어떻게 보일지가 그려지나?** 거기가 이 문서에서 제일 중요한 부분인데, 내가 「대체추천」·「주의」라는 화면 용어를 설명 없이 쓴 것 같아서 묻는다.
