# 플로우 제주(Flow Jeju) - 관광 흐름 분산 운영체제

## 한 줄 제안
제주 인기 관광지가 붐빌 때, 같은 취향의 덜 붐비는 대체 관광지와 주변 소비 동선을 자동 제안해 관광객 만족도와 지역 분산 효과를 동시에 높이는 데이터 기반 여행 플래너.

## 제출 추천도
1순위 대상 후보. 제주 자체 데이터 인프라가 가장 강하고, 공모전의 "데이터 가치를 서비스로 실현"한다는 슬로건에 가장 정면으로 맞는다. 단순 일정 추천이 아니라 혼잡 회피, 지역상생, 체류 분산을 하나의 점수 체계로 설명할 수 있어 서류 심사에서 논리 구조가 강하다.

## 기획 배경 및 필요성
제주는 국내 대표 관광지이지만 관광객이 특정 명소와 특정 시간대에 몰리는 구조적 문제가 있다. 유명 카페, 해변, 오름, 동부와 서부 핵심 명소는 주차, 대기, 환경 훼손, 주민 불편을 만들고, 반대로 덜 알려진 지역 관광자원과 로컬 상권은 충분한 방문을 받지 못한다.

기존 여행 앱은 "가볼 만한 곳"을 추천하지만, 사용자가 실제 현장에 도착했을 때 붐비면 다시 검색해야 한다. 한국관광공사 API와 제주 자체 데이터는 이미 관광지, 방문자, 연관 관광지, 집중률, 관광 수요를 제공하므로, 이를 묶어 "지금 어디로 흐름을 바꿀 것인가"를 판단하는 서비스가 가능하다.

## 핵심 사용자
| 사용자 | 문제 | 제공 가치 |
| --- | --- | --- |
| 제주 렌터카 가족 여행객 | 유명지를 찍어도 주차와 대기 때문에 일정이 무너짐 | 혼잡도를 피한 대체 코스와 예상 이동시간 제공 |
| 뚜벅이, 버스 여행객 | 대체 관광지를 알아도 이동 가능 여부 판단이 어려움 | 대중교통 가능 동선과 체류시간 기준 추천 |
| 제주 로컬 상권 | 인기 명소 주변 외 지역 방문이 약함 | 관광객 분산을 통한 지역 소비 유도 |
| 제주 RTO, 지자체 | 관광 흐름과 과밀 지점을 서비스적으로 조정하기 어려움 | 대시보드로 분산 추천 성과 확인 |

## 주요 기능
1. 혼잡 예측 지도
   - 주요 관광지와 권역을 쾌적, 보통, 혼잡, 과밀 4단계로 표시한다.
   - 실시간이라고 과장하지 않고, KTO 집중률 예측과 방문자 통계를 바탕으로 한 "예상 쾌적도"로 표현한다.

2. 같은 취향 대체 관광지 추천
   - 사용자가 성산일출봉, 협재해수욕장, 카페거리처럼 특정 목적지를 선택하면 신분류체계, 지리적 거리, 연관 관광지 정보를 기준으로 대체지를 제안한다.
   - 대체지는 단순히 덜 유명한 곳이 아니라 "같은 여행 목적을 충족하는 곳"이어야 한다.

3. 지역상생 동선 점수
   - 관광지 하나를 추천하는 것이 아니라 음식점, 카페, 시장, 산책 코스까지 이어지는 2~4시간 단위 동선을 제시한다.
   - 추천 카드에 쾌적도, 이동 가능성, 날씨 적합도, 지역 분산 기여도를 함께 표시한다.

4. 일정 붕괴 방지 리플랜
   - 비, 강풍, 혼잡, 운영시간 변경 등으로 일정이 깨졌을 때 현재 위치와 남은 시간 기준으로 대체 동선을 다시 만든다.
   - 여행자의 체류시간과 귀가 위치를 반영해 "무리하지 않는 코스"를 우선한다.

5. 제주 관광 흐름 대시보드
   - 공모전 최종심사에서 강하게 보일 기능이다.
   - RTO 관점에서 과밀 회피 추천 횟수, 대체지 클릭률, 권역별 분산 기여, 예상 소비 유도 지표를 보여준다.

## 추천 알고리즘 초안
대체 관광지 점수는 다음 5개 요소로 설명한다.

| 요소 | 설명 | 가중치 예시 |
| --- | --- | --- |
| 테마 유사도 | 신분류체계와 콘텐츠 타입이 원래 목적지와 얼마나 유사한가 | 25% |
| 혼잡 완화 효과 | 원래 목적지 대비 예상 집중률이 얼마나 낮은가 | 25% |
| 이동 가능성 | 현재 위치, 남은 시간, 교통수단 기준으로 방문 가능한가 | 20% |
| 날씨 적합도 | 실내/실외, 해안/산간, 우천/강풍 조건에 맞는가 | 15% |
| 지역상생 점수 | 방문 분산 필요 권역, 소비 강도, 주변 상권 연결성이 높은가 | 15% |

핵심은 AI가 막연히 일정을 생성하는 것이 아니라, 공공데이터 기반 점수 산식이 있고 그 산식이 화면에 설명된다는 점이다. 심사위원에게 데이터 활용의 적절성을 보여주기 쉽다.

## 5페이지 제안서 압축 구성
1. 1페이지: 제주 관광 흐름 문제와 서비스 한 줄 정의
2. 2페이지: 사용자 여정과 핵심 화면 3개
3. 3페이지: KTO API 활용 구조와 점수 산식
4. 4페이지: 지역특화, 차별성, 기존 서비스 대비 우위
5. 5페이지: 개발 일정, 확장성, 기대효과

## 차별성
- 기존 KTO AI콕콕이나 일반 AI 여행 플래너는 사용자의 선호 일정 생성에 가깝다. Flow Jeju는 관광객 흐름을 바꾸는 운영 로직이 핵심이다.
- 기존 제주 대체 관광지 아이디어가 관광객 관점에 머문다면, 이 서비스는 관광객 화면과 RTO 대시보드를 동시에 제공한다.
- 공공데이터를 "목록 노출"이 아니라 의사결정 점수로 쓰므로 데이터 활용 20점을 설명하기 쉽다.

## 리스크와 대응
| 리스크 | 대응 |

| 혼잡도 데이터가 실시간이 아닐 수 있음 | "실시간 혼잡도" 대신 "예상 쾌적도"와 "데이터 기준일"을 표시한다. |

| 대체 추천이 낯선 관광지를 밀어준다는 불신 | 왜 추천했는지 테마, 이동시간, 쾌적도, 주변 소비처를 함께 설명한다. |
| 제주 자체 데이터 연동 일정 | KTO API만으로 MVP를 완성하고, 제주데이터허브는 고도화 데이터로 단계 적용한다. |

## 기대효과
- 관광객: 대기와 주차 스트레스를 줄이고 만족도를 높인다.
- 지역: 특정 명소 쏠림을 줄이고 주변 상권 방문을 늘린다.
- KTO/RTO: 관광데이터가 실제 행동 변화를 만드는 사례를 확보한다.
- 서비스 사업화: 제주 이후 부산 해변권, 강원 산악권, 경북 유적권 등 혼잡/분산 이슈가 있는 지역으로 확장 가능하다.
