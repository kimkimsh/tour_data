# 제로클락 펄스(Zero Clock Pulse) - 대전 0시축제 혼잡분산·상권회유 네비게이터

## 한 줄 제안
대전 0시축제 방문객에게 현재 혼잡, 공연 시간, 이동 가능성, 주변 로컬 상권을 반영한 실시간 회유 동선을 제공해 축제 만족도와 원도심 소비를 동시에 높이는 축제 운영형 관광 서비스.

## 제출 추천도
2순위 대상 후보. 대전은 2026 특별상 RTO 권역에 포함되어 있고, 0시축제, 사이언스페스티벌, 빵축제, 국제와인엑스포처럼 도시 브랜드가 축제 IP에 집중되어 있다. 2026년 5월 서류 제출 후 여름 축제 시즌에 실제 데이터를 수집하고 10월 기능심사 전까지 검증 사례를 만들 수 있다는 점이 강하다.

## 기획 배경 및 필요성
대전은 과학도시, 빵, 야간축제, 와인 등 도시 브랜드를 축제와 이벤트 중심으로 강화하고 있다. 축제형 관광은 짧은 시간에 방문객이 몰리기 때문에 단순 관광정보보다 현장 운영 문제가 크다. 방문객은 어떤 무대가 붐비는지, 어디서 쉬어야 하는지, 다음 공연까지 어떤 상권을 방문하면 좋은지, 귀가 교통을 놓치지 않으려면 언제 이동해야 하는지 판단하기 어렵다.

RTO와 지자체 입장에서는 방문객을 한 구역에만 머물게 하는 것보다 원도심 골목, 빵집, 과학문화 콘텐츠, 야간관광 지점으로 분산시켜 체류시간과 소비를 늘리는 것이 중요하다. Zero Clock Pulse는 축제 운영 관점과 관광객 UX를 연결하는 서비스다.

## 핵심 사용자
| 사용자 | 문제 | 제공 가치 |
| --- | --- | --- |
| 축제 방문객 | 공연과 맛집을 모두 가고 싶지만 현장 혼잡과 이동시간을 모름 | 지금 갈 곳, 피할 곳, 쉬어갈 곳을 바로 안내 |
| 가족, 고령자 동반 방문객 | 혼잡한 구간과 귀가 동선이 부담 | 저혼잡 동선, 화장실, 휴식지, 귀가 알림 제공 |
| 외지 관광객 | 대전 로컬 상권과 축제 맥락을 모름 | 빵, 과학, 와인, 야간관광 테마 미션 제공 |
| 대전 RTO, 운영사 | 특정 무대와 구역에 인파가 몰림 | 회유 추천과 대시보드로 혼잡 분산 유도 |

## 주요 기능
1. 축제 펄스 맵
   - 행사장, 무대, 포토존, 화장실, 쉼터, 지하철역, 버스정류장, 로컬 상권을 지도에 표시한다.
   - 혼잡 수준은 직접 측정값이 없을 경우 일정, 시간대, 사용자의 체크인, 데이터랩 방문자 추세를 결합한 추정값으로 표시한다.

2. 다음 90분 회유 추천
   - "지금 중앙무대가 붐비면 45분 동안 빵집 거리와 과학문화 스팟을 들렀다가 다음 공연 15분 전에 복귀"처럼 시간 제한형 동선을 제안한다.
   - 축제 서비스는 하루 일정 생성보다 다음 30~90분의 판단이 중요하므로 기능 범위가 명확하다.

3. 귀가 실패 방지 알림
   - 사용자가 마지막 열차, 버스, 주차 위치, 숙소 위치를 등록하면 귀가 버퍼를 계산한다.
   - 축제 서비스의 실용성을 높이는 기능이며 최종심사에서 이용 편의성으로 어필 가능하다.

4. 로컬 상권 미션
   - 빵집, 전통시장, 과학 굿즈, 와인바, 야간 카페 등 대전 정체성에 맞는 회유 미션을 제시한다.
   - 단순 쿠폰이 아니라 혼잡 분산을 위한 동선 설계 수단으로 설명한다.

5. 운영자 대시보드
   - 구역별 클릭, 추천, 회유, 혼잡 경보, 상권 전환율을 시각화한다.
   - 기능심사에서 "관광객 앱 + 축제 운영 도구" 양면성을 보여줄 수 있다.

## 서비스 로직 초안
사용자에게 특정 시간의 "최고 관광지"를 추천하는 것이 아니라, 축제장 전체를 살아있는 흐름으로 보고 다음 행동을 결정한다.

| 판단 요소 | 설명 |
| --- | --- |
| 시간 적합성 | 다음 공연, 예약, 귀가 시간까지 여유가 있는가 |
| 혼잡 회피 | 사용자가 가려는 구역의 예상 혼잡이 높은가 |
| 상권 연결성 | 근처 로컬 상권이나 실내 휴식처로 자연스럽게 이동 가능한가 |
| 회귀 가능성 | 다음 목적지나 귀가 위치로 돌아오기 쉬운가 |
| 날씨 안전성 | 폭염, 비, 미세먼지 상황에서 무리 없는가 |

## 5페이지 제안서 압축 구성
1. 1페이지: 축제 현장의 혼잡, 대기, 귀가, 상권 분산 문제
2. 2페이지: 관광객 앱 화면과 핵심 사용자 여정
3. 3페이지: KTO API와 대전 공공데이터 결합 구조
4. 4페이지: 축제 운영자 대시보드와 지역경제 기대효과
5. 5페이지: 개발 일정, 실증 계획, 전국 축제 확장성

## 차별성
- 기존 일정 플래너는 여행 전 계획에 강하지만 축제 현장의 "지금 어디로 움직일지"에는 약하다.
- 지역 관광 앱은 정보를 보여주지만 혼잡 분산과 상권 회유라는 운영 목표를 직접 다루지 않는다.
- 대전은 2026 협업 RTO 권역에 포함되어 있고, 0시축제라는 강한 지역 IP가 있어 지역특화 서술이 선명하다.

## 기대효과
- 방문객은 현장에서 덜 헤매고, 안전하게 즐기고, 귀가 실패를 줄인다.
- 대전 원도심 상권은 공연 대기시간의 유입을 얻는다.
- RTO는 축제 운영 데이터를 확보하고 다음 축제 기획에 반영할 수 있다.
- KTO 입장에서는 TourAPI가 단순 정보 제공을 넘어 지역축제 운영 문제를 해결하는 사례가 된다.
