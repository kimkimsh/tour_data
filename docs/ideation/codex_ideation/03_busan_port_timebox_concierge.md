# 부산 포트타임(PortTime Busan) - 크루즈·KTX·공항 환승객 반나절 관광 컨시어지

## 한 줄 제안
부산항, 부산역, 김해공항으로 들어온 외래·환승 관광객에게 남은 시간 안에 반드시 복귀 가능한 반나절 코스를 다국어로 자동 구성하는 시간보장형 관광 컨시어지.

## 제출 추천도
3순위 대상 후보. 부산은 국제관광도시, 크루즈, KTX, 해변, 시티투어, Big-데이터웨이브 등 서류에 쓸 재료가 많다. 다만 부산 혼잡·맛집 추천류는 이미 수상 사례와 아이디어가 많으므로, "항구·역·공항 도착객의 제한시간 문제"로 좁혀야 차별성이 산다.

## 공모전 배점 대응
| 심사항목 | 대응 전략 |
| --- | --- |
| 서비스 기획력 30 | 외래관광객과 환승객의 "시간 안에 돌아와야 한다"는 구체 문제를 겨냥한다. |
| 서비스 완성도 30 | 도착/출발 입력, 시간보장 코스, 복귀 버퍼, 다국어 카드, 지도 화면으로 MVP가 명확하다. |
| 데이터 활용 20 | KTO 다국어 TourAPI, 국문 TourAPI, 위치기반 관광정보, 축제, 사진, 부산 공공데이터를 결합한다. |
| 발전성 20 | 부산에서 검증 후 인천공항, 제주항, 강릉역, 여수항 등 다른 관문형 관광지로 확장 가능하다. |
| 지역특화 가점 | 부산관광공사 특별상 권역. 국제관광도시와 부산항이라는 지역성이 뚜렷하다. |

## 기획 배경 및 필요성
부산은 국내 대표 해양관광 도시이며 외국인, 크루즈, KTX, 공항 접근성이 모두 강하다. 하지만 환승객과 단기 체류객은 "몇 시간이 남았는지", "짐을 들고 갈 수 있는지", "돌아오는 시간이 안전한지", "언어가 통하는지"가 핵심이다. 일반 관광 앱은 인기 순위와 장소 정보를 보여주지만, 제한시간과 복귀 리스크를 중심으로 코스를 짜주지는 않는다.

PortTime Busan은 여행지 추천 서비스가 아니라 시간 보장형 관광 컨시어지다. 사용자가 도착지, 출발지, 남은 시간, 언어, 이동수단, 관심사를 입력하면 복귀 실패 가능성이 낮은 코스만 추천한다.

## 핵심 사용자
| 사용자 | 문제 | 제공 가치 |
| --- | --- | --- |
| 크루즈 관광객 | 항구 복귀 시간이 엄격하고 현지 교통을 잘 모름 | 복귀 버퍼가 포함된 안전 코스 |
| KTX 당일 관광객 | 부산역 주변에서 어디까지 다녀올 수 있는지 판단이 어려움 | 2시간, 4시간, 6시간 코스 자동 구성 |
| 공항 환승객 | 짐, 교통, 언어 부담 때문에 도심 방문을 포기함 | 공항 기준 반나절 코스와 다국어 안내 |
| 부산 RTO | 관문 방문객을 도심과 상권으로 전환하고 싶음 | 체류시간별 추천과 전환 성과 확인 |

## 주요 기능
1. 시간보장 코스 생성
   - 출발지와 복귀지, 복귀 마감 시간, 이동수단을 입력하면 방문 가능한 POI만 필터링한다.
   - 코스 카드에는 관광시간, 이동시간, 복귀 버퍼, 실패 위험도를 함께 표시한다.

2. 다국어 관광 카드
   - KTO 영문, 일문, 중문 관광정보를 우선 활용하고, 부족한 항목은 국문 데이터를 번역 보조한다.
   - 장소 설명, 주문 문장, 택시 기사에게 보여줄 문장, 긴급 문구를 큰 글씨 카드로 제공한다.

3. 짐 부담 없는 동선
   - 역, 항구, 공항, 짐 보관 가능 지점, 엘리베이터, 대중교통 접근성을 고려해 코스를 나눈다.
   - 직접 예약이나 결제는 MVP에서 제외해 구현과 법적 리스크를 줄인다.

4. 부산 테마 퀵루트
   - "2시간 부산역 주변", "4시간 해운대", "6시간 감천문화마을+시장", "비 오는 날 실내", "야간 전망"처럼 즉시 선택 가능한 코스를 제공한다.
   - 축제나 행사 기간에는 `searchFestival2` 기반 이벤트를 코스 후보에 넣는다.

5. 복귀 알림과 리플랜
   - 현재 위치와 남은 복귀시간을 기준으로 더 이상 다음 장소를 추가하면 위험한 시점을 알려준다.
   - 지연이 발생하면 가장 가까운 복귀 경로와 대체 짧은 코스를 제안한다.

## 5페이지 제안서 압축 구성
1. 1페이지: 관문형 관광객의 제한시간 문제와 부산 지역성
2. 2페이지: 사용자 여정과 핵심 화면
3. 3페이지: KTO 다국어 API와 부산 공공데이터 활용 방식
4. 4페이지: 기존 관광 앱 대비 차별성과 실용성
5. 5페이지: 개발 일정, 법적 리스크 최소화, 확장 모델

## 차별성
- 부산 갈맷길, 해변, 맛집 추천과 달리 PortTime은 "관문 도착객"과 "복귀 시간"을 핵심 제약으로 삼는다.
- 외국인 대상 서비스이지만 번역 앱이 아니라 KTO 다국어 관광정보와 지도/시간 계산을 결합한 관광 실행 도구다.
- 예약, 결제, 커머스를 초기에 넣지 않아 3인 팀이 기능 완성도에 집중할 수 있다.

## 리스크와 대응
| 리스크 | 대응 |
| --- | --- |
| 정확한 실시간 교통 예측 어려움 | 보수적 복귀 버퍼를 적용하고 도보/대중교통/택시별 위험도를 표시한다. |
| 다국어 데이터 누락 | 다국어 TourAPI 우선, 누락 시 국문 데이터 기반 요약 번역을 명확히 표시한다. |
| 외국인 개인정보, GDPR | 회원가입 없는 익명 사용을 기본으로 하고 위치 권한은 1회성으로 처리한다. |
| 직접 예약 기능의 관광사업 등록 리스크 | MVP에서는 예약, 결제, 중개를 제외하고 외부 링크만 제공한다. |

## 기대효과
- 부산 관문 방문객의 도심 전환율과 체류시간 증가
- 외국인 관광객의 언어, 시간, 복귀 불안 감소
- RTO 관점의 체류시간별 추천 데이터 확보
- 향후 크루즈 선사, 역, 공항, 관광안내소 키오스크와 연결 가능
