## 2. 사용자 핵심 지적 — F1 4단계 카드의 한계

> "단순 4단계 카드(방문 가능/주의/정보 없음/대체 추천) 출력만으로는 부족. 더 상세한 배리어프리를 위한 기능과 서비스가 있어야 한다."

**Claude 해석**: 무장애 서비스의 가치는 **"갈 수 있는 곳을 분류해주는 것"**(classification)이 아니라 **"갈 때 함께 따라가는 것"**(현장 동반 도구)에 있다. 4단계 라벨은 카드의 한 영역일 뿐, 카드 전체는 사용자가 현장에서 어떻게 갈지 결정·실행 가능한 풍부한 도구여야 한다.

**v3 대응 — F1을 5 sub-feature로 풍부화**:
- **F1.A POI 무장애 상세 카드** — 4단계 라벨 + 출입구별 사진/경사도 + 휠체어 회전 가능 영역 폴리곤 + 점자블록·음성 안내 시스템 경로 + 휴식 인프라 + 장애인 화장실 사진 + 응급 인프라 + 페르소나×필드 5×21 매트릭스 + 부재 사유 2분류 라벨
- **F1.B 단계별 음성·시각 내비** — GPS 50m 단위 안내, 단계 안내 카드, 음성 모드, 자막 모드, 픽토그램 일정 카드
- **F1.C 무장애 SOS · 보조기기 · 장애인콜택시** — SOS 버튼 + 보조기기 대여 표시 + 콜택시 호출 + 휴식·약 알림 + 이상 감지 (발전방향)
- **F1.D 시간 예산 6단 모드 + 적합도 산식 v3** — 4 Layer 구조 (POI 본질 7축 × 페르소나 매트릭스 × 인증 보정 × 신뢰도 감쇠)
- **F1.E 페르소나별 후기 분리 + 무장애 동선 GPX 환류** — 휠체어/시각/청각/인지 별도 후기, 검수 통과 동선 GPX

v3에서 추가된 F1.B/F1.C/F2 점자·수어 sub-feature는 **모두 KTO API에 없는 영역**:
- **F1.B 도보 50m 단위 음성 내비** — KTO에 도보 길찾기 부재 → 카카오 모빌리티 100% 의존
- **F1.C 장애인콜택시 호출** — KTO에 콜택시 정보 부재 → 한국교통안전공단·시군 시스템 의존
- **F1.C 보조기기 대여** — KTO `wheelchair` 필드는 보유 여부만, 대여소 정보 부재 → 한국장애인개발원·복지센터 의존
- **F2 점자 호환 텍스트(.brf)** — KTO에 점자 콘텐츠 부재 → 한국점자도서관·국립국어원 의존
- **F2 수어 영상** — KTO에 수어 영상 부재 → 국립국어원 한국수어사전·서울관광재단 다누림 의존
- **F1 STT 음성 검색** — KTO에 STT 부재 → Clova/Whisper 의존
- **F1.B 픽토그램 일정 카드** — KTO에 픽토그램 부재 → KS 픽토그램 표준 의존

→ **"KTO API로 가능한 것 + KTO API로 불가능한 영역의 외부 보강"**이 v3의 데이터 활용 방안 정합성 핵심. 이는 Codex v2 비평("비KTO 데이터가 실제 기능에 들어가야 20점 만점")의 정확한 실증.
