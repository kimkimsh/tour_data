# 14 시연·PT 전략 (Demo & Presentation Strategy)

> **범위**: SPEC §12 + 제안서 부록 D (D.1–D.7) 구체화. 개발자·발표자 모두가 이 문서 한 장으로 "무엇을 언제 어떻게 보여주는가"를 알 수 있도록 작성. 채점 루브릭 대응까지 포함.
>
> **SPEC 12 핵심 인용** (절대 변경 불가):
> > _"한 번 수집한 무장애 데이터가 여행 전 판단, 현장 안내, 교육 기록, 다음 방문자의 경고, 충남의 시설 개선 우선순위까지 연결됩니다."_
> 이 한 문장이 PT 전체 키 메시지이며, 모든 시연 장면은 이 문장의 한 절(節)을 증명하는 구조로 배치된다.

|---|:--:|---|:--:|

| **1차 완성도** | 30 | D.1 골든 플로우 사전 녹화 PRIMARY + 3개 히어로 모먼트 라이브(§13.8) + D.2–D.6 보조 시연 작동 + 오프라인 fallback 시연 | 27–28 |
| **1차 데이터활용** | 20 | D.1 샷 1: 4-Layer 근거 카드에 `detailWithTour2` 필드명·출처·날짜 노출; F5 갭 대시보드로 마무리 | 20 |

| **PT 발표** | 15 | 12분 + 3분 Q&A 구성, 판사 추적 포인트 3개 이하로 집중 | 14–15 |

## 2. PT 키 메시지 구조

### 2.1 One-liner (슬라이드 상단 고정, 모든 장면 반복)

> **"한 번 수집한 무장애 데이터가 F1 여행 전 판단 → F2 현장 안내 → F3 사용자 제보 → F4 교육 기록 → F5 충남 시설 개선 우선순위까지 연결됩니다."**

각 시연 장면은 이 흐름의 하나의 절(節)을 라이브로 증명한다. 증명 순서는 반드시 F1→F5이며 역순 또는 임의 순서 배치 금지 (루브릭 논리성 직결).

### 2.2 3분 오프닝 구조 (발표 15점)

```
[00:00–00:30] 문제 정의
  KTO 「모두의 여행」·Wheelmap이 멈춘 곳:
  "이 관광지에 휠체어가 들어갈 수 있는가" = POI 단위 정적 분류.
  [화면 side-by-side: 좌 = Wheelmap 단일 핀(○/△/×) / 우 = 모두의 백제 4-Layer 근거 카드]
  → "핀 하나 vs 4-Layer 근거 카드" 시각 대비로 차별화 즉시 각인.
  실제 질문은 5가지 — (a) 시간 예산 안에 동선이 이어지는가
                       (b) 현장 엘리베이터 고장이 다음 방문자에게 전달되는가
                       (c) 자녀 체험학습 자료를 만들 수 있는가
                       (d) 외국인이 다국어 도슨트로 백제를 이해할 수 있는가
                       (e) 충남 RTO가 어느 시군 데이터가 부족한지 볼 수 있는가

[00:30–01:00] 제품 정의
  「모두의 백제」 = 충남 공주·부여 6 POI 무장애 헤리티지 관광 OS.
  한 번 수집한 무장애 데이터가 F1→F5 5축을 관통한다.
  [이 시점에 F1→F5 흐름 다이어그램 슬라이드 노출, 이후 모든 시연 장면에서 현재 위치 하이라이트]

[01:00–03:00] D.1 첫 장면 (샷 0) — 사전 녹화 영상 위 내레이션 진입 (SPEC §13.8)
  진입점은 사전 입력(타이핑/탭) 결과로 시작 — 데모 안정성 우선.
  음성 입력(STT)은 "KWCAG 2.2 다중 입력 진입점" 기능으로 소개하되, 데모 진입은 STT에 의존하지 않음.
  이후 D.1 전체 흐름은 녹화 영상으로 연속 재생, 라이브는 §6 히어로 모먼트 3개만.
```

### 2.3 클로징 문장 (반드시 D.1 샷 7 직후)

> "AI 기본법 2026년 1월 22일 시행. KWCAG 2.2 자체점검은 출시일부터. 무장애 여행이 자녀의 교육 산출물로 남고, 다음 사용자가 그대로 따라갈 수 있는 검증된 코스로 환류되며, 충남 RTO의 시설 개선 우선순위 데이터가 되는 — 한 번 수집한 무장애 데이터가 F1→F5 전체를 관통하는 첫 서비스입니다."

## 3. D.1 골든 플로우 — 샷-바이-샷 데모 스크립트

**페르소나**: 휠체어 70대 할아버지(P1a + P1b) + 시니어(P1b 만성질환) + 초등 손녀(P3 + 쉬운글 옵션)
**시나리오**: 충남 공주 도착 → 반나절 공산성 → 1박 2일로 전환 → 부여 부소산성 → 손녀 다이어리 → F5 CACF 대시보드

### 샷 0 — 음성 입력 + 페르소나 다중 선택 (KWCAG 자체점검)
**루브릭 포인트**: 기획력(STT · 접근성 우선 설계) + PT 적정성(KWCAG 2.2 직결)

| 단계 | 화면 / 액션 | 강조 포인트 |
|---|---|---|
| 0-a | 첫 화면 로드. 배경 색상 대비 4.5:1 명도비 수치 오버레이 즉시 노출 | KWCAG 2.2 § 1.4 색상 대비 준수 시각 증명 |
| 0-b | (녹화 영상) 마이크 버튼 탭 → 할아버지 음성: *"휠체어로 갈 수 있는 반나절 공주 코스 찾아줘"*. **라이브 데모 진입은 사전 타이핑/탭 입력** (SPEC §13.8); STT는 KWCAG 다중 입력 기능으로 소개 | STT = 기능 시연(녹화). 라이브 진입점 = 텍스트. 모바일 44pt 터치 타깃 |
| 0-c | P1a(휠체어) + P1b(시니어) + P3(가족·초등) 세 페르소나 자동 선택 제안 → 할아버지 확인 탭 | 다중 페르소나: 교집합 패널티 룰 설명 1줄 |
| 0-d | axe-core CI 통과율 배지(33검사항목 %) 화면 하단 고정 노출 | 자체점검 = 자동화 + 수동 NVDA 검증 병행 |

**개발 전제 조건**:
- STT 결과가 `PersonaId[]` + `TimeBudget` 파라미터로 파싱되어야 함.
- `axe-core` 통과율은 CI 빌드 시 집계 후 `public/a11y-badge.json`에 저장; 화면에서 fetch 렌더링.

### 샷 1 — F1.D 시간 예산 6단 + F1.A 4-Layer 근거 카드
**루브릭 포인트**: 데이터활용 20점(KTO 필드 노출) + 기획력(투명 근거 카드)

| 단계 | 화면 / 액션 | 강조 포인트 |
|---|---|---|
| 1-a | 슬라이더: "반나절 (180분)" 선택. 공산성 공주 POI 카드 자동 표시 | 시간 예산 6단 템플릿(`itinerary_templates` 행) 작동 |
| 1-b | 공산성 적합도 카드 오픈. 상단: 4-Layer 근거 카드 토글 버튼 탭 | **"왜 이 점수인가"를 한눈에** |
| 1-c | Layer A 세부: `detailWithTour2` 필드명 원문(`wheelchair`, `exit`, `elevator`, `restroom`) + 상태(`supported`/`partial`/`unknown`) + 출처일 노출 | 데이터활용 직결. KTO 필드 = 시각 증명 |
| 1-d | Layer B 패널: 페르소나×필드 매트릭스 일부 (P1a critical 4개 × P1b critical 4개) | 다중 페르소나 교집합 패널티 적용 시각화 |
| 1-e | Layer C: BF 인증 일반등급 + 열린관광지 가산 배지 (가산값·상한·가드는 `16_suitability_policy.md` §5 단일 권위) | 인증이 점수에 구체적으로 얼마만큼 기여하는지. 인증 단독으로 라벨 경계 이동 불가 (§13.1 가드) |
| 1-f | Layer D: 최근 갱신일 + 신뢰도 감쇠 비율 노출. "최종 확인 2026-05-21" | 데이터 신선도 투명 공개 |
| 1-g | 하단: 출입구별 사진(서문 평탄 / 북문 계단) + 휠체어 회전 폴리곤 지도 레이어 | 사진 = `PhotoGalleryService1` (공공누리 1유형) 출처 표기 자동 |
| 1-h | 응급의료 800m, AED 420m 배지. 벤치 4개, 실내 휴게 1개, 화장실 200m 간격 인프라 표 | P1b 만성질환 직결 피로도 정보 |

**개발 전제 조건**:
- `calculateSuitability()` 반환 값(권위: `16_suitability_policy.md` §1 / `packages/domain/policy/types.ts`): `{ score, label, layerA..D, axes[], evidenceConfidence, coverage, deductions, knownCriticalBlockers, alternatives, policyVersion, dataDates }` — 프론트엔드 카드가 `axes[]`(per-axis 기여)·`deductions`·`dataDates`·`evidenceConfidence`를 직접 렌더링.
- 4-Layer 토글 UI는 `<details>/<summary>` + `aria-expanded` 패턴 (KWCAG § 2.4 키보드 내비).
- 사진마다 `cpyrhtDivCd` 저장 필수; Type3(변경금지) 사진은 crop/필터 없이 원본 표시.

### 샷 2 — F1.B 사전 베리어프리 경로 + F3 검수 통과 알림
**루브릭 포인트**: 완성도(UGC→검수→알림 파이프라인) + 실용성(오프라인)

|---|---|---|
| 2-a | 화면 상단: 노란 배너 "어제 제보 검수 완료: 공산성 동문 공사 중 — 서문 이용 권장" (Supabase Realtime 알림) | F3 → F1.B 파이프라인 라이브 증명 |
| 2-b | "서문 진입 안내 보기" 탭 → F1.B 경로 카드 5단계 슬라이드 | 정적 사전 검수 경로: 자동 재계산 X, 관리자 승인 O |
| 2-c | 단계 카드 1: "서문 입구 (평탄 30m, 점자블록 유, 사진: [서문 입구 사진])" | 각 단계 = 1행동 + 사진 + 거리 + 노면 정보 |
| 2-d | 단계 카드 4: "만하루 진입로 우회 (경사 6° 우회로 → 북쪽 평탄 경로, 사진: [경사도 수치 표기 사진])" | 우회로 존재 = 사전 검수 데이터 가치 |
| 2-e | "오프라인 저장" 버튼 탭 → 공산성 가이드 패키지(사진+텍스트+GPX) 기기 저장 | Serwist IndexedDB 영속 저장; 네트워크 0 상태에서 재오픈 시연 |
| 2-f | (옵션) 비행기 모드 전환 후 동일 단계 카드 재오픈 → 동일 내용 표시 | 오프라인 완주 증명 = PT 완성도 직결 |

- 오프라인 번들: POI당 `[poi_id]/guide.json` + 사진 Blob IndexedDB 키 패턴.

- Odii 커버리지 없는 POI → 자체 TTS(국가유산청 텍스트 → CLOVA Voice) fallback 파이프라인 준비.

### 샷 4 — 시간 예산 전환: 반나절 → 1박 2일
**루브릭 포인트**: 실용성(시간 예산 적응) + 완성도(동일 템플릿 패밀리)

| 단계 | 화면 / 액션 | 강조 포인트 |
|---|---|---|
