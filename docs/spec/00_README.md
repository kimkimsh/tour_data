## 1. 왜 다시 썼는가

이전 기획 세트(`SPEC.md` + 01~16번 문서, 약 700KB)는 2026년 6월 14~15일에 작성됐다. 그때의 전제는 이랬다.

| 기존 전제 | 지금 현실 |
|---|---|
| 3.5개월 (6/14 ~ 9/30) 개발 기간 | **약 4주** (9/1 ~ 9월 말). 공고문 기준 서비스 개발은 5~9월이고 1차 기능심사는 10월 중 |
| 18개 워크스트림, 스트림별 담당자 배정 | **1명 + AI**. 코드 0줄 |
| 5개 계약 문서를 동결하고 순서대로 착수 | 계약 동결 의식(儀式)을 유지할 사람이 없음. `git diff`가 유일한 조율 수단 |
| 현장 실측(경사도·회전반경·단차) 후 데이터 입력 | 공주·부여 답사 일정 없음 |
| 관광약자 전문가·점자 전문가·수어 전문가 서명 검수 | 섭외된 전문가 없음 |
| 충남문화관광재단(CACF) 업무협약(LOI) 7월 말까지 확보 | 미확보 |
| 충남교육청 체험학습 서식 PDF 확보 | 미확보 |

기존 문서에는 좋은 내용이 많다. 특히 **적합도 산식**(이 스펙 06번의 원본)과 **"빈 값을 '불가'로 추론하지 않는다"** 원칙은 이 서비스의 핵심이고 그대로 가져왔다. 다만 그 위에 얹힌 조율 장치·검증 게이트·콘텐츠 물량이 지금 조건에서는 **작동 불가능한 상태로 남아 있어**, 그대로 두면 "게이트를 통과 못 해서 아무것도 못 내보내는" 결과가 된다.

### 실제로 발견한, 그대로 두면 사고 나는 것들

이건 취향 문제가 아니라 **버그**다.

1. **현장 검증 게이트가 서비스를 마비시킨다.** 이전 스펙은 접근성 항목을 "검증됨"으로 발행하려면 *2차 승인자 서명*이 필요하다고 못 박았다. 혼자서는 2차 승인자를 만들 수 없다. 그러면 모든 항목이 `unknown`이 되고, 모든 관광지가 `정보없음` 라벨을 받고, **점수 화면이 전부 빈 화면이 된다.**
2. **`sensory`라는 존재하지 않는 축.** 산식 문서 §2에서 7개 항목이 `axis: sensory`로 분류돼 있는데, 출력 타입(`AxisContribution.axis`)에는 `sensory`가 없다. 코드로 옮기면 컴파일 에러.
3. **축 안의 세부 가중치가 정의된 적이 없다.** "정책 JSON에 있다"고 쓰여 있지만 그 JSON은 작성된 적이 없다.
4. **PDF 파일 전체 SHA-256 골든 테스트는 100% 실패한다.** PDF에 생성 시각이 박히므로 빌드마다 해시가 바뀐다.
5. **`detailWithTour2` 필드가 "21개"라고 여러 문서에 적혀 있다.** 실제 매뉴얼(v4.3) 확인 결과 **24개(+기타 4개)** 다.
6. **Odii 좌표 파라미터가 `xCoord`/`yCoord`라고 적혀 있다.** 실제 매뉴얼(v4.1)은 **`mapX`/`mapY`** 다. 그대로 짜면 전부 빈 응답.
7. **관광지 집중률 API 지역코드가 `areaCd=34`(충남), 부여 `34800`이라고 적혀 있고 공주는 "TBD"로 남아 있다.** 실제 코드표 파일 확인 결과 **행정표준코드**를 쓴다 — 충남 `44`, **공주 `44150`, 부여 `44760`**. TBD였던 항목이 해소됐다.
8. **제보 중복방지 인덱스가 PostgreSQL에서 실행되지 않는다.** 인덱스 조건절에 `now()`를 썼는데 Postgres는 비-IMMUTABLE 함수를 인덱스 술어에 허용하지 않는다.
9. **접근성 색상 토큰 검사 스크립트가 자기 자신의 토큰에서 실패한다.** 모든 토큰에 4.5:1을 요구하는데 큰 글씨 토큰은 3.5:1로 정의돼 있다(그게 맞다).

이런 것들을 고치고, 실제로 만들 수 있는 범위로 줄인 것이 이 폴더다.

### 2026-09-01, 이 스펙 안에서 다시 두 번 바꾼 것

이 폴더도 처음 쓴 그대로가 아니다. 두 가지가 크게 바뀌었다.

**(1) 관광지 데이터를 테이블 18개 → `jsonb` 스냅샷 6개로.**
데이터가 250행 미만인데 스키마 설계·RLS·마이그레이션·뷰를 얹고 있었다. 이전 기획의 DB 중심 구조를 관성으로 이어받은 것이었다. 갱신은 여전히 **즉시**(재배포 없음)이고, 테이블 18 → 2 · 마이그레이션 8 → 2 · 뷰 2 → 0이 됐다. → [`04_data_model.md`](./04_data_model.md) §7

**(2) 제보를 사전 검수 → 즉시 공개(댓글)로.**
확인된 사실과 방문자 발언을 섞지 않기로 했다(원칙 7). 부수적으로 제보 사진을 받지 않게 됐고 — 즉시 공개에서는 초상권 위험이 이득보다 크다 — 저장소 버킷·EXIF 처리·서명 URL이 통째로 사라졌다. → [`01_scope.md`](./01_scope.md) §4.4 (4)

**(3) 라벨 규칙: "필수 항목 중 하나라도 모르면 정보없음" → "과반을 모르면".**
원래 규칙대로면 실제 채움률(24개 중 4~7개)에서 **모든 관광지가 모든 사용자에게 `정보없음`** 이 됐다. 위 1~9번에서 지적한 기존 계획의 결함을 형태만 바꿔 재현한 것이었다. → [`06_suitability.md`](./06_suitability.md) §6.4

## 4. 이 스펙을 관통하는 6가지 원칙

구현 중 판단이 갈리면 이 순서로 결정한다.

### 원칙 1 — 빈 값은 "불가"가 아니다

한국관광공사 무장애 데이터에서 어떤 항목이 비어 있으면, 그것은 **"정보 없음"** 이지 **"시설 없음"** 이 아니다. 절대 추론하지 않는다. 화면에는 "정보 없음 — 현장 확인 필요"로 표시하고, 그 빈칸이

- **(가) 본질 제약** — 사적지 계단처럼 문화재 보존상 바꿀 수 없는 것인지
- **(나) 운영자 미입력** — 그냥 아직 안 채운 것인지

를 구분한다. **(나)의 목록이 그대로 데이터 갭 리포트(S10)의 내용**이 된다. 이 구분이 이 서비스의 가장 독창적인 부분이고, 비용은 컬럼 하나다.

### 원칙 2 — 목록이 진실이고 지도는 보조다

접근성 정보를 담은 **텍스트 목록이 항상 존재**해야 하고, 스크린리더 사용자는 목록만으로 모든 기능을 쓸 수 있어야 한다. 지도(캔버스)는 스크린리더에 보이지 않으므로 부가물이다. 무장애 서비스가 지도 없이 못 쓰이면 자기모순이다.

### 원칙 3 — 화면은 실행 중에 외부 API를 부르지 않는다

모든 한국관광공사 데이터는 **수집 스크립트가 미리 Supabase에 적재**한다. 사용자가 페이지를 열 때 `apis.data.go.kr`를 호출하는 코드는 없다. 이유: 심사 당일 외부 API가 죽어도 서비스가 멀쩡하다. 이건 기존 스펙에서 가장 잘한 결정이고 그대로 가져왔다.

### 원칙 4 — 점수 계산은 순수 함수다

적합도 계산은 `src/domain/` 안의 **입출력만 있는 순수 TypeScript 함수**로 만든다. DB·네트워크·`Date.now()`·React를 쓰지 않는다. 같은 입력이면 언제나 같은 출력이다. 이래야 골든 테스트로 검증할 수 있고, 시연 중에 숫자가 흔들리지 않는다.

### 원칙 5 — 못 한 것은 못 했다고 쓴다

현장 실측을 안 했으면 "미검증"이라고 화면에 표시한다. 전문가 검수를 안 받았으면 "검수 대기"라고 쓴다. 집중률 API가 예측값이면 "예측 혼잡도(향후 30일)"라고 쓴다. **감추면 심사에서 걸리고, 밝히면 오히려 신뢰가 된다.**

### 원칙 6 — 조율 장치는 만들지 않는다

작성자가 1명이므로 계약 동결, 디렉터리 소유권, CODEOWNERS, 버전 잠금, 세트 동일성 CI 게이트 같은 것은 **전부 만들지 않는다**. 대신 **하나의 타입 파일을 import** 한다. 타입이 곧 계약이다.

### 원칙 7 — 확인한 사실과 방문자 발언을 섞지 않는다

**우리가 출처를 대고 확인한 것**(스냅샷)과 **방문자가 한 말**(제보)은 저장 위치가 다르고, 화면에서 분리되고, **점수에도 제보가 들어가지 않는다.**

방문자 제보는 댓글처럼 즉시 공개된다. 그게 사실로 승격되려면 **사람이 검토해 `content/curated-facts.json`에 적고 커밋**해야 한다. 그때 출처 칸에 제보 ID를 남기면 `git log`가 판단 기록이 된다.

섞으면 둘 다 신뢰를 잃는다. 분리해 두면 둘 다 제 값을 한다.

## 5. 이 문서들에 나오는 말

영어를 그대로 쓴 것은 업계에서 그 말을 쓰기 때문이지, 멋있어서가 아니다. 처음 나올 때 한 줄로 풀어 둔다.

| 말 | 뜻 |
|---|---|
| **ingest (수집)** | 외부 API에서 데이터를 받아 우리 DB에 넣는 작업. ETL(추출-변환-적재)이라고도 한다. `pnpm ingest` 한 줄로 돌고, 사용자 요청과 **무관하게** 하루 한 번 돈다. 이게 있어야 화면이 실행 중에 외부 API를 안 부를 수 있다 (§4 원칙 3) |
| **탐침 (probe)** | 가정이 맞는지 **실제로 한 번 호출해 보는 것**. `pnpm probe`. 결과는 `_probe-results.md`에 기록된다 |
| **페르소나** | 사용자의 이동 조건 묶음. 여기서는 5가지 — 휠체어 / 오래 걷기 어려움 / 시각 / 청각 / 유아차 |
| **RLS (행 수준 보안)** | Postgres가 **행 단위로** 접근을 막는 기능. "내 제보는 나만 본다"를 앱 코드가 아니라 DB가 강제한다. 코드에 버그가 있어도 DB가 막는다 |
| **골든 테스트** | 입력과 **기대 출력을 파일로 박아 두고** 매번 대조하는 테스트. 점수 산식처럼 "숫자가 조용히 바뀌면 큰일 나는 것"에 쓴다 |
| **성질 테스트 (property test)** | 입력을 무작위로 만들어 **항상 참이어야 하는 것**을 검사. 예: "점수는 언제나 0~100 사이" |
| **라우트 (route)** | 웹 주소 하나에 대응하는 화면. `/ko/places` 같은 것 |
| **캐시 무효화 (revalidate)** | 저장해 둔 화면을 버리고 새로 만들게 하는 것. 수집이 끝나면 호출한다 |
| **스크린리더** | 화면 내용을 소리로 읽어 주는 프로그램. NVDA·센스리더·VoiceOver 등 |
| **점자정보단말기** | 점자를 촉각으로 출력하는 기기. **자체 한국어 점역 엔진을 갖고 있어서** 앱이 점역해 줄 필요가 없다 |
| **공공누리** | 공공 데이터·저작물의 한국 표준 이용 허락 표시. 1유형(출처 표시)부터 4유형(출처+비상업+변경금지)까지 |
| **EXIF** | 사진 파일 안에 들어 있는 촬영 정보. **촬영 위치 좌표가 들어 있어서** 업로드 전에 지운다 |
