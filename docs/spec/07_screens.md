# 07 — 화면 기능 명세 (S1 ~ S10)

> 각 화면마다 **경로 / 목적 / 구성 / 동작 / 데이터 / 완료 기준**을 적는다.
> 접근성 공통 요구사항은 [`08_accessibility_legal.md`](./08_accessibility_legal.md)에 있고 여기서 반복하지 않는다.

## 전 화면 공통

| 요소 | 내용 |
|---|---|
| 레이아웃 | `<header>` (로고·언어 전환) · `<nav aria-label="주요 메뉴">` · `<main id="main-content">` · `<footer>` |
| 스킵 링크 | 첫 탭 정지점. `#main-content`로 이동 |
| 제목 | 페이지마다 `<h1>` 정확히 1개, `generateMetadata`로 고유 `<title>` |
| 언어 | `ko` / `en`. `<html lang>` 이 바뀐다 |
| 긴급 연락 | 화면 우하단 고정 버튼 → 119 · 1330 · 영사콜센터 `tel:` 링크 시트 |
| 푸터 | `출처: 한국관광공사 TourAPI (https://api.visitkorea.or.kr/) · 이용 조건은 자산별로 표기` + `/credits` `/privacy` 링크. **공공누리 유형은 자산 옆에 붙이고 푸터에 고정하지 않는다** ([`08`](./08_accessibility_legal.md) §3.3) |
| 조건 유지 | 홈에서 고른 페르소나·시간 예산은 `localStorage`에 저장되어 전 화면에 적용 |
| **스냅샷을 못 읽을 때** | **"데이터가 없다"와 "확인할 수 없다"를 구분해 쓴다.** [`04_data_model.md`](./04_data_model.md) §3.4의 `readSnapshot()`은 행이 없을 때도, 네트워크·인증·DB 오류일 때도 똑같이 예외를 던진다. 화면은 그 둘을 **다른 문구**로 쓴다:<br>· **스냅샷 행이 없다** → "아직 수집된 데이터가 없습니다" (첫 실행 전 상태)<br>· **조회 자체가 실패했다** → "데이터를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요" + `[다시 시도]` 버튼<br>**이전 값을 대신 보여주는 기능은 없다** — 그건 낡은 데이터를 오늘 데이터처럼 보여주는 것이고 원칙 5에 걸린다. 이 두 문구는 S2·S3·S10에 공통이다 |
| **금지 표현** | 화면 문구에서 **"공사"를 한국관광공사의 줄임말로 쓰지 않는다.** 이 앱에는 제보 분류 `construction`("공사 중")이 있어서 같은 두 글자가 정반대 뜻으로 읽힌다. 항상 `한국관광공사`로 쓴다 |

## S1 — 홈 / 조건 선택

**경로:** `/[locale]`
**목적:** 사용자가 자기 조건을 고르는 곳. 이 화면의 선택이 다른 모든 화면의 판정을 바꾼다.

### 구성

```
┌─────────────────────────────────────────────────┐
│ h1  누구와 함께 가시나요?                        │
│                                                  │
│ [체크박스 그룹] (다중 선택, 안 골라도 진행 가능)  │
│  ☐ 휠체어를 이용해요        (P1a)                │
│  ☐ 오래 걷기 어려워요       (P1b)                │
│  ☐ 눈이 잘 안 보여요        (P2a)                │
│  ☐ 귀가 잘 안 들려요        (P2b)                │
│  ☐ 유아차와 함께 가요       (P3)                 │
│     └ ☐ 낯선 곳이 힘든 아이와 함께  (인지·발달)  │
│                                                  │
│ [선택 요약 배너] ← 2개 이상 고르면 나타남         │
│  "가장 조건이 까다로운 분(휠체어)을 기준으로       │
│   판정합니다."                                    │
│                                                  │
│ h2  얼마나 머무르시나요?                          │
│  ( ) 반나절 (3~4시간)                            │
│  (•) 당일 (8~10시간)                             │
│  ( ) 1박 2일                                     │
│                                                  │
│ [ 관광지 보기 ]  [ 코스 보기 ]                    │
└─────────────────────────────────────────────────┘
```

### 동작

- 체크박스는 **다중 선택**. 하나도 안 고르면 "일반 방문" 기준(모든 페르소나 등급 `other`)으로 계산한다.
- **2개 이상 고르면 `min()` 규칙을 문장으로 설명하는 배너가 나온다.** 이게 이 서비스가 다른 무장애 앱과 다른 점이고, 화면에 없으면 아무도 모른다.
- "낯선 곳이 힘든 아이와 함께"는 유아차를 고를 때만 활성화된다.
- 선택 즉시 `localStorage`에 저장. 뒤로 가기·새로고침에도 유지된다.

### 데이터
없음 (클라이언트 상태만).

### 완료 기준
- 키보드만으로 전 항목 선택·이동 가능
- 선택 변경 시 요약 배너가 `aria-live="polite"`로 읽힌다
- 새로고침 후에도 선택이 유지된다

## S2 — 관광지 목록

**경로:** `/[locale]/places`
**목적:** 6곳을 내 조건 기준 적합도로 정렬해 보여준다.

### 구성

```
┌────────────────────────────────────────────────────┐
│ h1  공주·부여 백제역사유적지구                       │
│ [조건 요약] 휠체어 · 오래 걷기 어려움  [조건 바꾸기] │
│                                                     │
│ (탭 없음 — 목록이 먼저 오고 지도는 목록 아래)        │
│                                                     │
│ ┌── 카드 ────────────────────────────────────────┐ │
│ │ 공산성                            ⚠ 주의 필요 56 │ │
│ │ 공주시 · 사적                                    │ │
│ │ ⚠ 확인 필요: 엘리베이터                           │ │
│ │ 확인됨: 접근로·출입통로·휠체어·장애인 화장실       │ │
│ │ 정보 없음 17건 / 24건 · 한국관광공사 2025-11-03 기준│ │
│ │                          [상세 보기] [경로 안내] │ │
│ └────────────────────────────────────────────────┘ │
│ ┌── 카드 ────────────────────────────────────────┐ │
│ │ 정림사지                          ? 정보 없음  — │ │
│ │ 부여군 · 사적                                    │ │
│ │ 휠체어 이용에 꼭 필요한 5개 항목 중 4개를 모릅니다 │ │
│ │ → 접근로, 출입통로, 엘리베이터, 장애인 화장실      │ │
│ │                          [상세 보기]             │ │
│ └────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
```

### 동작

- **정렬:** `방문가능` → `주의` → `정보없음` → `대체추천` 순, 같은 라벨 안에서는 점수 내림차순.
  `정보없음`을 맨 뒤가 아니라 중간에 두는 이유: "모르는 곳"이 "못 가는 곳"보다 위다.
  **`대체추천`은 확인된 장벽이 있을 때만 나오므로 맨 뒤가 맞다** ([`06_suitability.md`](./06_suitability.md) §6.4 규칙 1). 점수가 낮아서 뒤로 가는 카드는 없다 — 그건 `주의` 안의 점수 순서로만 드러난다.
- **탭을 쓰지 않는다.** 목록이 항상 먼저 오고, 지도는 그 아래 블록이다. **목록은 어떤 경우에도 접근성 트리에서 사라지지 않는다.**
  > **★ `hidden` 속성을 쓰면 안 된다.** HTML 표준에서 `hidden`은 "관련 없음"을 뜻하고 접근성 트리에서 요소를 **제거**한다 — 스크린리더도 못 읽는다. `display:none`·`visibility:hidden`·`aria-hidden="true"`도 같다.
  > **쓰는 방법 (둘 중 하나, 이번 범위는 (가)):**
  > - **(가) 탭을 쓰지 않는다.** 목록을 항상 보이게 두고 지도를 그 아래에 붙인다. 원칙 2("목록이 진실이고 지도는 보조")를 화면 구조로 그대로 옮긴 것이고, 구현이 가장 싸다.
  > - (나) 탭을 쓴다면 비활성 패널을 **시각적으로만** 감춘다 — `clip-path: inset(50%)` + `position:absolute` + `width:1px` 계열. 이때 접근성 트리에는 남으므로 `role="tabpanel"`을 쓰지 않고 두 영역을 각각 `<section aria-label>`로 둔다(탭 역할을 선언하면 비활성 패널이 읽히는 것이 오히려 스크린리더 사용자를 혼란시킨다).
- 지도(Kakao) 로드 실패 시 지도 자리에 "지도를 불러오지 못했습니다. 위 목록으로 모든 기능을 이용할 수 있습니다"를 표시한다. **목록은 원래부터 위에 있으므로 되돌릴 상태가 없다** — 지도 실패가 아무것도 망가뜨리지 않는 것이 이 구조를 고른 이유다.
- 각 카드는 `<article>`, 제목은 `<h2>`.

### 데이터
스냅샷 `pois` + `accessibility` + `context` ([`04_data_model.md`](./04_data_model.md) §3).

**서버 컴포넌트는 사실 데이터만 내려보내고, `calculateSuitability()` 6회는 브라우저가 돌린다.**
페르소나가 `localStorage`에 있으므로 서버에서 계산하면 캐시된 HTML이 모두에게 같아져 조건을 바꿔도 결과가 안 바뀐다 ([`04_data_model.md`](./04_data_model.md) §3.5).
페이지 캐시 `revalidate = 3600` — HTML은 누구에게나 같으므로 캐시가 그대로 유효하다.

### 완료 기준
- 지도 없이 목록만으로 전 관광지의 라벨·점수·근거 요약을 읽을 수 있다
- 조건을 바꾸면 순서와 라벨이 실제로 바뀐다
- `정보없음` 카드에 점수 숫자가 표시되지 않는다

## S3 — 관광지 상세 ★ 핵심 화면

**경로:** `/[locale]/places/[slug]`
**목적:** **판정과 그 근거를 전부 공개한다.** 이 서비스의 존재 이유이자 심사에서 가장 오래 보게 될 화면.

### 구성 — 순서가 중요하다

**결론 먼저, 계산 나중.** 사용자는 "내 일행이 갈 수 있나, 뭘 조심해야 하나"를 먼저 알아야 한다.

```

│    조건: 휠체어 · 오래 걷기 어려움                         │
│    ▸ 확인된 것: 접근로, 출입통로, 휠체어, 장애인 화장실     │
│    ▸ 정보 없음 17건 / 24건                                │
│    [경로 안내 보기]  [도슨트 듣기]  [제보하기]             │

├──────────────────────────────────────────────────────────┤
│ ③ 판정에 들어간 항목 32개  ← 원문 그대로                   │

│    (그중 한국관광공사 무장애여행 항목이 24개, 나머지 8개는  │
│     경로 데이터·콘텐츠 파일·부가 API에서 온 파생 항목)      │
```

### 동작 규칙

| # | 규칙 |
|---|---|
| 1 | **원문을 보여준다.** 앱의 판정(`✓ 확인됨`)과 함께 KTO 원문 문장을 그대로 붙인다. 사용자가 직접 판단할 수 있어야 한다 |
| 2 | **출처를 항목마다 붙인다.** 한국관광공사 항목은 `한국관광공사 무장애여행 · {원래 필드명} · {확인일}`. 필드명(`route`, `elevator`)까지 노출하는 것이 이 화면의 핵심이다 |
| 2b | **파생 항목 8개도 여기 함께 보인다.** `path_continuity` `rest_seating` `shade_indoor` `visual_alarm` `crowd_forecast` `weather_warning` `emergency_distance` `aed_distance` — ④의 6개 축 중 **'상황' 축 전체와 '이동'·'휴식'의 일부가 이 항목들로 계산되므로, 이들이 ③에 없으면 "판정 근거를 전부 공개한다"가 거짓이 된다.** 출처는 `kto_with`가 아니라 각자의 것을 쓴다 — `경로 데이터` · `content/facilities.json` · `관광지 집중률 API` · `기상청`. 파생임을 라벨로 표시한다 |
| 2c | **`정보 없음 n건 / {ktoTotalCount}건` 카운터는 한국관광공사 항목만 센다.** 32개를 세지 않는다 — 그 숫자는 S10 갭 리포트의 분모와 같아야 하고, 갭 리포트는 **한국관광공사가 비운 칸**을 세는 것이 목적이다 ([`06_suitability.md`](./06_suitability.md) §6.7). 화면 라벨에 `(한국관광공사 항목 기준)`을 반드시 붙인다 |
| 3 | **`정보 없음`은 (가)/(나)를 구분한다.** "운영자가 입력하지 않은 항목입니다"(개선 가능) vs "사적지 구조상 설치가 어려운 항목입니다"(본질 제약) |
| 3b | **모르는 필수 항목의 이름을 라벨 바로 옆에 반드시 쓴다.** `⚠ 확인 필요: 엘리베이터`. "주의 필요"만 쓰고 무엇을 확인해야 하는지 안 알려주면 판정이 쓸모없어진다 ([`06_suitability.md`](./06_suitability.md) §6.4·§6.6 — **강제 요구사항**) |
| 3c | **`정보 없음 n건 / {ktoTotalCount}건`을 항상 함께 보여준다.** 점수만 있고 몇 개를 모르는지가 없으면 과신을 부른다. **분모를 `24`로 하드코딩하지 않는다** — 관광지 유형에 따라 `not_applicable` 항목이 빠져 줄어든다 ([`06_suitability.md`](./06_suitability.md) §3·§6.7) |
| 4 | ④는 **기본 접힘.** 심사·관심 있는 사용자만 펼친다. 일반 사용자에게 수식을 먼저 보이면 안 된다 |
| 5 | ④의 숫자는 **`SuitabilityResult`에서 그대로 렌더링**한다. 화면에서 다시 계산하지 않는다. **표시는 소수 3자리 반올림이고 점수는 반올림 전 값으로 계산한다** — 그래서 행별 기여값의 합과 `A 합계` 표시값이 마지막 자리에서 다를 수 있다. 위 예시 블록도 그 상태이고, 이건 오류가 아니라 반올림이다. **이 블록의 숫자는 손으로 적지 않고 골든 결과에서 생성한다** ([`09_test_and_ci.md`](./09_test_and_ci.md) §2) |
| 6 | ⑧은 **⑦과 시각적으로 확실히 분리**한다. 배경색·아이콘·경고 문구를 다르게 준다 |
| 6b | **⑨ 방문자 제보는 ③ 무장애 정보와 시각적으로 확실히 분리한다.** 배경·아이콘·제목을 다르게 주고, "운영자가 확인한 정보가 아닙니다"를 항상 붙인다. ③은 **우리가 출처를 대고 확인한 사실**이고 ⑨는 **방문자가 한 말**이다. 섞이면 둘 다 신뢰를 잃는다 |
| 6c | **⑨는 적합도 점수에 영향을 주지 않는다.** 제보가 사실이 되는 통로는 사람이 `content/curated-facts.json`에 옮겨 적는 것뿐이다 ([`05_ingest.md`](./05_ingest.md) §4.4) |
| 7 | 사진이 `no_transform = true`(공공누리 3유형)면 `next/image` 최적화를 태우지 않고 `object-fit: contain`으로 원본을 그대로 보여준다 |
| 8 | 도슨트·경로 안내 버튼은 **해당 데이터가 있을 때만** 표시한다 |

### 데이터
- 스냅샷 `pois` · `accessibility` · `routes` · `docent` · `context` · `related`
- 테이블 `barrier_reports` (숨겨지지 않은 것 전부, **캐시하지 않음**)
- 6곳 전체 점수 (대체 관광지용) — 브라우저에서 6회 계산

### 완료 기준
- **32항목 전부**가 상태·원문·출처·확인일과 함께 보인다. 한국관광공사 항목 24개는 **원래 필드명**까지, 파생 항목 8개는 **계산 근거**까지
- 라벨이 `주의`이고 모르는 필수 항목이 있으면 **그 항목 이름이 라벨 옆에 보인다**
- `정보 없음 n건 / {ktoTotalCount}건`이 항상 보이고, 그 숫자가 S10 갭 리포트와 같다
- ⑨ 방문자 제보가 ③과 시각적으로 구분되고 "확인한 정보가 아님" 문구가 보인다
- 빈 항목이 (가)/(나)로 구분돼 표시된다
- 계산 내역의 **A·B·C**와 축별 기여값이 전부 보이고, **데이터 신뢰도가 점수와 분리돼 표시된다**
- 스크린리더로 ①→②→③→④ 순서로 자연스럽게 읽힌다

- 시간 예산을 바꾸면 다른 템플릿이 선택된다. 목록은 서버에서 미리 계산된 것 중 고르는 것이지 새로 짜는 게 아니다.
- 체류 시간은 **원래 값 → 보정값**을 둘 다 보여준다. 왜 늘었는지 알 수 있게.
- 페르소나 휴식 한계를 **넘는**(초과) 이동 구간에 경고를 붙인다 ([`06_suitability.md`](./06_suitability.md) §7). 여러 명이면 가장 짧은 한계를 쓴다 — 위 예에서는 시니어의 15분.
- **관광지 점수는 S2·S3과 같은 값을 쓴다.** 같은 조건에서 같은 관광지가 화면마다 다른 점수를 보이면 안 된다.
- "여행 기록에 담기"를 누르면 S9에 코스의 관광지들이 추가된다.

### 완료 기준
- 조건에 따라 총 시간이 실제로 달라진다
- 휴식 경고가 나타나고 사라진다

### 동작

| # | 규칙 |
|---|---|
| 1 | **근거 수준 경고를 맨 위에 고정한다.** 현장에 안 갔으면 그렇게 쓴다. 감추면 안 된다 |
| 2 | **경사도를 숫자로 쓰지 않는다.** "평탄 / 완만한 오르막 / 가파른 구간 있음" 같은 서술만. 재지 않은 값을 측정값처럼 내보내지 않는다 |
| 3 | **"한 번에 한 단계" 모드** — 현재 단계와 다음 단계만 보이고 나머지는 감춘다. 인지·발달 옵션을 켰으면 기본값 |
| 4 | 지도는 없어도 된다. 단계 카드 목록이 완전한 안내다 |
| 5 | GPX는 `routes` 스냅샷 `steps[].coord`에서 생성 (`src/domain/gpx.ts`). 지도 앱 딥링크는 아래 형식 |

**지도 앱 딥링크 — URL 형식**

```
카카오맵 (앱)   kakaomap://route?sp={lat},{lng}&ep={lat},{lng}&vp={lat},{lng}&vp2=…&by=foot
카카오맵 (웹)   https://m.map.kakao.com/scheme/route?sp=…&ep=…&vp…=…&by=foot
구글지도        https://www.google.com/maps/dir/?api=1&origin={lat},{lng}
                  &destination={lat},{lng}&travelmode=walking&waypoints={lat}%2C{lng}%7C…
```

| 규칙 | 값 |
|---|---|
| 경유지 상한 | **카카오맵 5개** (`vp`, `vp2`~`vp5` — 첫 경유지는 번호 없이 `vp`) · **구글 3개**(모바일) |
| 좌표 순서 | 전부 `lat,lng`. 구글의 `waypoints`는 `%7C`(파이프)로 구분하고 좌표 안의 쉼표는 `%2C` |
| 이동 수단 | 카카오 `by=foot` · 구글 `travelmode=walking` |
| 분기 | 모바일은 앱 스킴, 데스크톱은 웹 URL. 앱이 없으면 웹으로 떨어진다 |

> **★ `kakao.maps.LatLng`의 인자 순서는 `(lat, lng)`다.** 우리 JSON은 `{ lat, lng }` 이름 있는 객체이므로 헷갈릴 일이 없지만, GeoJSON(`[lng, lat]`)이나 KTO `mapx`(경도)/`mapy`(위도)에서 값을 가져올 때는 **반드시 뒤집어 넣어야 한다.** 지도를 붙이는 순간 걸리는 함정이다.

### 데이터
스냅샷 `routes` + `pois`(사진).

### 완료 기준
- 5단계가 사진·쉬운 글·거리·노면과 함께 표시된다
- 근거 수준 경고가 항상 보인다
- GPX가 내려받아지고 지도 앱에서 열린다
- 스크린리더로 단계 순서대로 읽힌다

### 동작

| # | 규칙 |

| 2 | **대본은 항상 화면에 있다.** 기본은 펼침. 접을 수는 있어도 DOM에서 사라지지는 않는다 |
| 3 | **GPS를 쓰지 않는다.** 이 화면에 들어오는 것 자체가 재생 의사 표시다. `navigator.geolocation`을 호출하는 코드가 앱 전체에 없다 |

| 5 | 재생 위치에 맞춰 대본 문단을 강조한다(`aria-current="true"`). `playTime`과 문단 수로 균등 분할하는 근사치로 충분하다 |
| 6 | **대본 내려받기 버튼을 두지 않는다.** 대본은 이미 화면에 HTML로 있고, 스크린리더·점자 디스플레이가 그대로 읽는다. 파일로 한 번 더 주는 것은 아무것도 추가하지 않는다 ([`01_scope.md`](./01_scope.md) §4.4 (2)) |
| 7 | Odii 이야기가 없는 관광지는 이 화면 대신 "오디오 가이드가 제공되지 않는 관광지입니다"와 국가유산청 해설 링크를 보여준다 |
| 8 | 오디오가 없고 대본만 있으면, 브라우저 음성 합성(`SpeechSynthesis`)으로 읽어주는 버튼을 제공하고 **"기기 음성 합성"** 배지를 붙인다 |
| 9 | **`audioUrl`은 있는데 재생이 실패하면** (`<audio>`의 `error` 이벤트 — 호스트 장애·CORS·파일 삭제) 플레이어 자리에 **"오디오를 불러오지 못했습니다"** 를 표시하고 **7번의 규칙 8을 그대로 켠다**(기기 음성 합성 버튼). **대본은 원래 화면에 있으므로 아무것도 사라지지 않는다.**<br>**"오디오 미제공"(규칙 7)과 문구를 다르게 쓴다** — 앞은 그 관광지에 콘텐츠가 없는 것이고 뒤는 있는데 지금 못 받는 것이다. 사용자가 나중에 다시 오면 되는지 아닌지가 갈린다 |

### 데이터
스냅샷 `docent` (관광지 × 언어 × 이야기).

### 완료 기준
- 오디오가 재생되고 대본이 함께 보인다
- 영어로 전환된다 (Odii `langCode` 확인 결과에 따름)
- 앱 전체에 `navigator.geolocation` 호출이 0건 (E2E로 검증)

**사진 입력이 없다.** 이유는 [`01_scope.md`](./01_scope.md) §4.4 (4).

### 동작

| # | 규칙 |
|---|---|
| 1 | 로그인 불필요. Supabase **익명 인증**으로 세션을 만들고 그 `uid`를 `reporter_id`로 쓴다 |
| 2 | **저장 즉시 공개된다.** 대기 상태가 없다. 등록 후 S3 ⑨로 이동해 자기 글이 보이는 것을 확인시킨다 |
| 3 | **서버 측 검사** — 설명 500자 초과 거부, 같은 사람이 같은 관광지·분류로 **같은 날(UTC) 재제보 시 거부.** 서버 코드가 먼저 확인해 친절한 문구를 주고, **경합으로 뚫려도 DB 유니크 제약이 두 번째를 거절한다** → [`04_data_model.md`](./04_data_model.md) §5.2 |
| 4 | 동의 체크박스는 **필수 1개만.** 마케팅 등 다른 항목을 묶지 않는다 (개인정보보호법 제22조) |
| 5 | 즉시 공개이므로 **동의 문구가 "검수를 거쳐"가 아니라 "즉시 공개"여야 한다.** 개인정보 처리방침도 같은 내용을 적는다 ([`08_accessibility_legal.md`](./08_accessibility_legal.md) §2) |
| 6 | 각 제보 옆에 **[신고]** 버튼을 둔다. 누르면 `flag_report(id)` RPC가 **`flagged_at`을 처음 한 번만** 채우고, 관리자 목록에서 **신고 들어온 것이 위로 올라온다** ([`04_data_model.md`](./04_data_model.md) §5.2·§5.3). 누른 뒤 "신고했습니다"를 `aria-live="polite"`로 알린다. **버튼만 두고 아무 일도 안 일어나게 하지 않는다** — 08 §2.3이 이 버튼을 즉시 공개 모델의 안전장치로 세고 있으므로, 동작하지 않으면 그 주장이 거짓이 된다.<br>**신고 횟수를 세지 않는다** — 익명 사용자가 아무 제보 ID로 무한히 호출할 수 있으므로 카운터는 관리자가 읽는 순서를 조작하는 손잡이가 된다. `flagged_at`은 두 번째 호출부터 아무 일도 하지 않는다 |

### 완료 기준
- 제보를 올리면 **즉시** S3 ⑨에 나타난다
- 같은 사람·관광지·분류의 **같은 날 두 번째 제보가 거부된다** (DB 유니크 제약이 강제하므로 동시 요청에서도 깨지지 않는다)
- 로그인 없이 동작한다

## S8 — 관리자

**경로:** `/admin/reports`
**접근:** Supabase 로그인 + `admin_users` 테이블에 있는 계정만. **환경변수로 관리자를 지정하지 않는다.**

**하는 일 두 가지:** ① 부적절한 제보 숨기기 ② 사실로 반영할 것 골라내기

### 구성

```
h1  방문자 제보  (전체 24건 · 숨김 2건 · 신고 접수 3건)

[보기] ● 전체  ○ 신고된 것  ○ 숨김만
[정렬] ● 신고된 것 먼저  ○ 최신순

┌───────────────────────────────────────────────────┐
│ 공산성 · 공사 중 · 2026-09-10 목격      🚩 신고됨  │
│ 등록 2026-09-11 09:14                              │
│ "동문 쪽 계단 보수 공사로 통행이 막혀 있습니다"     │
│                                                    │
│ [숨기기 ▾]              [항목으로 복사 📋]         │
│   └ 사유: 욕설 / 허위 / 중복 / 개인정보 / 기타     │
└───────────────────────────────────────────────────┘
```

### 동작

| # | 규칙 |
|---|---|
| 1 | **[숨기기]** → `is_hidden = true` + 사유·처리자·시각 기록. 되돌리기(`is_hidden = false`)도 가능하다 |
| 2 | 숨겨진 제보는 **본인에게는 계속 보인다**(왜 안 보이는지 알 수 있게). 다른 사용자에게는 안 보인다 |
| 3 | **[항목으로 복사]** → `curated-facts.json` 조각을 클립보드에 넣는다. 관리자가 `capabilityCode`·`status`를 채워 파일에 붙여넣고 커밋한다 |
| 4 | **자동으로 사실이 바뀌는 경로는 없다.** 사람이 파일에 적고 커밋해야만 다음 수집에서 반영된다 ([`05_ingest.md`](./05_ingest.md) §7) |
| 5 | 숨김 처리 후 해당 관광지 페이지를 `revalidatePath`로 갱신한다 |
| 6 | **목록 기본 정렬은 `(flagged_at is not null) desc, created_at desc`.** 신고가 들어온 제보를 먼저 본다. 신고 여부는 판정이 아니라 **읽는 순서**만 정하고, **신고가 쌓인다는 개념 자체가 없다** — 한 번 신고되면 그걸로 끝이고, 자동으로 숨겨지지도 않는다 (다수가 소수 의견을 지우는 통로가 되면 안 된다) |

**[항목으로 복사]가 만드는 조각:**

```jsonc
{
  "poiSlug": "gongsanseong",
  "capabilityCode": "",                    // ← 관리자가 채운다
  "status": "",                            // ← 관리자가 채운다
  "detail": "동문 쪽 계단 보수 공사로 통행이 막혀 있습니다",
  "source": "방문자 제보 #a1b2c3 확인 후 ○○ 로 교차 확인",   // ← 확인 경로를 적는다
  "checkedAt": "2026-09-18"
}
```

> **이 흐름이 감사 기록 그 자체다.** "왜 이 값이 바뀌었나"는 `git log`가 답한다. 별도 이력 테이블이 필요 없다.

### 완료 기준
- 관리자가 아닌 계정으로 `/admin/reports`에 접근하면 차단된다
- 숨기면 다른 사용자 화면에서 즉시 사라진다
- [항목으로 복사]가 유효한 JSON 조각을 만든다

### 인쇄용 페이지 (`/diary/print`)

- 별도 레이아웃 (헤더·내비 없음)
- `@media print` CSS: A4, 여백 20mm, 페이지 나눔 제어
- 내용: 표지(날짜·동행 조건) → 관광지별 (사진·방문 시각·경로 단계·메모·국가유산청 해설 인용) → 출처 목록
- **하단 고정 문구:** `출처: 한국관광공사 TourAPI · 공공누리 제1유형 / 한국관광공사 Odii 오디오 가이드`

### 동작

| # | 규칙 |
|---|---|
| 1 | **`localStorage`에만 저장.** 서버에 올리지 않는다. 개인정보 수집이 없다 |
| 2 | 저장 구조에 `schemaVersion`을 둔다. 나중에 구조가 바뀌어도 옛 기록을 읽을 수 있게 |
| 3 | **텍스트로 내보내기(.txt)** — 마크업·표·이모지 없는 순수 텍스트, 한 줄에 한 정보. 메모 앱·이메일에 붙여넣거나 다른 기기로 옮기는 용도다. **"점자용"이라고 쓰지 않는다** — 점자 지원은 접근성 있는 HTML 자체다 |
| 4 | GPX는 방문한 관광지의 좌표 + 경로 단계 좌표로 생성 |
| 5 | "접근성 한 줄"에 쓴 내용은 **S7 제보 폼으로 넘길 수 있다.** 이게 사용자 기록 → 다음 방문자 → 데이터 개선으로 이어지는 고리다 |

### 우선순위 계산 (`src/domain/gap.ts`)

```
대상       = status 가 'unknown' 또는 'unsupported' 인 항목만.
             'supported' 와 'partial' 은 목록에 들어가지 않는다
             (채워진 값을 개선 과제로 올리면 목록이 노이즈가 된다)

우선순위 = 영향 × 심각도 × 실현가능성

영향       = 이 항목이 어떤 페르소나의 critical 이면 1.0, 아니면 0.5
심각도     = unknown 1.0 / unsupported 0.2   (모르는 게 없는 것보다 급하다)
실현가능성 = absenceKind 가 null(원인 미확인) 이면 1.0
             operator_missing(확인됨) 이면 1.0
             intrinsic(확인됨) 이면 0.1
             not_applicable 이면 제외
             not_registered 이면 항목 단위로 올리지 않는다 (아래)

             ★ null 과 operator_missing 이 같은 1.0 인 이유:
               담당자의 첫 행동이 둘 다 '이 칸을 확인하고 채운다' 로 같다.
               다른 것은 우리가 원인을 아는지 여부이고, 그건 아래 표의
               '원인' 열이 말한다 — 우선순위로 말하지 않는다.

동점 정렬  = 우선순위 내림차순 → 관광지의 '정보 없음' 개수 내림차순
             → CAPABILITIES 카탈로그 순서 (05 §4.1)
             ★ 세 번째까지 가면 항상 하나로 정해진다. 정렬이 결정적이어야
               스크린샷·CSV·골든 결과가 실행마다 흔들리지 않는다
```

**`not_registered`는 관광지 한 줄로 올린다.** 관광지가 데이터셋에 없으면 24항목이 전부 같은 우선순위로 올라와 **표 상단을 한 관광지가 24줄로 점거한다.** 그리고 담당자가 할 일은 "24개 항목 입력"이 아니라 **"관광지 등록"** 하나다 ([`05_ingest.md`](./05_ingest.md) §4.2). 그래서 별도 블록에 관광지 단위로 표시하고, 항목별 표에서는 제외한다.

> **이전 산식은 인수가 4개였다** — `영향 × 심각도 × 신뢰도 × 실현가능성`. `신뢰도`는 "방문자 제보가 1건 이상이면 1.0, 없으면 0.6"이었다.
> **`신뢰도`를 뺐다.** 원칙 7(확인된 사실과 방문자 발언을 섞지 않는다)에 따라 제보가 판정과 점수에 들어가지 않으므로 개선 우선순위에도 들어갈 수 없다. 제보 수가 순위를 흔들면 **말이 많은 관광지가 먼저 고쳐지고 말이 없는 관광지가 뒤로 밀린다** — 그건 데이터 공백의 우선순위가 아니다.

> **핵심 아이디어:** "엘리베이터가 없다"와 "엘리베이터 정보가 없다"는 **완전히 다른 문제**다. 앞은 공사가 필요하고 뒤는 입력 한 번이면 된다. 지자체 담당자에게 유용한 건 뒤쪽 목록이다. 이 구분이 리포트의 전부다.
>
> **그런데 "정보가 없다"에서 "입력 한 번이면 된다"로 가는 것도 추론이다.** 그래서 이 리포트가 단언하는 것은 **"이 칸이 비어 있다"** 까지이고, 원인은 **확인된 것만** 적는다 ([`05_ingest.md`](./05_ingest.md) §4.2). 나머지는 "원인 미확인"이고, 그 목록이 담당자의 첫 작업 목록이다 — 채우는 것이 아니라 **확인하는 것**이 첫 작업이다.

### 동작
- **정보 없음 개수는 관광지 상세(S3 ③)의 숫자와 반드시 같다.** 같은 `accessibility` 스냅샷 배열을 센다 — 계산이 한 곳에만 있으므로 갈라질 수가 없다.
- **"채움률"이라는 한 개의 숫자를 쓰지 않는다.** 출처를 나눠 세지 않으면 **우리가 `curated-facts.json`에 한 줄 넣을 때마다 "지자체 개선 성과"가 올라간다** — 지자체가 아무것도 하지 않았는데도. 인계 성과 지표로 쓰이는 숫자이므로(기획안 `03_operation_and_growth.md` §6) 여기서 섞으면 그 지표가 거짓이 된다. 열을 셋으로 나눈 것이 그 대응이다.
- 집계는 SQL 뷰가 아니라 **코드 20줄**이다 (6곳뿐).
- CSV 헤더: `관광지,항목코드,항목명,상태,부재유형,우선순위,출처,확인일`
- 방문자 추이는 숫자만 표시하고 **주의 문구를 `role="note"`로 항상 보이게** 둔다. `display:none` 금지.
- 지자체 담당자가 그대로 쓸 수 있게 표는 `<caption>`과 `<th scope>`를 갖춘 진짜 `<table>`.

### 완료 기준
- 6곳의 **'공사 원문' / '우리가 확인' / '정보 없음' 세 열**이 각각 표시되고 합이 24다
- 우선순위 표에서 **"원인 미확인" · "미입력(확인됨)" · "구조 제약(확인됨)"** 세 가지가 시각적으로 구분된다
- **미등록 관광지가 있으면 관광지 단위 한 줄로 표시되고, 항목별 표에는 그 24줄이 나오지 않는다**
- 같은 데이터로 두 번 렌더하면 우선순위 표의 행 순서가 같다 (동점 정렬 규칙)
- CSV가 내려받아진다
- 방문자 주의 문구가 항상 보인다

## 화면 간 데이터 흐름 — "한 번 모은 데이터가 어디까지 가는가"

이 서비스의 주장은 "기능이 많다"가 아니라 **"하나의 데이터가 다섯 군데로 흐른다"** 이다. 발표에서 이 그림 하나를 보여주면 된다.

```
KorWithService2 / detailWithTour2  (무장애 24항목)
        │
        ▼
  스냅샷 'accessibility'
  (관광지 · 항목코드 · 상태 · 원문 · 출처필드 · 확인일)
        │
        ├──▶ S2 목록      : 라벨과 정렬 순서를 정한다
        ├──▶ S3 상세      : 원문·출처·계산 근거를 전부 공개한다
        ├──▶ S5 경로 안내 : 어떤 단계에 무엇을 주의할지 정한다
        ├──▶ S9 여행 기록 : 인쇄물에 "이 코스의 접근성"으로 들어간다
        └──▶ S10 갭 리포트: 비어 있는 항목이 개선 우선순위가 된다


별도 흐름 — 방문자가 말한 것
        S7 제보 ──즉시──▶ S3 ⑨ 방문자 제보 (다음 방문자가 본다)
                              │
                              │ 관리자가 검토
                              ▼
                    content/curated-facts.json 에 사람이 적고 커밋
                              │
                              ▼
                    다음 수집 → 스냅샷 → 위 다섯 화면 전부에 반영
```

**두 흐름을 분리한 것이 핵심이다.** 위는 **우리가 출처를 대고 확인한 사실**, 아래는 **방문자가 한 말**이다. 아래가 위로 올라가려면 반드시 사람의 판단과 git 커밋을 거친다.
