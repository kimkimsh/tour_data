# 07 — 화면 기능 명세 (S1 ~ S10)

> 각 화면마다 **경로 / 목적 / 구성 / 동작 / 데이터 / 완료 기준**을 적는다.
> 접근성 공통 요구사항은 [`08_accessibility_legal.md`](./08_accessibility_legal.md)에 있고 여기서 반복하지 않는다.

## 전 화면 공통

| 요소 | 내용 |
|---|---|
| 레이아웃 | `<header>` (로고·언어 전환) · `<nav aria-label="주요 메뉴">` · `<main id="main-content">` · `<footer>` |
| 스킵 링크 | 첫 탭 정지점. `#main-content`로 이동 |
| 제목 | 페이지마다 `<h1>` 정확히 1개, `generateMetadata`로 고유 `<title>` |
| 언어 | `ko` / `en`. `<html lang>` 이 바뀐다 |
| 긴급 연락 | 화면 우하단 고정 버튼 → 119 · 1330 · 영사콜센터 `tel:` 링크 시트 |
| 푸터 | `출처: 한국관광공사 TourAPI (https://api.visitkorea.or.kr/) · 공공누리 제1유형` + `/credits` `/privacy` 링크 |
| 조건 유지 | 홈에서 고른 페르소나·시간 예산은 `localStorage`에 저장되어 전 화면에 적용 |

## S1 — 홈 / 조건 선택

**경로:** `/[locale]`
**목적:** 사용자가 자기 조건을 고르는 곳. 이 화면의 선택이 다른 모든 화면의 판정을 바꾼다.

### 구성

```
┌─────────────────────────────────────────────────┐
│ h1  누구와 함께 가시나요?                        │
│                                                  │
│ [체크박스 그룹] (다중 선택, 안 골라도 진행 가능)  │
│  ☐ 휠체어를 이용해요        (P1a)                │
│  ☐ 오래 걷기 어려워요       (P1b)                │
│  ☐ 눈이 잘 안 보여요        (P2a)                │
│  ☐ 귀가 잘 안 들려요        (P2b)                │
│  ☐ 유아차와 함께 가요       (P3)                 │
│     └ ☐ 낯선 곳이 힘든 아이와 함께  (인지·발달)  │
│                                                  │
│ [선택 요약 배너] ← 2개 이상 고르면 나타남         │
│  "가장 조건이 까다로운 분(휠체어)을 기준으로       │
│   판정합니다."                                    │
│                                                  │
│ h2  얼마나 머무르시나요?                          │
│  ( ) 반나절 (3~4시간)                            │
│  (•) 당일 (8~10시간)                             │
│  ( ) 1박 2일                                     │
│                                                  │
│ [ 관광지 보기 ]  [ 코스 보기 ]                    │
└─────────────────────────────────────────────────┘
```

### 동작

- 체크박스는 **다중 선택**. 하나도 안 고르면 "일반 방문" 기준(모든 페르소나 등급 `other`)으로 계산한다.
- **2개 이상 고르면 `min()` 규칙을 문장으로 설명하는 배너가 나온다.** 이게 이 서비스가 다른 무장애 앱과 다른 점이고, 화면에 없으면 아무도 모른다.
- "낯선 곳이 힘든 아이와 함께"는 유아차를 고를 때만 활성화된다.
- 선택 즉시 `localStorage`에 저장. 뒤로 가기·새로고침에도 유지된다.

### 데이터
없음 (클라이언트 상태만).

### 완료 기준
- 키보드만으로 전 항목 선택·이동 가능
- 선택 변경 시 요약 배너가 `aria-live="polite"`로 읽힌다
- 새로고침 후에도 선택이 유지된다

## S2 — 관광지 목록

**경로:** `/[locale]/places`
**목적:** 6곳을 내 조건 기준 적합도로 정렬해 보여준다.

### 구성

```
┌────────────────────────────────────────────────────┐
│ h1  공주·부여 백제역사유적지구                       │
│ [조건 요약] 휠체어 · 오래 걷기 어려움  [조건 바꾸기] │
│                                                     │
│ [탭] ● 목록  ○ 지도        ← 기본은 목록            │
│                                                     │
│ ┌── 카드 ────────────────────────────────────────┐ │
│ │ 공산성                            ⚠ 주의 필요 51 │ │
│ │ 공주시 · 사적                                    │ │
│ │ ⚠ 확인 필요: 엘리베이터                           │ │
│ │ 확인됨: 접근로·출입통로·휠체어·장애인 화장실       │ │
│ │ 정보 없음 17건 / 24건 · 공사 2025-11-03 기준      │ │
│ │                          [상세 보기] [경로 안내] │ │
│ └────────────────────────────────────────────────┘ │
│ ┌── 카드 ────────────────────────────────────────┐ │
│ │ 정림사지                          ? 정보 없음  — │ │
│ │ 부여군 · 사적                                    │ │
│ │ 휠체어 이용에 꼭 필요한 5개 항목 중 4개를 모릅니다 │ │
│ │ → 접근로, 출입통로, 엘리베이터, 장애인 화장실      │ │
│ │                          [상세 보기]             │ │
│ └────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────┘
```

### 동작

- **정렬:** `방문가능` → `주의` → `정보없음` → `대체추천` 순, 같은 라벨 안에서는 점수 내림차순.
  `정보없음`을 맨 뒤가 아니라 중간에 두는 이유: "모르는 곳"이 "못 가는 곳"보다 위다.
- **목록/지도 탭.** 기본은 목록. 지도 탭을 눌러도 **목록은 DOM에서 사라지지 않는다**(`hidden` 속성으로만 감춘다). 스크린리더는 항상 목록을 읽는다.
- 지도(Kakao) 로드 실패 시 지도 탭에 "지도를 불러오지 못했습니다. 목록 탭을 이용하세요"를 표시하고 목록 탭으로 되돌린다.
- 각 카드는 `<article>`, 제목은 `<h2>`.

### 데이터
스냅샷 `pois` + `accessibility` + `context` ([`04_data_model.md`](./04_data_model.md) §3).

**서버 컴포넌트는 사실 데이터만 내려보내고, `calculateSuitability()` 6회는 브라우저가 돌린다.**
페르소나가 `localStorage`에 있으므로 서버에서 계산하면 캐시된 HTML이 모두에게 같아져 조건을 바꿔도 결과가 안 바뀐다 ([`04_data_model.md`](./04_data_model.md) §3.5).
페이지 캐시 `revalidate = 3600` — HTML은 누구에게나 같으므로 캐시가 그대로 유효하다.

### 완료 기준
- 지도 없이 목록만으로 전 관광지의 라벨·점수·근거 요약을 읽을 수 있다
- 조건을 바꾸면 순서와 라벨이 실제로 바뀐다
- `정보없음` 카드에 점수 숫자가 표시되지 않는다

## S3 — 관광지 상세 ★ 핵심 화면

**경로:** `/[locale]/places/[slug]`
**목적:** **판정과 그 근거를 전부 공개한다.** 이 서비스의 존재 이유이자 심사에서 가장 오래 보게 될 화면.

### 구성 — 순서가 중요하다

**결론 먼저, 계산 나중.** 사용자는 "내 일행이 갈 수 있나, 뭘 조심해야 하나"를 먼저 알아야 한다.

### 동작 규칙

| # | 규칙 |
|---|---|
| 1 | **원문을 보여준다.** 앱의 판정(`✓ 확인됨`)과 함께 KTO 원문 문장을 그대로 붙인다. 사용자가 직접 판단할 수 있어야 한다 |
| 2 | **출처를 항목마다 붙인다.** `한국관광공사 무장애여행 · {원래 필드명} · {확인일}`. 필드명(`route`, `elevator`)까지 노출하는 것이 이 화면의 핵심이다 |
| 3 | **`정보 없음`은 (가)/(나)를 구분한다.** "운영자가 입력하지 않은 항목입니다"(개선 가능) vs "사적지 구조상 설치가 어려운 항목입니다"(본질 제약) |
| 3b | **모르는 필수 항목의 이름을 라벨 바로 옆에 반드시 쓴다.** `⚠ 확인 필요: 엘리베이터`. "주의 필요"만 쓰고 무엇을 확인해야 하는지 안 알려주면 판정이 쓸모없어진다 ([`06_suitability.md`](./06_suitability.md) §6.4·§6.6 — **강제 요구사항**) |
| 3c | **`정보 없음 n건 / 24건`을 항상 함께 보여준다.** 점수만 있고 몇 개를 모르는지가 없으면 과신을 부른다 |
| 4 | ④는 **기본 접힘.** 심사·관심 있는 사용자만 펼친다. 일반 사용자에게 수식을 먼저 보이면 안 된다 |
| 5 | ④의 숫자는 **`SuitabilityResult`에서 그대로 렌더링**한다. 화면에서 다시 계산하지 않는다 |
| 6 | ⑧은 **⑦과 시각적으로 확실히 분리**한다. 배경색·아이콘·경고 문구를 다르게 준다 |
| 6b | **⑨ 방문자 제보는 ③ 무장애 정보와 시각적으로 확실히 분리한다.** 배경·아이콘·제목을 다르게 주고, "운영자가 확인한 정보가 아닙니다"를 항상 붙인다. ③은 **우리가 출처를 대고 확인한 사실**이고 ⑨는 **방문자가 한 말**이다. 섞이면 둘 다 신뢰를 잃는다 |
| 6c | **⑨는 적합도 점수에 영향을 주지 않는다.** 제보가 사실이 되는 통로는 사람이 `content/curated-facts.json`에 옮겨 적는 것뿐이다 ([`05_ingest.md`](./05_ingest.md) §4.4) |
| 7 | 사진이 `no_transform = true`(공공누리 3유형)면 `next/image` 최적화를 태우지 않고 `object-fit: contain`으로 원본을 그대로 보여준다 |
| 8 | 도슨트·경로 안내 버튼은 **해당 데이터가 있을 때만** 표시한다 |

### 데이터
- 스냅샷 `pois` · `accessibility` · `routes` · `docent` · `context` · `related`
- 테이블 `barrier_reports` (숨겨지지 않은 것 전부, **캐시하지 않음**)
- 6곳 전체 점수 (대체 관광지용) — 브라우저에서 6회 계산

### 완료 기준
- 24항목 전부가 상태·원문·출처 필드명·확인일과 함께 보인다
- 라벨이 `주의`이고 모르는 필수 항목이 있으면 **그 항목 이름이 라벨 옆에 보인다**
- `정보 없음 n건 / 24건`이 항상 보이고, 그 숫자가 S10 갭 리포트와 같다
- ⑨ 방문자 제보가 ③과 시각적으로 구분되고 "확인한 정보가 아님" 문구가 보인다
- 빈 항목이 (가)/(나)로 구분돼 표시된다
- 계산 내역의 A/B/C/D와 축별 기여값이 전부 보인다
- 스크린리더로 ①→②→③→④ 순서로 자연스럽게 읽힌다

**목적:** 시간 예산에 맞는 코스를 보여주고, 내 조건에서 무리인 구간을 경고한다.

```
h1  당일 코스
[시간 예산] ( )반나절  (•)당일  ( )1박 2일

┌─ 공주 당일 — 공산성 중심 ────────────────────┐

│    ⚠ 주의 필요 64                             │
```

### 동작
- 시간 예산을 바꾸면 다른 템플릿이 선택된다. 목록은 서버에서 미리 계산된 것 중 고르는 것이지 새로 짜는 게 아니다.

- **관광지 점수는 S2·S3과 같은 값을 쓴다.** 같은 조건에서 같은 관광지가 화면마다 다른 점수를 보이면 안 된다.
- "여행 기록에 담기"를 누르면 S9에 코스의 관광지들이 추가된다.

### 완료 기준
- 조건에 따라 총 시간이 실제로 달라진다
- 휴식 경고가 나타나고 사라진다

| 1 | **자동 재생 금지.** 사용자가 재생 버튼을 눌러야 시작 |
| 2 | **대본은 항상 화면에 있다.** 기본은 펼침. 접을 수는 있어도 DOM에서 사라지지는 않는다 |
| 3 | **GPS를 쓰지 않는다.** 이 화면에 들어오는 것 자체가 재생 의사 표시다. `navigator.geolocation`을 호출하는 코드가 앱 전체에 없다 |
| 4 | 재생·일시정지·볼륨은 항상 보이는 실제 `<button>`. 키보드로 조작 가능 |
| 5 | 재생 위치에 맞춰 대본 문단을 강조한다(`aria-current="true"`). `playTime`과 문단 수로 균등 분할하는 근사치로 충분하다 |
| 6 | **대본 내려받기 버튼을 두지 않는다.** 대본은 이미 화면에 HTML로 있고, 스크린리더·점자 디스플레이가 그대로 읽는다. 파일로 한 번 더 주는 것은 아무것도 추가하지 않는다 ([`01_scope.md`](./01_scope.md) §4.4 (2)) |
| 7 | Odii 이야기가 없는 관광지는 이 화면 대신 "오디오 가이드가 제공되지 않는 관광지입니다"와 국가유산청 해설 링크를 보여준다 |
| 8 | 오디오가 없고 대본만 있으면, 브라우저 음성 합성(`SpeechSynthesis`)으로 읽어주는 버튼을 제공하고 **"기기 음성 합성"** 배지를 붙인다 |

### 데이터
스냅샷 `docent` (관광지 × 언어 × 이야기).

### 완료 기준
- 오디오가 재생되고 대본이 함께 보인다
- 영어로 전환된다 (Odii `langCode` 확인 결과에 따름)
- 앱 전체에 `navigator.geolocation` 호출이 0건 (E2E로 검증)

### 동작

| # | 규칙 |
|---|---|
| 1 | 로그인 불필요. Supabase **익명 인증**으로 세션을 만들고 그 `uid`를 `reporter_id`로 쓴다 |
| 2 | **저장 즉시 공개된다.** 대기 상태가 없다. 등록 후 S3 ⑨로 이동해 자기 글이 보이는 것을 확인시킨다 |
| 3 | **서버 측 검사** — 설명 500자 초과 거부, 같은 사람이 같은 관광지·분류로 **24시간 내 재제보 시 거부**(코드에서 검사. 인덱스 술어에 `now()`를 쓸 수 없다 → [`04_data_model.md`](./04_data_model.md) §5.2) |
| 4 | 동의 체크박스는 **필수 1개만.** 마케팅 등 다른 항목을 묶지 않는다 (개인정보보호법 제22조) |
| 5 | 즉시 공개이므로 **동의 문구가 "검수를 거쳐"가 아니라 "즉시 공개"여야 한다.** 개인정보 처리방침도 같은 내용을 적는다 ([`08_accessibility_legal.md`](./08_accessibility_legal.md) §2) |
| 6 | 각 제보 옆에 **[신고]** 버튼을 둔다. 누르면 관리자 목록에서 위로 올라온다 (별도 테이블 없이 `barrier_reports`에 `report_count` 정수 컬럼 하나로 충분하지만, 이번 범위에서는 **버튼만 두고 관리자 화면에서 최신순으로 본다**) |

### 완료 기준
- 제보를 올리면 **즉시** S3 ⑨에 나타난다
- 24시간 내 중복 제보가 거부된다
- 로그인 없이 동작한다

**경로:** `/admin/reports`
**접근:** Supabase 로그인 + `admin_users` 테이블에 있는 계정만. **환경변수로 관리자를 지정하지 않는다.**

**하는 일 두 가지:** ① 부적절한 제보 숨기기 ② 사실로 반영할 것 골라내기

```
h1  방문자 제보  (전체 24건 · 숨김 2건)
```

| # | 규칙 |
|---|---|
| 1 | **[숨기기]** → `is_hidden = true` + 사유·처리자·시각 기록. 되돌리기(`is_hidden = false`)도 가능하다 |
| 2 | 숨겨진 제보는 **본인에게는 계속 보인다**(왜 안 보이는지 알 수 있게). 다른 사용자에게는 안 보인다 |
| 3 | **[항목으로 복사]** → `curated-facts.json` 조각을 클립보드에 넣는다. 관리자가 `capabilityCode`·`status`를 채워 파일에 붙여넣고 커밋한다 |
| 4 | **자동으로 사실이 바뀌는 경로는 없다.** 사람이 파일에 적고 커밋해야만 다음 수집에서 반영된다 ([`05_ingest.md`](./05_ingest.md) §7) |
| 5 | 숨김 처리 후 해당 관광지 페이지를 `revalidatePath`로 갱신한다 |

**[항목으로 복사]가 만드는 조각:**

```jsonc
{
  "poiSlug": "gongsanseong",
  "capabilityCode": "",                    // ← 관리자가 채운다
  "status": "",                            // ← 관리자가 채운다
  "detail": "동문 쪽 계단 보수 공사로 통행이 막혀 있습니다",
  "source": "방문자 제보 #a1b2c3 확인 후 ○○ 로 교차 확인",   // ← 확인 경로를 적는다
  "checkedAt": "2026-09-18"
}
```

> **이 흐름이 감사 기록 그 자체다.** "왜 이 값이 바뀌었나"는 `git log`가 답한다. 별도 이력 테이블이 필요 없다.

### 완료 기준
- 관리자가 아닌 계정으로 `/admin/reports`에 접근하면 차단된다
- 숨기면 다른 사용자 화면에서 즉시 사라진다
- [항목으로 복사]가 유효한 JSON 조각을 만든다

| 1 | **`localStorage`에만 저장.** 서버에 올리지 않는다. 개인정보 수집이 없다 |
| 2 | 저장 구조에 `schemaVersion`을 둔다. 나중에 구조가 바뀌어도 옛 기록을 읽을 수 있게 |
| 3 | **텍스트로 내보내기(.txt)** — 마크업·표·이모지 없는 순수 텍스트, 한 줄에 한 정보. 메모 앱·이메일에 붙여넣거나 다른 기기로 옮기는 용도다. **"점자용"이라고 쓰지 않는다** — 점자 지원은 접근성 있는 HTML 자체다 |
| 4 | GPX는 방문한 관광지의 좌표 + 경로 단계 좌표로 생성 |
| 5 | "접근성 한 줄"에 쓴 내용은 **S7 제보 폼으로 넘길 수 있다.** 이게 사용자 기록 → 다음 방문자 → 데이터 개선으로 이어지는 고리다 |

### 도메인 함수 (`src/domain/diary.ts`)


### 우선순위 계산 (`src/domain/gap.ts`)

```
우선순위 = 영향 × 심각도 × 실현가능성

영향       = 이 항목이 어떤 페르소나의 critical 이면 1.0, 아니면 0.5
심각도     = unknown 1.0 / unsupported 0.2   (모르는 게 없는 것보다 급하다)
실현가능성 = absence_kind 가 operator_missing 이면 1.0
             intrinsic 이면 0.1
             not_applicable 이면 제외
```

> **핵심 아이디어:** "엘리베이터가 없다"와 "엘리베이터 정보가 없다"는 **완전히 다른 문제**다. 앞은 공사가 필요하고 뒤는 입력 한 번이면 된다. 지자체 담당자에게 유용한 건 뒤쪽 목록이다. 이 구분이 리포트의 전부다.

### 동작
- **정보 없음 개수는 관광지 상세(S3 ③)의 숫자와 반드시 같다.** 같은 `accessibility` 스냅샷 배열을 센다 — 계산이 한 곳에만 있으므로 갈라질 수가 없다.
- 집계는 SQL 뷰가 아니라 **코드 20줄**이다 (6곳뿐).
- CSV 헤더: `관광지,항목코드,항목명,상태,부재유형,우선순위,출처,확인일`
- 방문자 추이는 숫자만 표시하고 **주의 문구를 `role="note"`로 항상 보이게** 둔다. `display:none` 금지.
- 지자체 담당자가 그대로 쓸 수 있게 표는 `<caption>`과 `<th scope>`를 갖춘 진짜 `<table>`.

### 완료 기준
- 6곳 채움률이 표시된다
- 우선순위 표에서 "개선 가능"과 "구조 제약"이 시각적으로 구분된다
- CSV가 내려받아진다
- 방문자 주의 문구가 항상 보인다

## 화면 간 데이터 흐름 — "한 번 모은 데이터가 어디까지 가는가"

이 서비스의 주장은 "기능이 많다"가 아니라 **"하나의 데이터가 다섯 군데로 흐른다"** 이다. 발표에서 이 그림 하나를 보여주면 된다.

```
KorWithService2 / detailWithTour2  (무장애 24항목)
        │
        ▼
  스냅샷 'accessibility'
  (관광지 · 항목코드 · 상태 · 원문 · 출처필드 · 확인일)
        │
        ├──▶ S2 목록      : 라벨과 정렬 순서를 정한다
        ├──▶ S3 상세      : 원문·출처·계산 근거를 전부 공개한다
        ├──▶ S5 경로 안내 : 어떤 단계에 무엇을 주의할지 정한다
        ├──▶ S9 여행 기록 : 인쇄물에 "이 코스의 접근성"으로 들어간다
        └──▶ S10 갭 리포트: 비어 있는 항목이 개선 우선순위가 된다


별도 흐름 — 방문자가 말한 것
        S7 제보 ──즉시──▶ S3 ⑨ 방문자 제보 (다음 방문자가 본다)
                              │
                              │ 관리자가 검토
                              ▼
                    content/curated-facts.json 에 사람이 적고 커밋
                              │
                              ▼
                    다음 수집 → 스냅샷 → 위 다섯 화면 전부에 반영
```

**두 흐름을 분리한 것이 핵심이다.** 위는 **우리가 출처를 대고 확인한 사실**, 아래는 **방문자가 한 말**이다. 아래가 위로 올라가려면 반드시 사람의 판단과 git 커밋을 거친다.

**검증:** 같은 항목 하나(예: 공산성 `elevator`)를 S3 · S5 · S9 · S10에서 전부 찾을 수 있는지를 E2E 테스트 하나로 확인한다 → [`09_test_and_ci.md`](./09_test_and_ci.md) §5.1.
