# 08 — 웹 접근성 + 법적 표시

> 무장애 관광 서비스가 정작 웹 접근성을 못 지키면 자기모순이다. 이 문서의 §1은 **선택이 아니다.**
> §2~§4는 법적 최소 요건이다. 이전 기획의 접근성·법무 문서에서 **상업 운영용 장치를 걷어내고 실제 의무만** 남겼다. **조문 번호와 검사항목 번호의 근거는 [`13_legal_citations.md`](./13_legal_citations.md)** 에 모아 뒀다.

## 1. 웹 접근성 (KWCAG 2.2)

**기준:** 한국형 웹 콘텐츠 접근성 지침 2.2 (KS X OT0003, 2022-12-28) — 4원칙 · 14지침 · **33개 검사항목**
**법적 근거:** 지능정보화 기본법 계열 · 디지털포용법 · 장애인차별금지법 — **조문 번호는 [`13_legal_citations.md`](./13_legal_citations.md) §7에서 확인 후 인용한다.** 이 문서 세트의 규칙은 "원문으로 확인한 것만 번호로 쓴다"다

### 1.1b 점자 지원 = 위 목록 그 자체

**이 서비스의 점자 지원은 별도 기능이 아니라 §1.1이다.**

점자정보단말기 사용자는 스크린리더 + 점자 디스플레이로 **화면 내용을 실시간 점역해서 읽는다.** 따라서 위 목록(제목 구조·랜드마크·라벨·포커스 관리·표 마크업)이 제대로 지켜지면 점자로 읽힌다. 별도의 점자 파일이나 텍스트 파일을 만드는 것은 **거의 아무것도 추가하지 않는다** ([`01_scope.md`](./01_scope.md) §4.4 (2)).

**검증 방법:** §1.4의 NVDA 수동 과업 A·B·C가 이걸 확인한다. 여기서 통과하면 점자 디스플레이에서도 읽힌다.

**쓰면 안 되는 표현:** "점자 채널", "점자 지원", "점자 호환 텍스트". 정식 점자(한국점자규정 점역 + 전문가 검수 + 엠보서 출력)는 발전 방향이다.

### 1.2 지도 — 가장 비싸지만 반드시 해야 하는 것

KWCAG 2.2에서 **「단일 포인터 입력 지원」이 새로 들어왔다.** 드래그·핀치로만 되는 기능이 있으면 위반이다. (§1.1의 규칙대로 **검사항목 번호를 말하지 않고 지침 이름으로** 쓴다. 번호 대응은 [`13_legal_citations.md`](./13_legal_citations.md) §2.2)

| 필수 | 내용 |
|---|---|
| **목록이 항상 존재한다** | **`hidden`·`display:none`·`aria-hidden`으로 감추지 않는다** — 셋 다 접근성 트리에서 요소를 제거하므로 스크린리더가 못 읽는다. 이번 범위는 **탭을 쓰지 않고 목록을 항상 보이게 두고 지도를 아래에 붙인다** ([`07_screens.md`](./07_screens.md) S2 동작) |
| **버튼으로 되는 확대/축소/이동** | `<button aria-label="지도 확대">` `"지도 축소"`. 방향키 이동 핸들러 |
| **드래그·핀치 전용 기능 금지** | 모든 동작에 버튼 대안 |
| **마커는 실제 DOM** | Kakao `CustomOverlay` 사용. 래스터 마커는 스크린리더에 안 보인다 |
| 마커 Enter/Space = 클릭, `aria-label` = 관광지명 + 판정 요약 | — |
| 지도 캔버스는 axe 검사에서 제외(`.map-canvas`) + **수동 점검 항목으로 대체** | 자동 검사가 못 보는 영역이라 제외하는 것이지 면제가 아니다 |

**타협안:** 시간이 부족하면 **지도를 통째로 빼도 된다.** 목록만으로 모든 기능이 동작하도록 설계했기 때문이다. 반쯤 접근 가능한 지도보다 **없는 게 낫다.** (탭이 없으므로 지도를 빼도 화면 구조가 바뀌지 않는다 — 블록 하나가 사라질 뿐이다)

### 1.3 자동 검사 (CI에는 1개만)

| 도구 | 어디서 | 무엇을 |
|---|---|---|
| `eslint-plugin-jsx-a11y` | **CI (`pnpm lint`)** | 8개 규칙 `error` 승격: `alt-text`, `anchor-is-valid`, `aria-props`, `aria-role`, `interactive-supports-focus`, `label-has-associated-control`, `media-has-caption`, `no-redundant-roles` |
| `scripts/check-contrast.ts` | **CI (빌드 전)** | 색상 토큰 대비율. 20줄짜리 스크립트 |
| `@axe-core/playwright` | **로컬 (`pnpm e2e`)** | 아래 **6개 경로** 스캔, 위반 0 목표 |
| Lighthouse | **수동 1회** | 제출 직전 접근성 점수 확인용 스크린샷 |

**대비율 검증 스크립트 주의:** 기준을 **토큰 종류마다 다르게** 잡는다.

```ts
// scripts/check-contrast.ts
// 기준 자체가 다르다 — 본문 글자 4.5:1, 큰 글씨(18pt+ / 14pt bold+)와
// UI 테두리·그래픽 3:1. 전부 4.5로 검사하면 '큰 글씨'로 쓰라고 만든
// 토큰을 본문 기준으로 재는 것이 되어, 기준을 잘못 적용한 실패가 난다.
const MIN_RATIO = { body: 4.5, large: 3.0, ui: 3.0 } as const;
```

> **기준을 나누는 근거는 표준이다** — 큰 글씨에 3:1을 허용하는 것은 접근성 기준 자체의 규정이고, 우리 토큰값이 어떻든 스크립트는 그 기준으로 검사해야 한다.
> **토큰의 실제 대비율은 [`13_legal_citations.md`](./13_legal_citations.md) §2.4에서 계산해 확인했다.** 이전 스펙 문서에 적혀 있던 값들은 대부분 실제 계산과 달랐으므로(예: `#1A1A1A`/`#FFFFFF`를 21.0으로 적었는데 실제는 17.40), **문서에 적힌 비율을 골든값으로 쓰지 않고 스크립트가 색상값에서 매번 계산한다.**

**axe 스캔 대상 경로 — 이 목록이 단일 권위다 (6개):**
`/ko` · `/ko/places` · `/ko/places/gongsanseong` · `/ko/places/gongsanseong/route-guide` · `/ko/report` · `/ko/gap-report`

> 앞 판은 두 곳에서 "5개"라고 쓰면서 여기 6개를 나열했다. **개수를 다시 쓰지 않고 이 목록을 센다.**

### 1.4 수동 검사 (범위를 줄인다)

기존 스펙은 **5개 스크린리더 × 7개 과업 = 35칸** 매트릭스를 요구했다. 센스리더와 JAWS는 유료 제품이다.

**하는 것: NVDA + Chrome (Windows), 과업 3개.** 3시간이면 끝나고 실제 실패 유형은 거의 다 잡힌다.

| 과업 | 확인 내용 |
|---|---|
| A | 홈에서 조건 3개 선택 → 목록 → 공산성 상세 → 판정과 근거를 소리만으로 파악 |
| B | 도슨트 재생·정지, 대본이 읽히는지 |
| C | 지도를 붙였을 때 그 아래·위의 목록이 계속 읽히는지, 제보 폼 라벨이 읽히는지 |

**안 하는 것:** WA/KWACC 정식 인증 신청(비용·기간은 [`13_legal_citations.md`](./13_legal_citations.md) §2.5가 단일 권위다), 5개 스크린리더 매트릭스, K-WAH 자가진단 결과서(2.0 시대 도구다. 필요하면 OpenWAX를 쓴다).

### 1.5 과장하지 않기

axe-core 자동 검사는 KWCAG 33개 항목의 **30~50% 정도만** 잡는다. **"axe 위반 0건 = 접근성 준수"가 아니다.**

화면과 발표에는 이렇게 쓴다:
> **"KWCAG 2.2 자체 점검 (axe-core 자동 검사 + NVDA 수동 검증)"**

이렇게 쓰지 않는다:
> ~~"KWCAG 2.2 인증"~~ · ~~"웹 접근성 인증 획득"~~

## 2. 개인정보 (개인정보보호법)

이 서비스가 실제로 수집하는 개인정보는 **익명 식별자(UUID)와 제보 본문** 둘이다. 회원가입도, 위치 정보도, 사진도, 결제도 없다.

> 앞 판은 "제보 본문뿐"이라고 쓰고 두 줄 뒤 §2.1에서 UUID를 처리 항목으로 적었다. **처리방침이 실제 저장 항목보다 적게 고지하면 그 자체가 누락이다** — `barrier_reports.reporter_id`가 그 UUID다([`04_data_model.md`](./04_data_model.md) §5.2).

**제보는 올리는 즉시 공개된다.** 이건 처리방침과 동의 문구에 그대로 써야 한다.

### 2.1 필수 — 개인정보 처리방침 (`/privacy`)

한국어로, 첫 이용 전에 접근 가능해야 한다 (제30조).

> **★ 담아야 할 항목의 단일 권위는 [`13_legal_citations.md`](./13_legal_citations.md) §3.1이다 (14항목).** 아래 목록은 앞 판이 11항목만 적어 **13의 최종 목록과 갈라져 있었다** — 자동수집장치·행태정보·가명정보 세 항목이 빠져 있었고, 이 문서만 보고 구현하면 법정 기재 사항이 누락된다.
>
> **그래서 이 문서는 목록을 소유하지 않는다.** 아래는 읽는 사람의 편의를 위한 요약이고, **개수를 세거나 이 목록으로 완료 판정을 하지 않는다.** 완료 판정은 13 §3.1의 14행을 하나씩 대조한다.

요약(권위 아님):

1. 처리 목적 — 현장 접근성 정보의 공유
2. 처리 항목 — 익명 식별자(UUID), 제보 내용 (**사진은 받지 않는다**)
3. 보유 기간 — 공개 제보는 서비스 운영 기간 동안 / **숨김 처리된 제보는 90일 후 삭제**
4. 제3자 제공 — 없음
5. **처리 위탁** — Supabase Inc.(서울 리전, 데이터베이스·저장소) / Vercel Inc.(호스팅) / Kakao Corp.(지도 SDK, 국내)
6. **국외 이전** — Vercel Inc.(미국). 이전 항목: 공개 관광 정보와 요청 로그. 개인정보는 서울 리전 Supabase에만 저장
7. 정보주체의 권리 — 열람·삭제·처리정지 요구 방법과 연락처
8. **개인정보 보호책임자** — 이름과 연락처
9. 안전성 확보 조치 — 전송 구간 TLS, 저장 암호화, 행 수준 보안(RLS), 최소 권한
10. 파기 절차
11. 처리방침 변경 시 고지 방법

### 2.2 필수 — 동의

**동의 체크박스는 딱 1개:**
> "위 내용이 **즉시 공개**되는 것에 동의합니다."

**"검수를 거쳐"라고 쓰면 안 된다.** 실제로는 검수 없이 바로 공개되므로 사실과 다르다.
마케팅·선택 항목을 **묶지 않는다** (제22조 — 필수와 선택을 섞으면 위반).

### 2.3 즉시 공개 모델의 안전장치

사전 검수가 없으므로 다음이 필요하다.

| 장치 | 내용 |
|---|---|
| **사진을 받지 않는다** | 초상권·위치 EXIF 문제가 원천적으로 사라진다 ([`01_scope.md`](./01_scope.md) §4.4 (4)) |
| **입력 화면에 경고** | "다른 사람의 이름·연락처·얼굴이 드러나는 내용은 쓰지 마세요" |
| **관리자 사후 숨김** | `is_hidden = true`. 사유·처리자·시각을 기록 ([`07_screens.md`](./07_screens.md) S8) |
| **신고 버튼** | 각 제보 옆. `flag_report()` RPC가 **`flagged_at`을 처음 한 번만** 채우고 관리자 목록이 신고된 것을 먼저 보여준다 ([`04_data_model.md`](./04_data_model.md) §5.3). **자동 숨김은 없다.** 그리고 **횟수를 세지 않는다** — 카운터를 두면 익명 사용자가 무한히 올려 관리자의 주의 순서를 조작할 수 있다 |
| **90일 후 실제 삭제** | 숨김 처리된 제보는 수집 스크립트가 지운다 ([`05_ingest.md`](./05_ingest.md) §7). **처리방침에 쓴 것을 실제로 지키는 코드가 있어야 한다** |
| **본인에게는 계속 보임** | 숨겨져도 작성자 본인은 자기 글을 볼 수 있다 (왜 안 보이는지 알 수 있게) |

### 2.4 안 해도 되는 것 — 그리고 왜

| 항목 | 이유 |
|---|---|
| **위치기반서비스사업 신고 (위치정보법 제9조 계열)** | **개인위치정보를 일절 수집·이용·제공하지 않는다.** `navigator.geolocation`을 호출하는 코드가 앱에 없고, 제보에도 좌표를 저장하지 않으며, 도슨트는 관광지를 선택해 재생한다. 따라서 **위치기반서비스사업자에 해당하지 않아** 신고 의무 자체가 발생하지 않는다 |
| 위치정보 보호책임자 지정·공시 | 위와 동일 |
| 위치정보 접근 기록 6개월 보관 (제16조) | 위와 동일 |
| 통신판매업 신고 / 여행업 등록 | 결제·예약·중개가 없다 |
| 이용자 데이터 자가 조회·삭제 화면 | 법이 요구하는 건 요구에 응하는 것이고, 연락처 공개로 충족된다 |
| 감사 로그 5년 보관 / 월간 접근 기록 점검 | 상업 운영 절차. 운영자 1명 |

> **이건 "안 지켜도 된다"가 아니라 "해당하지 않는다"이다.** GPS 기능을 나중에 켜면 위치정보법 신고가 다시 필수가 된다.
>
> **조문 번호를 말할 때 주의 [미확인].** 신고 **의무**를 정한 조문과 신고 **면제**를 정한 조문(1인 창조기업·소상공인 대상)은 다른 조항이다. 우리 논지는 "면제받는다"가 아니라 **"해당하지 않는다"** 이므로, 면제 조항을 인용하면 오히려 "우리는 위치기반서비스사업자다"라고 인정하는 셈이 된다. 발표에서 조문 번호를 말할 거면 **법제처 원문으로 확인한 뒤** 말하고, 확인 전에는 조문 없이 **"개인위치정보를 수집하지 않으므로 위치정보법상 신고 대상이 아니다"** 로만 말한다 → [`13_legal_citations.md`](./13_legal_citations.md) §1.

## 3. 저작권 / 라이선스 (공공누리)

### 3.1 유형

| 유형 | 의미 | 변형 | 상업 |
|---|---|---|---|
| 제1유형 | 출처 표시 | 가능 | 가능 |
| 제2유형 | 출처 표시 + 비상업 | 가능 | **금지** |
| 제3유형 | 출처 표시 + **변경 금지** | **금지** | 가능 |
| 제4유형 | 출처 표시 + 비상업 + 변경 금지 | **금지** | **금지** |

### 3.2 우리가 쓰는 자산

| 자산 | 라이선스 | 처리 |
|---|---|---|
| KTO 관광 정보 텍스트 | 공공누리 1유형 | 출처 표시 |
| KTO 이미지 (`cpyrhtDivCd=Type1`) | 1유형 | 출처 표시 + 리사이즈 가능 |
| **KTO 이미지 (`cpyrhtDivCd=Type3`)** | **3유형** | **자르기·필터·합성·리사이즈 전부 금지.** `next/image` 최적화도 태우지 않고 원본 그대로 `object-fit: contain` |
| **관광사진갤러리** | **[미확인]** | **매뉴얼에 공공누리·저작권 서술이 한 줄도 없고 `cpyrhtDivCd` 필드도 없다** ([`03_external_data.md`](./03_external_data.md) §2.7). **1유형이라고 쓰지 않는다.** 출처(촬영자 포함)를 표기하고 **변형하지 않는다** |
| **Odii 오디오·대본** | **[미확인]** | 같은 이유 — 오디 매뉴얼에도 라이선스 서술이 없다. 출처 표기하고 **원문 그대로** 쓴다 |
| 국가유산청 해설 | 1·4유형 혼재 | **4유형 항목은 원문 그대로만 인용.** 재편집 금지 |
| Pretendard 폰트 | SIL OFL 1.1 | 웹 임베드 가능 |

**여러 출처를 합칠 때는 가장 제한적인 것을 따른다.** 예: 1유형 + 4유형을 한 페이지에 넣으면 그 페이지는 4유형 조건(비상업 + 변경 금지)을 따른다.
공모전 출품 자체는 상업적 이용이 아니므로 2·4유형 조건을 충족한다. 수상 후 실제 운영 시 재검토가 필요하다.

### 3.3 표시 위치

| 위치 | 문구 |
|---|---|
| 모든 페이지 푸터 | `출처: 한국관광공사 TourAPI (https://api.visitkorea.or.kr/) · 이용 조건은 자산별로 표기` — **유형을 하나로 고정하지 않는다.** 이미지가 1·3유형 혼재이고 국가유산청 해설이 1·4유형 혼재이므로, 한 유형을 전 페이지에 박으면 §3.2의 최고 제약 원칙과 충돌한다 |
| Type3 이미지 옆 | `출처: 한국관광공사 · 공공누리 제3유형 (변경금지)` |
| 관광사진 옆 | `출처: 한국관광공사 관광사진갤러리 · {촬영자}` — **공공누리 유형을 쓰지 않는다.** 매뉴얼에 근거가 없다 ([`13_legal_citations.md`](./13_legal_citations.md) §4.2) |
| 도슨트 화면 | `출처: 한국관광공사 Odii 오디오 가이드` |
| 국가유산청 인용 | `출처: 국가유산청` |
| 방문자 수 표시 화면 | `방문자는 관광객과 동일하게 정의되지 않습니다 (출처: 한국관광 데이터랩)` ← **문자열 고정.** [`04_data_model.md`](./04_data_model.md) §3.3의 `caveat: z.literal(...)`이 이 값을 강제하므로 다르게 쓰면 Zod 검증이 payload를 거부한다 |
| 인쇄용 문서 하단 | 위 문구 전부 |

스냅샷 `pois[].media[].attribution`에 **완성된 문구를 저장**하고 화면에서는 그대로 출력한다. 화면에서 문자열을 조합하지 않는다.

## 4. 인공지능 (인공지능 기본법)

**시행: 2026-01-22.** 유예 기간이 있지만 **유예되는 건 과태료와 사실조사이고 표시 의무 자체는 지금 적용된다.**

### 4.1 이 서비스에는 생성형 AI가 없다

| 기능 | AI 사용? |
|---|---|
| 관광 정보 | 아니오 — 한국관광공사 API 원문 |
| 다국어 | 아니오 — 한국관광공사 다국어 서비스의 공식 번역 |
| 도슨트 오디오·대본 | 아니오 — 한국관광공사 Odii 제작물 |
| 적합도 점수 | 아니오 — 결정적 수식 |
| 코스 | 아니오 — 미리 짜 둔 템플릿 선택 |

**따라서 "AI 번역" · "AI 생성 코스" 배지는 붙일 데가 없다.** 그리고 발표에서도 "AI가 추천합니다" 같은 말을 하지 않는다 — 사실이 아니다.

### 4.2 딱 한 군데 예외 — 기기 음성 합성

도슨트에 오디오가 없고 대본만 있을 때, 브라우저 `SpeechSynthesis`로 읽어주는 버튼을 제공한다. 이건 합성 음성이므로 표시한다.

```tsx
<span role="img" aria-label="기기 음성 합성으로 읽어줍니다">기기 음성 합성</span>
```

**규칙:**
- 실제 DOM 텍스트로 넣는다. CSS로만 표시하면 스크린리더가 못 읽는다
- `role="img"` + `aria-label`을 함께 준다. 빈 `<span aria-label>`은 역할이 없어 노출이 불안정하다
- **접근 가능한 이름이 보이는 글자를 포함**해야 한다 (「레이블과 네임」 — §1.1과 같은 항목. 번호로 부르지 않는다)

### 4.3 향후 AI를 넣게 되면

- 이용약관·첫 화면에 **사전 고지** (제31조 제1항)
- 출력물마다 **표시** (제31조 제2항)
- 외부로 배포되는 문서(인쇄물·텍스트 파일)에는 **문서 안에 표시를 넣어야 한다.** 화면 배지만으로는 부족하다

관광 정보 서비스는 고영향 인공지능(의료·금융·공공·교통·에너지·채용)에 해당하지 않으므로 **영향평가 의무는 없다.**
