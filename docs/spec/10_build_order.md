## 0. 순서를 정하는 원칙

1. **가정을 먼저 죽인다.** 6곳이 무장애여행 API에 없으면 프로젝트 형태가 달라진다. 이걸 4주차에 알면 늦다.
2. **한 관광지가 끝까지 흐르게 만든 다음 옆으로 넓힌다.** 공산성 하나가 S2→S3→S5→S9→S10을 관통한 뒤에 나머지를 붙인다. 6곳 × 10화면을 동시에 진행하면 아무것도 안 끝난다.
3. **점수 로직을 제일 먼저 만든다.** 외부 의존이 0이고, 만들면서 [`06_suitability.md`](./06_suitability.md)의 빈틈이 드러난다.
4. **매주 금요일에 컷 라인을 본다.** 밀렸으면 그 주의 컷 목록을 자동 적용한다. 다시 묻지 않는다.

> **2026-09-01 구조 변경으로 약 1주가 절약됐다.** 테이블 18개 → 3개, 마이그레이션 8개 → 2개, 뷰 2개 → 0, 제보 사진 파이프라인 삭제 ([`04_data_model.md`](./04_data_model.md) §7). 그 여유는 **경로 콘텐츠 작성(2주차)과 접근성 다듬기(4주차)** 에 쓴다 — 둘 다 시간이 곧 품질인 작업이다.

### 경로 데이터 작성 방법 (현장에 못 가는 조건에서)

이게 2주차의 가장 큰 작업이다. 순서:

1. 카카오맵 로드뷰 / 위성 이미지로 출입구와 주 동선을 확인
2. 관광지 공식 홈페이지의 안내도·시설 안내 확인
3. 한국관광공사 관광사진갤러리에서 해당 지점 사진 확보
4. 5단계 내외로 나누고 각 단계에 `title` / `easyText` / `distanceM` / `surface` / `slopeNote`(서술) / `hazard` 작성
5. **`evidenceLevel: "desk"`, `evidenceNote`에 "현장 실측 미실시" 명기**

> **넘지 말아야 할 선:** 경사도를 숫자로 쓰지 않는다 — `8.5%`도, `1:12`도, `0.08`도, `8°`도. **`slopeNote`는 허용 목록 안의 값과 정확히 일치해야 하고**, `pnpm validate:content`가 그걸 검사한다 ([`09`](./09_test_and_ci.md) §4). 금지할 문자를 세는 대신 허용할 값을 세는 쪽이 빈틈이 없다.

### 주말 판정 (9/21) — **컷 게이트 2**

**"제보를 올리면 즉시 상세 화면에 뜨고, 여행 기록이 인쇄되고, 갭 리포트가 뜬다."**

**밀렸으면 자동 적용 (이 순서로):**
1. 도슨트 영어 → 한국어만
2. 쉬운 글 모드 → 원문만
3. S9 GPX 내보내기 → 인쇄용 + 텍스트만
4. S8 관리자 화면 → **직접 SQL로 숨김 처리.** `supabase/seed.sql`에 예시 제보를 넣어 S3 ⑨ 시연은 유지
5. S7 제보 폼 → 삭제. 대신 시드 제보로 S3 ⑨만 시연

> **★ 컷하면 E2E 필수 흐름도 같은 게이트에서 함께 줄인다.** [`09_test_and_ci.md`](./09_test_and_ci.md) §5.1의 골든 플로우는 **GPX 내려받기(10번)와 제보 등록(17번)을 반드시 검사**한다. 그런데 이 컷 목록은 그 둘을 지울 수 있게 열어 뒀다 — **컷을 적용하면 "필수" E2E가 스펙 자신 때문에 실패하고, 완료 판정이 불가능해진다.**
>
> **규칙:** 컷을 적용하는 그 자리에서 **골든 플로우의 해당 단계도 함께 지운다.** 지운 단계는 커밋 메시지에 적는다. 테스트를 끄지 않고 **지운다** — 만들지 않기로 한 것을 요구하는 검사는 규칙에서 지운다는 [`09`](./09_test_and_ci.md) §6의 원칙과 같다.
>
> **★ S10의 방문자 추이도 컷 목록에서 뺐다.** 잘리면 `DataLabService`가 사라져 10종이 9종이 된다. 구현은 **수집 1단계 + 숫자 3줄 + 주의 문구**다. ⑧과 같은 이유로 배점 20점을 지키는 쪽이 싸다.
>
> **4·5번을 자르면 "방문자 제보 → 데이터 개선" 고리가 시연에서 빠진다.** 마지막 순서에 둔 이유다.
>
> **컷 게이트의 상위 규칙 — API 1종을 없애는 컷은 하지 않는다.** 공고문이 심사 대상을 "공사 OpenAPI 필수 활용하여 개발 완료된 완성 서비스"로 한정하고, 데이터 활용 적절성이 20점이다. **10종 중 몇 종을 실제로 쓰는가는 제안서가 이미 약속한 숫자이므로, 그것을 깎는 컷은 다른 어떤 컷보다 비싸다.**
