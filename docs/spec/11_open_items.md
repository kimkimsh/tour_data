### P0-1 ★★★ — 6곳이 무장애여행 API에 등록돼 있는가

**이 프로젝트에서 가장 중요한 질문이다.**

```
GET KorWithService2/detailWithTour2?contentId={각 6곳}
```

| 결과 | 의미 |
|---|---|
| `resultCode = 0000` + 항목에 값이 있음 | 정상. 계획대로 |
| `resultCode = 0000` + 전 항목 빈 문자열 | 등록은 됐지만 운영자가 안 채움. **이게 갭 리포트의 정확한 근거가 된다** |
| `resultCode = 03` | **무장애여행 서비스에 없음.** 그 관광지는 24항목 전부 `unknown` |

**분기 판단은 [`10_build_order.md`](./10_build_order.md) Day 1~2 참조.**

> **★ 이전 기획 문서에 `contentId` 후보가 3세트 있었고 서로 다르다.** 예: 공산성이 `2634812` / `264736` / `126121`로 적힌 세 곳이 있다. 좌표도 두 세트가 서로 어긋난다(반경보다 크게). **어느 값도 믿지 말고 아래 조회로 새로 얻는다.** 옛 값을 시드에 넣으면 조용히 다른 관광지 데이터를 수집한다.

**선행 작업:** 6곳의 `contentId`를 먼저 찾아야 한다.
```
GET KorService2/areaBasedList2?lDongRegnCd=44&lDongSignguCd=150&contentTypeId=12&numOfRows=100
GET KorService2/areaBasedList2?lDongRegnCd=44&lDongSignguCd=150&contentTypeId=14&numOfRows=100
GET KorService2/areaBasedList2?lDongRegnCd=44&lDongSignguCd=760&contentTypeId=12&numOfRows=100
GET KorService2/areaBasedList2?lDongRegnCd=44&lDongSignguCd=760&contentTypeId=14&numOfRows=100
→ title 로 6곳을 찾아 contentid 확보 → content/pois.json
```
(`KorWithService2/areaBasedList2`로도 같은 조회를 해서 **무장애 대상 목록에 있는지 교차 확인**한다. 이쪽이 더 직접적인 답이다.)

### P0-3 — Odii에 6곳 콘텐츠가 있는가

```
GET Odii/themeSearchList?keyword={관광지명}&langCode=ko
GET Odii/storyLocationBasedList?mapX={경도}&mapY={위도}&radius=1000&langCode=ko
```

**두 방법 다 시도한다.** 어느 하나라도 `tid`가 나오면 `storyBasedList`로 이야기 목록을 확인한다.

| 결과 | 대응 |
|---|---|
| 공산성·부소산성 둘 다 있음 | 도슨트 화면 정상 진행 |
| 한 곳만 | 있는 곳만 도슨트 제공. 없는 곳은 안내 문구 |
| 둘 다 없음 | **도슨트 화면을 국가유산청 해설 + 기기 음성 합성으로 대체**하거나 기능을 뺀다 |

> **좋은 신호:** Odii 매뉴얼의 예시 응답이 `themeCategory: "백제역사여행"`, `title: "백제문화단지"`, `addr2: "부여군"` 이다. 백제권 콘텐츠가 실제로 있다는 뜻이다.

### P0-4 — Odii `langCode`의 실제 값

**매뉴얼에 값 목록이 없다.** 기존 문서들이 서로 다른 주장을 한다.

```
같은 호출을 langCode 값만 바꿔가며 6회:
  ko / en / ja / jp / zh-CN / cn1
→ resultCode 와 totalCount 를 기록
```

추가로: `themeSearchList`의 파라미터 이름이 **`lang`인지 `langCode`인지** 확인한다 (매뉴얼의 표와 예시 URL이 서로 다르다).

### P0-7 — 백제역사유적지구 구성유산 8곳의 공식 명칭 (사람이 직접, 필수)

**이 항목의 내용이 바뀌었다.** 원래는 "제안서의 `史477` 계열 지정번호 정정"이었는데, **제출된 제안서에 그 표기가 없다** — 이전 기획 문서에만 있었다. 정정할 대상이 없으므로 실제로 확인이 필요한 것으로 교체한다.

**확인할 것:**

| # | 확인 내용 | 왜 |
|---|---|---|
| 1 | **백제역사유적지구(2015년 등재) 구성유산 8곳의 공식 명칭과 소재 시군** | 제안서·기획안·발표에서 "8개 구성유산 중 6개가 공주·부여"라고 말한다. 틀리면 지역특화 근거가 무너진다 |
| 2 | 우리 6곳 중 **어느 것이 구성유산이고 어느 것이 아닌지** | 국립공주·부여박물관은 구성유산이 아니다. 6곳을 전부 구성유산처럼 쓰면 사실과 다르다 |
| 3 | 「관북리 유적과 부소산성」이 **하나의 구성유산**인지 | 우리는 부소산성만 다룬다. 명칭을 쪼개 쓰면 지적당한다 |
| 4 | 「무령왕릉과 왕릉원」의 개칭 연도와 구 명칭(송산리 고분군) | 확장 목록에 구 명칭을 다시 넣는 실수를 막는다 |
| 5 | 각 관광지의 **사적 지정 명칭** (`사적 「공주 공산성」` 형태) | `pois.json`의 `heritageLabel`에 들어간다 |

**확인처:** 국가유산청 국가유산포털(`heritage.go.kr`) · 유네스코 세계유산 등재 목록
**결과 반영:** `content/pois.json`의 `heritageLabel`. **불확실하면 `null`로 두고 화면에 아무것도 쓰지 않는다.**

> 지정번호는 쓰지 않는다. 부수 효과로 한자 폰트 글리프 문제(Pretendard에 한자가 없다)도 사라진다.
> 리포지토리 안의 조사 문서조차 구성유산 목록이 틀려 있었으므로(정지산을 넣고 익산 2곳을 뺀 기록이 있다) **원 출처로만 확인한다.**

### P0-9 — 매뉴얼 표기 불일치 확인 (5군데)

매뉴얼 자체에 표와 예시가 어긋나는 곳이 **5군데**다. 이름은 두 쪽을 다 호출해 200이 오는 쪽을 쓰고, 필드는 두 이름을 다 읽어 값이 있는 쪽을 쓴다.

| # | 서비스 | 표기 A | 표기 B | 종류 |
|---|---|---|---|---|
| 1 | TatsCnctrRateService | `tatsCnctrRateList` (표) | `tatsCnctrRatedList` (예시 URL) | 오퍼레이션명 |
| 2 | Odii | `themeBaseSyncdList` (표) | `themeBasedSyncList` (예시 URL) | 오퍼레이션명 |
| 3 | TarRlteTarService1 | `AreaBasedList1` (표) | `areaBasedList1` (예시 URL) | 오퍼레이션명 |

### P0-10 — `contentId`가 국문/다국어에서 같은 값인가 ★★

**수집 설계가 여기에 전면 의존한다.** 매뉴얼에 "동일"이라는 서술이 없고 세 다국어 매뉴얼이 서로 다른 샘플 `contentId`를 쓴다.

```
GET KorService2/detailCommon2?contentId={공산성 contentId}      → 국문 제목
GET EngService2/detailCommon2?contentId={같은 값}               → 영문 제목이 오는가?
```

| 결과 | 대응 |
|---|---|
| 같은 관광지의 영문 정보가 온다 | 계획대로. `05_ingest.md` §5.1 그대로 |
| 빈 응답 또는 다른 관광지 | **다국어 경로를 `searchKeyword2`(관광지명 검색)로 바꾼다.** 6곳 × 3언어 = 18콜은 그대로다 |

### P0-11 — 무장애 대상 목록으로 6곳을 한 번에 찾을 수 있는가

`detailWithTour2`는 `contentId`를 먼저 알아야 한다. 반면 목록 오퍼레이션은 등록 여부와 `contentId`를 **한 번에** 준다.

```
GET KorWithService2/areaBasedSyncList2?showflag=1&numOfRows=100&pageNo=1..N
  → 매뉴얼 자체 샘플의 totalCount 는 8,852. 89페이지면 전수
  → title 에 우리 6곳 이름이 있는지 확인
```
`lDongRegnCd=44`·`lDongSignguCd=150|760` 필터가 이 오퍼레이션에서 동작하면 페이지 수가 크게 줄어든다. **그것부터 시도한다.**

| **R-5** | 기능 과밀로 4주 안에 못 끝낸다 | 미완성 = **심사 대상 제외 위험** | 컷 게이트를 미리 정하고 금요일에 자동 적용. 다시 묻지 않는다 |
| **R-6** | 자동 접근성 검사를 과신한다 | 접근성 실점 | axe가 33항목의 30~50%만 잡는다고 문서에 명시 + NVDA 수동 3과업 ([`08`](./08_accessibility_legal.md) §1.5) |
| **R-7** | 접근성을 "인증"으로 과장 표기 | **허위 기재 조항에 걸린다** | "자체 점검"으로 고정. 정직성 문구 9개 ([`08`](./08_accessibility_legal.md) §5) |
| **R-8 ★** | **AI 코딩 에이전트로만 만들어 접근성 판단의 실제 맥락을 아무도 검증하지 않았다** | 숫자는 맞고 실제 이동 난이도와 어긋날 수 있다 | **완전한 대응이 없다.** 완화 수단 셋 — ① 판정 근거를 전부 공개해 사용자가 검산할 수 있게 한다 ② 경사도를 숫자로 쓰지 못하게 막는다 ③ 화면에 "전문가 검수 미실시"를 표시한다. **발표에서 이 위험을 먼저 인정한다** ([`12_judging_and_demo.md`](./12_judging_and_demo.md) §6) |

> **R-8이 이 프로젝트의 유일한 근본 위험이다.** 다른 일곱은 확인·대체·컷으로 처리되지만 이건 사람이 현장에 가야 사라진다. 발전 방향 3단계의 현장 실측·전문가 검수가 그 대응이고, 그때까지는 **감추지 않는 것이 유일한 정직한 처리**다.

## 4. 명시적으로 포기한 것 (다시 꺼내지 않는다)

기존 스펙에 미결 항목으로 올라 있었지만, 이번 조건에서는 **되살릴 방법이 없다.** 발표에서는 "발전 방향"으로 말한다.

| 항목 | 왜 포기하는가 |
|---|---|
| 현장 실측 (경사도·단차·회전반경) | 공주·부여 답사 일정 없음 |
| 2차 승인자가 서명한 증거 팩 | 검증자가 1명. 2차 승인자가 존재할 수 없다 |
| 관광약자 접근성 전문가의 산식 검수 서명 | 섭외 없음. **화면에 "전문가 검수 미실시"로 표시한다** |
| 정식 점자 지원 (점역 + 점자 전문가 검수 + 엠보서 출력 검증) | 셋이 한 묶음이고 하나도 확보되지 않았다. **텍스트 파일로 대체하지도 않는다** — 점자 지원은 접근성 있는 HTML 자체다 ([`01_scope.md`](./01_scope.md) §4.4 (2)) |
| 제보 사진 | 즉시 공개 모델에서 초상권·개인정보 위험이 이득보다 크다 ([`01_scope.md`](./01_scope.md) §4.4 (4)) |
| 제보 사전 검수 큐 | 댓글 모델로 바꿨다. 관리자는 사후 숨김만 한다 |
| 수어 영상 | 국립국어원 클립별 라이선스 확인 + 다누림 협약 + 수어 전문가 + 촬영. 외부 기관 3곳 |
| 충남문화관광재단 업무협약(LOI) | 7월 말 기한이 이미 지났다. 리포트는 **CSV 내려받기**까지만 만들고, "지자체 인계를 염두에 두고 설계"라고 표현한다 |
| 충남교육청 체험학습 서식 정합 PDF | 서식 원본 미확보. 인쇄용 HTML로 대체 |
| 마스코트 6컷 | 외주 제작 |
| 실제 이용자 3회차 사용성 검증 | 모집·보상·장소 섭외 |
| KWCAG 정식 인증 (WA/KWACC) | 약 110~120만원 + VAT · 5~10영업일 + 보완 라운드. 게다가 **사용자 심사 과업 성공률 100%** 를 요구하므로 실사용자 검증이 0건인 상태로는 떨어진다 ([`13_legal_citations.md`](./13_legal_citations.md) §2.5). **자체 점검으로 표기한다** |
