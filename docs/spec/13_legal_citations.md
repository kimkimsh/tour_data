# 13 — 법령·기준 근거 모음 (인용 원장)

> **왜 이 문서가 있는가.** 08번은 "무엇을 구현하는가"를 다루고, 이 문서는 **"그 근거가 어느 조문·어느 기준의 몇 번인가"** 를 다룬다. 발표에서 조문 번호를 말하려면 여기서 확인하고 말한다.
>
> **이 문서의 규칙 하나:** 조문 번호와 기준 번호는 **원문으로 확인한 것만 번호로 쓴다.** 확인하지 못한 것은 `[미확인]`을 붙이고, 그 상태에서는 **번호 없이 내용으로만** 말한다. 근거를 강점으로 내세우는 프로젝트에서 틀린 조문 번호는 강점을 약점으로 바꾼다.
>
> 내용은 2026-06 1차 조사에서 옮겨 왔다. 그 조사 원본은 리포지토리에 남아 있고, **원본으로 확인해야 할 것은 §8의 확인처 목록이 정한다.** 여기서 옛 기획 문서를 출처로 대지 않는다 — 그 문서들은 삭제됐고, 삭제된 파일을 근거로 적으면 확인할 수 없는 근거가 된다.

## 1. 위치정보법 — 「위치정보의 보호 및 이용 등에 관한 법률」

**이 서비스의 입장:** 개인위치정보를 **수집·이용·제공하지 않는다.** 따라서 위치정보사업자도 위치기반서비스사업자도 아니고, 아래 의무가 **면제되는 것이 아니라 해당하지 않는다.**

이 구분이 중요하다. **"면제"라고 말하면 우리가 사업자임을 인정하는 셈**이 되고, 면제 조항(1인 창조기업·소상공인 대상 간소화)은 우리 논지와 무관하다.

| 의무 | 우리 상태 | 조문 |
|---|---|---|
| 위치기반서비스사업 신고 (방송통신위원회) | **해당 없음** | 신고 의무 조문 **[미확인]** — 법제처 원문 확인 후 인용 |
| 개인위치정보 수집 전 목적·보유기간·거부권 고지 | 해당 없음 | **[미확인]** |
| 위치 동의를 개인정보 동의와 **분리** 수집 | 해당 없음 | **[미확인]** |
| 제3자 제공 시 사전 동의 | 해당 없음 | **[미확인]** |
| 위치정보 이용·제공 기록 보관 | 해당 없음 | **[미확인]** |
| 목적 달성 후 복구 불가 방식 삭제 | 해당 없음 | **[미확인]** |
| 위치정보 보호책임자 지정·공시 | 해당 없음 | — |

**설계로 증명하는 방법 (이게 근거의 본체다):**
- `navigator.geolocation`을 호출하는 코드가 앱 전체에 없다
- 제보에 좌표 컬럼이 없다 ([`04_data_model.md`](./04_data_model.md) §5.2)
- 도슨트는 관광지를 선택해 재생한다 ([`07_screens.md`](./07_screens.md) S6 규칙 3)
- **E2E 테스트가 `navigator.geolocation` 호출 0건을 검증한다** ([`09_test_and_ci.md`](./09_test_and_ci.md) §5.1 15번)

**발표에서 말하는 방식 (조문 확인 전):**
> "개인위치정보를 일절 수집하지 않는 설계이므로 위치정보법상 신고 대상이 아닙니다. 그 사실을 자동 시험으로 검증합니다."

**GPS를 나중에 켜면 위 전부가 되살아난다.** 그때는 조문 번호를 확인해 처리방침·동의 화면·기록 보관을 모두 만들어야 한다.

## 2. KWCAG 2.2 — 한국형 웹 콘텐츠 접근성 지침 2.2

**기준 문서:** KS X OT0003 (2022-12-28 개정) — **4원칙 · 14지침 · 33개 검사항목**

### 2.1 번호 체계 — 확인이 필요한 지점 **[미확인] ★**

두 가지 번호가 돌아다니고 **서로 다르다.**

| 번호 체계 | 예 | 성격 |
|---|---|---|
| **WCAG 2.x 성공기준 번호** | `1.4.1` 색에 무관한 인식 · `2.4.1` 반복영역 건너뛰기 | 국제 표준(W3C)의 번호. [`08_accessibility_legal.md`](./08_accessibility_legal.md) §1.1이 쓰는 것 |
| **KWCAG 2.2 검사항목 번호** | 표준 문서의 절 번호를 따라 **5.x(인식) / 6.x(운용) / 7.x(이해) / 8.x(견고)** 체계로 알려져 있다 | 국내 기준의 번호 |

**아래 §2.2 표의 번호 열은 이전 기획 문서에서 옮겨 온 것이고 원문 대조를 하지 못했다.** 이름은 신뢰할 수 있고 번호는 신뢰하지 않는다.

**확인처:** KS X OT0003 원문(e나라표준인증) 또는 한국지능정보사회진흥원(NIA) 「한국형 웹 콘텐츠 접근성 지침 2.2」 해설서
**확인 전 규칙:** 화면·문서·발표에서 **"KWCAG 검사항목 N.N.N"이라고 번호를 말하지 않는다.** 지침 이름으로 말한다 — "색에 무관한 인식", "반복 영역 건너뛰기".

### 2.4 색상 토큰과 실측 대비율

`scripts/check-contrast.ts`가 검사하는 대상이다. **기준을 토큰 종류별로 다르게 잡는다** — 전부 4.5로 검사하면 큰 글씨 토큰에서 스스로 실패한다.

**아래 비율은 색상값에서 상대휘도 공식으로 직접 계산한 값이다.** 이전 기획 문서에 적혀 있던 값은 10행 중 8행이 실제와 달랐으므로 전부 다시 계산했다.

| 토큰 | 라이트 (전경/배경/비율) | 다크 (전경/배경/비율) | 기준 |
|---|---|---|---|
| `textPrimary` | `#1A1A1A` / `#FFFFFF` / **17.40** | `#F5F5F5` / `#121212` / **17.18** | 4.5 |
| `textSecondary` | `#595959` / `#FFFFFF` / **7.00** | `#ABABAB` / `#121212` / **8.16** | 4.5 |
| `textLarge` | `#767676` / `#FFFFFF` / **4.54** | `#8A8A8A` / `#121212` / **5.43** | **3.0** |

**배지 색은 [`06_suitability.md`](./06_suitability.md) §6.6이 단일 권위다.** 그 값으로 계산한 결과 (전경은 전부 흰 글자):

| 라벨 | 배경 | 비율 | 기준 |
|---|---|---|---|
| `방문가능` | `#1B7A2E` | **5.43** | 4.5 |
| `주의` | `#8A6100` | **5.54** | 4.5 |
| `대체추천` | `#C0392B` | **5.44** | 4.5 |
| `정보없음` | `#5A5A5A` | **6.90** | 4.5 |

> **전 토큰이 기준을 넘는다.** 최저가 `textLarge` 라이트 4.54이고 그것도 큰 글씨 기준 3.0을 크게 넘는다.
>
> **★ 그래도 이 숫자를 스크립트의 골든값으로 박지 않는다.** 문서에 적은 비율과 실제 계산이 어긋나는 것이 바로 이번에 발견한 문제다. `scripts/check-contrast.ts`는 **색상값에서 매번 계산하고 기준과만 비교한다.** 이 표는 사람이 눈으로 확인하는 참고값이다.
>
> 이전 문서에서 자주 나온 오류 하나: `#1A1A1A`/`#FFFFFF`를 **21.0**으로 적은 것. 21.0은 **순검정(`#000000`)과 순백의 최대값**이고 `#1A1A1A`는 17.40이다.

### 2.5 정식 인증 — 발전 방향

| 기관 | 심사 기간 | 비용 (소규모) |
|---|---|---|
| 한국정보접근성인증평가원 (WA) · `wa.or.kr` | 5영업일 + 2차 4일 | 약 110~120만원 + VAT |

**합격 기준 (이게 "자체 점검"과의 실질 차이다):**
- 전문가 심사 — **33개 검사항목 전체 준수율 95% 이상**
- 사용자 심사 — **모든 장애 유형 과업 성공률 100%**
- 2차 심사 기회 — 전문가 심사 85~95% 구간 또는 사용자 심사 85% 이상일 때 (KWACC)

**신청 서류:** 사업자등록증(또는 단체 등록증) · 자가진단 결과서 · 서비스 URL + 테스트 계정

> **이번 범위에서 신청하지 않는다.** 사용자 심사 과업 성공률 100%를 요구하므로, 실사용자 검증이 0건인 상태로 신청하면 떨어진다. **발전 방향 2단계**에 둔다 ([`12_judging_and_demo.md`](./12_judging_and_demo.md) §5).

### 4.1 유형 — 5개다

|---|:--:|:--:|:--:|

| 제2유형 | 필수 | **금지** | 허용 |
| 제3유형 | 필수 | 허용 | **금지** |
| 제4유형 | 필수 | **금지** | **금지** |

> 08번은 1~4유형만 적었다. **AI유형이 별도로 존재한다** — 이 서비스는 쓰지 않지만, 발전 방향에서 AI를 넣을 때 자산 조달 기준이 된다.
>
> **[미확인] ★** AI유형의 정확한 조건을 원문 대조하지 않았다. 특히 **"출처표시 불필요"는 의심스럽다** — 출처표시는 공공누리 1~4유형 전부의 공통 조건이고, 이 표의 다른 네 행과 어긋난다. §4.3의 최고 제약 원칙도 1~4유형만 안다. **`kogl.or.kr/info/license.do` 원문으로 확인하기 전까지 AI유형을 근거로 아무것도 결정하지 않는다.**

**공모전 출품 자체는 상업적 이용이 아니다.** 수상 후 실제 운영 시 2·4유형 자산의 상업성을 재검토한다.

### 4.2 자산별 유형

| 자산 | 유형 | 가공 | 비고 |
|---|---|---|---|
| KTO TourAPI 텍스트 | 제1유형 | 허용 | 출처 표시 |
| KTO 이미지 `cpyrhtDivCd=Type1` | 제1유형 | 허용 | 리사이즈·썸네일 가능 |
| **KTO 이미지 `cpyrhtDivCd=Type3`** | **제3유형** | **금지** | 자르기·필터·합성·최적화 전부 금지. 전용 프록시 라우트 |
| **관광사진 갤러리** | **[미확인]** | 보수적으로 **금지 취급** | **매뉴얼에 공공누리·저작권 서술이 없다** ([`03`](./03_external_data.md) §2.7). 출처(촬영자 포함)를 표기하고 변형하지 않는다 |
| **Odii 오디오·대본** | **[미확인]** | — | 같은 이유. 출처 표기하고 원문 그대로 |
| 국가유산청 해설 | 1·4유형 혼재 | **4유형 항목은 원문 인용만** | 재편집 금지 |
| Pretendard 폰트 | SIL OFL 1.1 | 허용(임베드 포함) | 폰트 자체 판매 금지 |

> **`cpyrhtDivCd`의 허용값은 `Type1`·`Type3` 둘뿐이다.** `Type2`·`Type4`는 이 필드에 오지 않는다.

### 4.3 최고 제약 원칙 — 결합 시

여러 자산을 한 출력물에 합치면 **가장 제약이 강한 유형**이 전체에 적용된다. **자산 단위로 적용하고 서비스 단위로 적용하지 않는다.**

```
1유형 + 1유형          → 1유형 (양쪽 출처 표시)
1유형 + 4유형          → 4유형 (비상업 + 변경금지)
1유형 + 2유형          → 2유형 (비상업)
3유형 이미지           → 단독 표시. 합성·필터·크롭 금지
```

**전략:** 가공이 필요한 자산은 1유형·OFL·CC-BY에서만 조달한다. 4유형 자산은 원문 그대로 인용하거나 링크로 연결한다.

**이 원칙이 푸터 문구를 정한다** — 페이지마다 유형이 다를 수 있으므로 **푸터에 유형을 하나로 고정하지 않고 자산 옆에 붙인다** ([`08`](./08_accessibility_legal.md) §3.3).

## 6. 인공지능 관련 법

**「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」** (약칭 「인공지능 기본법」) — **2026-01-22 시행**

- 이 서비스에는 생성형 AI 산출물이 **없다.** 다국어는 공사 공식 번역, 적합도는 결정적 수식, 코스는 사전 작성 템플릿이다 ([`08`](./08_accessibility_legal.md) §4.1)
- 예외 하나 — 브라우저 음성 합성을 쓸 때 **"기기 음성 합성"** 을 화면 텍스트로 표시
- **고영향 인공지능**(의료·금융·공공·교통·에너지·채용 등)에 해당하지 않으므로 영향평가 의무가 없다
- 유예되는 것은 **과태료와 사실조사**이고 **표시 의무 자체는 시행일부터 적용**된다

**조문 번호 [미확인]** — 사전 고지·출력물 표시 조항의 번호는 확인 후 인용한다.

> **약칭만 쓰지 않는다.** 발표에서 처음 말할 때 정식 명칭을 한 번 붙인다. 심사위원이 법명을 확인하는 자리에서 약칭만 쓰면 근거가 얇게 들린다.
