## 이 기록의 규칙

이 프로젝트가 스스로에게 요구하는 것과 같다.

1. **못 한 것은 못 했다고 쓴다.** 돌리지 않은 검사를 통과했다고 쓰지 않는다.
2. **실측한 것과 추론한 것을 구분한다.** 02번의 각 항목에는 어떻게 확인했는지가 붙어 있다.
3. **스펙을 조용히 고치지 않았다.** 실측으로 틀린 것이 확인된 곳은 02번에 목록으로 남겼고, 스펙 파일 자체는 사람이 소유하는 문서다.

   **예외 두 곳은 명시한다.** 검토 라운드(06번)에서 코드가 스펙보다 정확해진 두 지점은 스펙에 직접 반영했다 — 그 상태로 두면 스펙이 코드가 하지 않는 것을 지시하는 문서가 되기 때문이다.
   - `docs/spec/05_ingest.md` §4.2 — `resolveStatus()`의 규칙 전체. 방향이 두 번 뒤집힌 곳이고, 이전 규칙을 그대로 두면 다음 사람이 그것을 되살린다
   - `docs/spec/04_data_model.md` §5.4 — 컬럼 단위 권한. 스펙에 없던 보안 통제를 마이그레이션이 강제하게 되었으므로 절을 새로 넣었다

## 지금 상태 한 줄

**조건별 판정이 화면에 있고, 적합도 점수는 계산 패널로 내려갔다.** 12번에서 **동행을 한 명 더 고르면 앞서 알고 있던 판정이 전부 사라진다**는 것을 재어서 확인했다 — 청각장애의 기준 항목 2개 중 하나는 13곳 어디에도 값이 없고, 규칙 2가 조건마다 묻기 때문이다. 전체 판정은 그대로 두고 **조건별 판정을 카드와 상세 양쪽에** 붙였다. 같은 회차에 **적합도 점수를 기본 화면에서 뺐다** — 확인된 항목만 평균 낸 값이라 장소마다 계산에 들어간 항목이 다르고, `공주 고마나루`가 확인 6/31에 100점이었다.

조용히 틀려 있던 것 중 무거운 넷: **수집기가 `resultCode 30`(키 오류)으로도 빈 스냅샷을 발행**했고, **`/api/export/text`가 Postgres 오류와 환경변수 이름을 낯선 사람에게** 돌려줬고, **관리자 세션이 토큰 갱신 한 번에 끊겼고**, **인쇄물의 출처 줄이 본문 마지막 줄과 1.25pt 겹쳤다**(그리고 그 구조를 택한 이유 — 「Chrome은 `@page` 마진 박스가 없다」 — 가 이미 사실이 아니었다).

`pnpm typecheck`·`lint`·`validate:content`·`test`(187)·`build`·`e2e`(42)가 전부 통과한다. 18개 경로를 데스크톱·휴대폰·다크 세 조합으로 열어 가로 넘침 0, 깨진 이미지 0, 예상 밖 콘솔 오류 0.

## 11번까지의 상태 한 줄

**관광지 13곳, 점수 모델 v6, 네이버 지도, 화면 재설계.** 11번에서 「방문 가능」 라벨이 이 데이터에서는 **산술적으로 나올 수 없다**는 것을 재어서 확인하고(모델 상한 62점, 기준선 75점) 모델을 고쳤다. 같은 회차에 **도슨트 오디오가 배포 이래 한 번도 재생된 적이 없다**는 것도 찾았다 — CSP `media-src`가 사진 호스트만 적고 있었고, 막힌 `<audio>`는 코드가 볼 수 있는 error를 쏘지 않는다.

아래는 10번까지의 상태다.

**데이터가 붙었고, 화면을 직접 열어 보고 고쳤고, 배포된 것을 다시 의심했다.** 공공데이터포털 API 11종과 Supabase가 연결돼 `pnpm ingest`가 6개 스냅샷을 올린다. 09번에서 전 화면을 브라우저로 돌았고, 10번에서 배포 상태를 다시 감사해 **첫 화면 404**·**동작하지 않던 캐시 무효화**·**다른 관광지가 섞인 오디오 해설**을 포함해 조용히 틀려 있던 것들을 고쳤다.

가장 무거웠던 것은 **`resolveStatus()`가 확인된 부재를 「확인됨」으로 발행**하고 있었던 것이다 — 「장애인용 화장실이 설치되어 있지 않습니다」가 `supported`였다. 09번 §1.

`pnpm typecheck`·`lint`·`test`(160건)·`validate:content`·`build`·`e2e`(24건, axe 20경로)가 전부 통과한다.
