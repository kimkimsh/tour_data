## 이 기록의 규칙

이 프로젝트가 스스로에게 요구하는 것과 같다.

1. **못 한 것은 못 했다고 쓴다.** 돌리지 않은 검사를 통과했다고 쓰지 않는다.
2. **실측한 것과 추론한 것을 구분한다.** 02번의 각 항목에는 어떻게 확인했는지가 붙어 있다.
3. **스펙을 조용히 고치지 않았다.** 실측으로 틀린 것이 확인된 곳은 02번에 목록으로 남겼고, 스펙 파일 자체는 사람이 소유하는 문서다.

   **예외 두 곳은 명시한다.** 검토 라운드(06번)에서 코드가 스펙보다 정확해진 두 지점은 스펙에 직접 반영했다 — 그 상태로 두면 스펙이 코드가 하지 않는 것을 지시하는 문서가 되기 때문이다.
   - `docs/spec/05_ingest.md` §4.2 — `resolveStatus()`의 규칙 전체. 방향이 두 번 뒤집힌 곳이고, 이전 규칙을 그대로 두면 다음 사람이 그것을 되살린다
   - `docs/spec/04_data_model.md` §5.4 — 컬럼 단위 권한. 스펙에 없던 보안 통제를 마이그레이션이 강제하게 되었으므로 절을 새로 넣었다

## 지금 상태 한 줄

**수집이 GitHub 러너에서 Vercel 함수(서울)로 옮겨졌고, 운영에서 돌고 있습니다.**

야간 수집이 이틀째 실패했는데 로그가 `fetch failed — fetch failed`만 말했습니다. undici는 TypeError의 message를 상수 문자열로 두고 진짜 이유를 `.cause`에 넣습니다 — 체인을 찍게 하자 **`UND_ERR_CONNECT_TIMEOUT`, apis.data.go.kr:443**이 나왔습니다. DNS는 풀렸고 소켓에 한 바이트도 안 쓰였습니다.

8번 실행을 세어 보니 **실패한 런 안의 성공 콜이 0건**(12번 시도 / 80초)이고, 성공한 런은 전부 성공했습니다. 런 내내 고정이면서 런마다 바뀌는 변수는 러너의 출발지 주소 하나입니다. **재시도로는 못 넘습니다** — 그래서 앞서 올린 재시도 예산의 근거도 같이 정정했습니다.

200줄을 쓰기 전에 **10줄 프로브**로 icn1을 물었습니다. 13/13 성공, 27~54ms. 그다음 옮겼습니다.

옮기다 드러난 것: **파이프라인이 한 프로세스 안에서 디스크를 거쳐 자기와 대화하고 있었습니다**(`publish()` → 파일 → `readGenerated()`). 이제 메모리로 넘깁니다. 그리고 `require.main === module` 가드는 Turbopack ESM에 `module`이 없어 터졌는데, **두 단어로 고치지 않고 CLI를 파일로 분리했습니다** — 그 가드가 잘못 걸리면 `next build` 중에 실제 수집이 돕니다.

수집은 Vercel cron(04:00~04:59 KST), 스냅샷 git 커밋은 GitHub Actions(04:30 KST, Supabase만 읽음)로 나뉩니다. **Pro는 필요 없습니다** — Hobby에서 cron 100개·하루 1회·함수 300초이고 우리 실행은 27~33초입니다.

`typecheck`·`lint`·`validate:content`·`test`(**271**)·`build`·`e2e`가 전부 통과합니다. 프로덕션 빌드에서 수집 실행 0건·파일 변경 0건을 확인했습니다.

**환경변수는 하나가 아니라 셋이었습니다.** `CRON_SECRET`을 넣자 라우트가 열렸고, 그다음 게이트웨이 단계에서 `KTO_SERVICE_KEY_DECODING`이 없다고 멈췄습니다 — 수집을 옮긴다는 말은 수집이 읽던 비밀을 GitHub 시크릿에서 Vercel로 옮긴다는 뜻인데 19번 §8에는 하나만 적혀 있었습니다. 변수 하나당 배포 한 번이 들어서, **아무것도 부르기 전에 빠진 것을 전부 한 줄로 말하게** 고쳤습니다. Vercel 환경변수는 넷이 아니라 **일곱**입니다.

**운영에서 실제로 돌았습니다** — `{"ok":true,"seconds":27}`, 스냅샷 6개, `context.fetchedAt 2026-09-19T16:45:05.853Z`, 격차 보고서 「2026-09-20까지 확인」. `snapshot` 워크플로는 여섯 개를 읽고 차이가 없어 커밋 없이 끝났습니다 — **커밋 단계는 내용이 달라지는 첫 야간 실행에서 확인됩니다.**

`docs/guide/`의 운영 문서도 같이 고쳤습니다. 지워진 `ingest.yml`을 이름으로 부르고 있었고, 「Vercel에 서비스 롤 키는 필요 없다」고 적혀 있었습니다.

**NVDA로 직접 들었고, 판정이 바로 뒤 낱말과 붙어서 읽히고 있었다.**

05번이 처음 적고 09·10·11·12·15·17이 이월한 「NVDA 수동 검증」을 실제로 돌렸다. NVDA 2026.2 + Chrome, 스펙 `08_accessibility_legal.md` §1.4의 과업 A·B·C.

**이 서비스가 내놓는 단 하나의 답이 한 낱말로 뭉쳐 있었다.** 화면에는 「방문 가능」과 「휠체어 이용 기준」이 떨어져 있고 스크린리더에는 「방문 가능휠체어 이용 기준」으로 들어갔다 — 한 덩어리로 들으면 판정이 조건의 수식어가 되어 사라진다. 마스트헤드(모든 화면)·긴급 연락처(「외교부 영사안전콜센터 (국내)02-3210-0404」)·목록 카드 13곳의 판정 넷씩·상세 통계·근거 표·도슨트 재생 시간·안전시설 거리까지 **18종 58건**.

뿌리는 하나다. 이 자리들은 플렉스 `gap`과 마진으로만 떨어져 있고 **그 간격은 그려지는 것이지 문서에 적히는 것이 아니다.** 공백을 넣으면 되는 문제도 아니었다 — `DocentView.tsx`에는 이미 `{' '}`가 있었고 HTML에도 찍혀 있었는데, **Chrome이 공백만으로 된 텍스트 노드를 접근성 트리에 넣지 않는다.** 구분자 후보 다섯을 NVDA로 재어 일반 공백은 세 형태 전부 사라지는 것을 확인하고, `.sr-only` 안의 쉼표로 12자리를 고쳤다(`position:absolute`라 레이아웃은 움직이지 않는다).

**axe도 브라우저 순회도 이걸 볼 수 없다.** 접근 가능한 이름은 비어 있지 않고, 간격은 정확히 그려져 있다. 소리로 들어야만 나온다.
