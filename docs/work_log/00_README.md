> **이 폴더가 무엇인가**

>
> **권위 없음.** 구현 사양은 `docs/spec/`이 이긴다. 이 폴더는 "그 사양을 어떻게 이행했고 어디서 어긋났는가"의 기록이다.

## 이 기록의 규칙

이 프로젝트가 스스로에게 요구하는 것과 같다.

1. **못 한 것은 못 했다고 쓴다.** 돌리지 않은 검사를 통과했다고 쓰지 않는다.
2. **실측한 것과 추론한 것을 구분한다.** 02번의 각 항목에는 어떻게 확인했는지가 붙어 있다.
3. **스펙을 조용히 고치지 않았다.** 실측으로 틀린 것이 확인된 곳은 02번에 목록으로 남겼고, 스펙 파일 자체는 사람이 소유하는 문서다.

   **예외 두 곳은 명시한다.** 검토 라운드(06번)에서 코드가 스펙보다 정확해진 두 지점은 스펙에 직접 반영했다 — 그 상태로 두면 스펙이 코드가 하지 않는 것을 지시하는 문서가 되기 때문이다.
   - `docs/spec/05_ingest.md` §4.2 — `resolveStatus()`의 규칙 전체. 방향이 두 번 뒤집힌 곳이고, 이전 규칙을 그대로 두면 다음 사람이 그것을 되살린다
   - `docs/spec/04_data_model.md` §5.4 — 컬럼 단위 권한. 스펙에 없던 보안 통제를 마이그레이션이 강제하게 되었으므로 절을 새로 넣었다

## 지금 상태 한 줄

**화면 10개·도메인 함수·수집 파이프라인·마이그레이션·테스트가 모두 있다. `pnpm typecheck`·`lint`·`test`(119건)·`build:fixtures`·`e2e`(24건, axe 17경로 포함)가 통과하고, 마이그레이션은 실제 Postgres 17.11에 대고 두 라운드 검증했다.**

**한국관광공사 API 키와 Supabase 프로젝트가 없어서 `pnpm probe`·`pnpm ingest`는 한 번도 실행되지 않았고, 그래서 화면에 보이는 무장애 항목은 전부 `정보 없음`이다.** `pnpm validate:content`는 지금 **의도적으로 빨간불**이고 그래서 CI도 빨간불이다 — 확인되지 않은 `contentId`로 배포하면 조용히 다른 관광지의 데이터를 수집한다.

자세히는 [`04_open_items.md`](./04_open_items.md), 검토에서 잡힌 것은 [`06_review_round.md`](./06_review_round.md).

**막힌 것을 실제로 푸는 절차는 [`../guide/`](../guide/)에 있다** — 키를 어디서 받아 어디에 넣는지, 그리고 사람이 정해야 하는 5가지가 각각 숫자로 얼마나 달라지는지.
