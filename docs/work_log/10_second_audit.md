# 10 — 두 번째 전수 감사

> 09번이 브라우저로 전 화면을 열어 본 회차였다면, 이 회차는 **배포된 것을 다시 의심한 회차**다.
> 스펙 16개 문서와 작업 기록 10개 문서를 다시 읽고, 화면을 다시 열고, `src/` 전부를 다시 읽었다.
>
> 나온 것 중 다섯 건은 **배포된 상태에서 사용자에게 잘못된 것을 보여주고 있었다.** 그중 하나는
> 서비스의 첫 화면이 404였고, 하나는 「이 야간 수집이 반영됐다」는 응답이 사실이 아니었다.

## 1. 프록시 파일이 한 번도 로드된 적 없다 — 첫 화면이 404

`proxy.ts`가 저장소 루트에 있었다. 이 프로젝트는 `src/app`을 쓰므로 Next 16은 **`src/proxy.ts`**에서만
그 파일을 찾는다. 문서 원문(`node_modules/next/dist/docs/01-app/01-getting-started/16-proxy.md`):

> Create a `proxy.ts` (or `.js`) file in the project root, **or inside `src` if applicable, so that it is
> located at the same level as `pages` or `app`.**

**실패는 조용하다.** Next은 프록시가 없다고 말하지 않고, 프록시가 0개인 상태로 빌드한다. 증거는
빌드 산출물에 그대로 있었다:

```json
// .next/server/middleware-manifest.json
{ "version": 3, "middleware": {}, "sortedMiddleware": [], "functions": {} }
```

`localePrefix: 'always'`에서 `/` → `/ko`를 보내는 것은 **프록시뿐**이다. 맨 루트를 맡는 라우트 파일은
없다. 그래서:

```
https://modu-baekje.vercel.app/     →  404      (배포된 상태에서 실측)
https://modu-baekje.vercel.app/ko   →  200
```

**공모전 심사위원이 주소만 받아서 열면 404를 본다.** Accept-Language 협상도 같이 죽어 있었다.

`git mv proxy.ts src/proxy.ts` 한 줄. 그 뒤 실측:

```
/          307 → /ko
/places    307 → /ko/places
/          307 → /en      (Accept-Language: en-US)
```

## 2. `/api/revalidate`가 `{"ok":true}`를 돌려주면서 아무것도 무효화하지 않았다

야간 수집이 끝나면 ingest가 이 엔드포인트를 부른다. 200과 `ok:true`가 돌아왔고, 화면은 계속
**이전 스냅샷**을 서빙했다.

`revalidatePath('/ko', 'layout')`은 `_N_T_/ko/layout`이라는 태그를 만든다
(`node_modules/next/dist/server/web/spec-extension/revalidate.js:86-105`). 실제 페이지에 붙은 태그는
빌드 산출물에 적혀 있다:

```
// .next/server/app/ko/places.meta → x-next-cache-tags
_N_T_/layout,_N_T_/(site)/layout,_N_T_/(site)/[locale]/layout,
_N_T_/(site)/[locale]/places/layout,_N_T_/(site)/[locale]/places/page,_N_T_/ko/places
```

`_N_T_/ko/layout`은 **어느 라우트에도 없다.** layout 태그는 요청 URL이 아니라 **라우트 파일 경로**에서
파생되기 때문이다(`server/lib/implicit-tags.js:14-41`) — 파일 경로에는 `[locale]`이 들어 있지 `ko`가
들어 있지 않다. URL이 기여하는 태그는 정확히 일치하는 `_N_T_/ko/places` 하나뿐이다.

`revalidatePath('/admin/reports')`는 **정확 경로 태그와 일치해서 잘 동작한다.** 이것이 이 결함이
눈에 띄지 않은 이유다 — 관리자 화면만 제대로 갱신되고 있었다.

### 실측으로 확인하고 실측으로 고쳤다

픽스처 프로덕션 빌드를 띄우고, 픽스처 파일의 제목을 바꾸고, 엔드포인트를 부르고, 다시 읽었다.

```
고치기 전:  before 0 → {"ok":true} → after 0     (그대로 옛 렌더)
고친 뒤:    before 0 → {"ok":true} → /ko/places 1 · 상세 2 · /ko/courses 1 · /ko/gap-report 1
```

`revalidatePath('/', 'layout')`. 이 하나가 `_N_T_/layout`을 만들고, 그 태그는 `.next/server/app` 아래
**모든** 항목이 달고 있다 — 두 라우트 그룹과 두 언어 전부. 로케일 순회도 같이 사라졌다.

관리자 액션(`actions.ts`)도 같은 잘못된 호출을 하고 있었고 같이 고쳤다.

## 3. 오디오 해설이 **다른 관광지의 이야기**를 붙여 놓고 있었다

수집은 Odii 테마를 좌표로 골랐다 — 반경 1,000m 안이면 그 관광지의 것.

무령왕릉과 왕릉원과 국립공주박물관은 **700m 떨어져 있다.** 그래서 두 곳은 **완전히 같은 50개 이야기**를
갖고 있었다. 공산성의 오디오 해설에는 「공주 산성시장」이, 무령왕릉에는 **부여에 있는**
「백제문화단지」 이야기가 들어 있었다.

라이브 API에서 실제 테마 목록을 받아 거리와 함께 찍어 보면, 반경으로는 갈라지지 않는다는 것이
바로 보인다:

| tid | 테마 이름 | 가장 가까운 관광지 | 거리 | 그 관광지의 것인가 |
|---|---|---|---|---|
| 22 | 공주 공산성 | gongsanseong | 341m | 예 |
| 2838 | 전설따라 설화따라-부여군 | muryeong-royal-tombs | **115m** | **아니오** (백제문화단지 이야기) |
| 2980 | 부여 관북리 유적 | busosanseong | **124m** | **아니오** (우리가 다루는 곳이 아니다) |
| 371 | 공주 산성시장 | gongsanseong | 637m | **아니오** |

**틀린 것이 맞는 것보다 가깝다.** 어떤 반경도 이 둘을 갈라내지 못한다 — 거리는 애초에 묻고 있던
질문이 아니었다.

### 고친 방식 — 근접이 아니라 선언

`content/pois.json`에 `odiiThemeIds`를 뒀다. 경로 안내를 사람이 직접 쓰고 확인 사실을 사람이 직접
검증하는 것과 같은 자리다. 수집은 여전히 카탈로그를 전수 열거하지만, 이제 열거는 **선택이 아니라
점검**에 쓴다:

```
warn  Odii theme 371 (공주 산성시장) is 637m from gongsanseong and is claimed by no place.
      Add it to odiiThemeIds or leave it out on purpose.
```

선언한 tid를 찾지 못해도 경고한다. 둘 다 사람이 읽으라고 있는 것이다.

### 덤으로 드러난 것 — `seq`가 관광지 안에서 유일하지 않았다

`seq`는 **테마마다** 1부터 다시 시작했다. 한 관광지가 테마를 여러 개 가지면 한 화면에 `seq: 1`이
둘 이상 생긴다. 결과가 셋이었다:

1. React 키 충돌 — `Encountered two children with the same key, 'ko-1'`
2. **DOM id 중복 14건** — `story-1`부터 `story-14`까지. `aria-labelledby`는 먼저 나온 것만 가리키므로
   **화면의 절반이 남의 제목을 자기 제목이라고 읽어 줬다**
3. `seq` 정렬이 서로 다른 테마의 이야기를 교차시켰다

수집이 이제 **관광지·언어마다** 이어서 번호를 매긴다. 화면 쪽 키와 id도 테마를 함께 물게 해서,
수집이 아직 안 돈 스냅샷에서도 충돌하지 않는다.

| | 전 | 후 |
|---|---|---|
| 행 수 | 222 | **103** |
| `(관광지, 언어, seq)` 중복 | **59조** | **0** |
| 무령왕릉 ↔ 국립공주박물관 | 같은 50개 | 17개 / 32개, 각자의 것 |

## 4. 자유 문장 판정에서 「엘리베이터 없음」이 다시 「확인됨」이 됐다

`resolveStatus()`가 방향을 뒤집은 것이 이번이 **네 번째**다(스펙 수정 Q → 검토 S1–S3 → 09번 §1 →
여기). 이번에는 장애물 명사 뒤 8자 창이 **다음 명사의 부정**까지 먹어 버리는 형태였다.

실제 모듈을 돌려서 측정한 것:

| 문장 | 필드 | 고치기 전 | 옳은 값 |
|---|---|---|---|
| `계단·엘리베이터 없음` | elevator | **supported** | unsupported |
| `계단, 승강기 없음` | elevator | **supported** | unsupported |
| `단차·경사로 없음` | access_route | **supported** | unsupported |
| `장애물·점자블록 없음` | braille_block | **supported** | unsupported |
| `문턱 및 수유실 없음` | nursing_room | **supported** | unsupported |

`계단`의 창이 `·엘리베이터 없음`까지 닿아 `없`을 계단의 것으로 읽고, 창을 통째로 잘라내면서
**엘리베이터를 문장에서 지웠다.** 남은 글자에는 부정이 없으니 「장애물이 없으면 좋은 소식」 규칙이
발동했다.

**고친 곳**: 나열 구분자(`·`, `,`, `/`, `및`, `또는`, `와/과`)에서 창을 끊는다. 나열의 부정은 구성원
전체에 걸리고, 구성원이 전부 장애물인 것은 아니다. 창이 끊기면 그 장애물은 극성을 못 읽어
`ambiguous`가 되고, 문장 전체가 `NEGATION`에 넘어간다.

### 같은 함수에서 둘 더

**`계단 없음`이 어느 필드에서나 `supported`였다.** 함수가 자기가 어느 필드를 읽고 있는지 몰랐다.
`elevator` 칸에 이 문장이 오면 화면에 **엘리베이터 확인됨**이 찍힌다 — 아무도 확인한 적 없는 승강기다.
이제 `capabilityCode`를 받고, 「장애물 부재 = 좋은 소식」은 주어가 길 자체인 세 항목
(`access_route`, `entrance_passage`, `path_continuity`)에서만 `supported`에 닿는다. 나머지는 `unknown`.

**`해당 없음`이 `unsupported`였다.** 이 문장에는 시설도 장애물도 없는데, 시스템에서 가장 가혹한
판정(`대체추천` + 점수 상한 49)을 끌어냈다. 해당 여부는 `absenceKind: 'not_applicable'`이 맡고
있고 그건 사람이 `curated-facts.json`에서 정하는 것이다. 이제 `unknown`을 돌려준다.

회귀 스위트를 54건 → **57건 + 검사 2개**로 늘리고, **모든 사례에 필드를 붙였다.** 같은 문장이 필드에
따라 다른 뜻이라는 것이 이제 파일에 적혀 있다.

### 실데이터 영향 — 없다. 그리고 그것도 확인한 것이다

라이브 스냅샷 85개 사실을 판정과 나란히 전부 읽었다(04번 §1.2와 08번 §7이 「아무도 안 했다」로
남겨 둔 그것이다). **오판 0건.** KTO가 자유 문장을 채워 넣은 칸이 4개뿐이라서, 위 결함들은 아직
데이터에 닿은 적이 없다. 오늘의 데이터를 고친 게 아니라 **내일의 데이터를 막은 것**이다.

## 5. 잘 맞는 동행자가 다른 동행자의 「모름」을 희석했다

Layer B는 `Math.min(...fits)`을 쓴다 — 가장 안 맞는 사람이 판정을 정한다. 첫 화면도 그렇게 말한다.
**라벨 규칙만 그러지 않았다.** 「필수 중 unknown 과반」을 선택한 페르소나들의 필수 집합 **합집합**
위에서 계산했다.

실제 모듈로 측정:

```
P2b 혼자        → 정보없음  (점수 숨김)   unknownCriticals sign_guide, video_caption
P2b + P1a       → 주의  95점             unknownCriticals sign_guide, video_caption   ← 같은 근거
P2b + 3명       → 주의  95점
```

**청각장애인이 혼자 오면 「판단할 정보가 부족합니다」, 휠체어 이용자와 같이 오면 95점.** 근거는 한
글자도 바뀌지 않았다. 합집합 7개 중 2개는 과반이 아니지만, 그 방문자가 의존하는 것의 **100%**다.

규칙 2를 **페르소나마다 따로** 묻고 가장 나쁜 답을 쓴다. 골든 스위트가 못 잡던 자리라 테스트를
하나 박았다.

## 6. 기상 예보가 36℃인 날을 「무리가 없는 예보」로 발행할 수 있었다

`TMX`(일 최고기온)는 **하루 한 번, 15시에** 나온다. 그 시각이 지난 발표분에는 오늘의 `TMX` 행이
없다 — 타입 주석이 그렇게 적혀 있다. 더위 판정이 `tmx`만 보고 있어서, 그런 발표분에서는 **판정이
아예 돌지 않았다.**

`TMP`(시간별 기온)는 이미 받아서 `READ_CATEGORIES`에 들어 있는데, `switch`에 `case 'TMP'`가 없어서
버려지고 있었다. 36℃ 행들을 받아 놓고 버린 다음 「야외 이동에 무리가 없는 예보입니다」를 찍었다.

이제 `TMX`가 없으면 남은 시간대의 최고 기온을 쓰고, **문장이 어느 쪽인지 말한다** —
`남은 시간대 최고기온 36℃`.

**그리고 「좋음」의 문턱을 올렸다.** 파일 머리말이 「읽을 수 없으면 unknown, 절대 good이 아니다」라고
적어 놓고, 구현은 필드가 **하나라도** 읽히면 good을 줬다. 하늘 상태만 있는 날이
`맑음. 야외 이동에 무리가 없는 예보입니다`가 됐다. 이제 강수와 기온을 **둘 다** 읽어야 good이고,
아니면 무엇이 없었는지 이름을 대며 unknown이다.

## 7. 게이트웨이 장애가 「연락됐다」로 기록됐다

09번 §12가 넣은 보호 장치 — 게이트웨이에 닿지 못한 실행은 아무것도 발행하지 않는다 — 에 구멍이 있었다.

`attemptOnce`는 **HTTP 상태를 보기 전에 본문을 킁킁거린다.** 게이트웨이 자체의 HTML 오류 페이지는
`<`로 시작하므로 XML 장애 봉투로 파싱되고, 결과는 `transport/xml-body`가 된다. `isRetryable`이 이 코드에
대해 false를 주므로 **백오프가 통째로 건너뛰어지고**, 그 실패는 `gatewayReached`로 계상된다.

즉 잠깐의 503이 「게이트웨이가 답했다」로 남고, 수집은 자기가 본 적 없는 부재를 발행할 수 있었다.

상태를 본문 형태와 무관하게 읽는다. 429와 5xx는 어떤 본문이 왔든 재시도 대상이고, 재시도를 다 쓰고도
안 되면 **연결 거부와 똑같이 `gatewayUnreachable`로 센다.** 503을 세 번 받은 것은 데이터에 대해
아무것도 말해 주지 않는다. 분류기에 테스트 8건.

## 8. 없는 주소가 전부 200이었다

프록시 매처가 api/admin이 아닌 모든 경로를 로케일 트리로 보내고, 거기서 `[...rest]` 포괄 세그먼트가
받았다. 포괄 세그먼트는 **진짜 페이지**이므로 진짜 200이다.

```
/nonexistent      → 307 → /ko/nonexistent → 200
/ko/아무거나        → 200
/ko/places/없는곳   → 200
```

그 위에 딸린 결함 하나 더: `generateMetadata`가 일치하는 관광지가 없으면 **slug로 되돌아갔다.**

```
GET /ko/places/Account-Suspended-Call-02-1234-5678
200  <title>Account-Suspended-Call-02-1234-5678 · 모두의 백제</title>
```

XSS는 아니다 — React가 이스케이프한다. **진짜 도메인에서 200으로 색인되는 페이지의 제목을 링크를
보내는 쪽이 정한다**는 것이 문제다.

### 포괄 세그먼트가 서 있던 전제가 틀렸다

네 곳의 주석이 「app/layout.tsx가 없으므로 Next의 not-found 렌더는 lang도 제목도 본문도 없는 문서가
된다」고 적고 있었다. **실제로 열어서 측정했다:**

```js
document.documentElement.lang  // "ko"
document.querySelectorAll('html').length  // 1
document.querySelector('h1').textContent  // "이 주소에는 아무것도 없습니다"
// HTTP 404
```

파서가 중첩 `<html lang="ko">`의 속성을 루트에 **병합한다.** `src/app/not-found.tsx`가 이미 해결하고
있었고, 포괄 세그먼트는 그 위에 얹혀 200을 주고 있었을 뿐이다.

**고친 모양**: `src/app/(site)/[locale]/not-found.tsx`를 두고, 관광지·도슨트·경로 세 화면의 대역
컴포넌트를 `notFound()`로 바꿨다. 그러면 화면은 진짜 레이아웃 안에서 렌더되고 — 언어, 건너뛰기 링크,
내비게이션, 긴급 연락 버튼 전부 — 상태는 404다. `[...rest]`와 대역 컴포넌트 3개는 지웠다.

루트 `not-found.tsx`는 중첩 `<html>` 때문에 **하이드레이션 불일치 오류**를 콘솔에 찍고 있었다.
병합이 의도한 결과이므로 `suppressHydrationWarning`을 달았다.

e2e 9건으로 박았다 — 404 상태 6경로, 200 대조 1, 제목 반사 1, 「없는 관광지 화면에 사이트가 남아
있는가」 1.

## 9. 실패한 조회가 「없습니다」로 읽혔다

`src/lib/data.ts`의 머리말은 이 모듈의 첫 번째 책임이 **「아직 데이터가 없다」와 「조회가 실패했다」를
구별하는 것**이라고 적어 놓았다. 경로 안내와 도슨트 화면은 그 구별을 쓰지 않고 있었다:

- `routeGuide.none` = 「이 관광지에는 경로 안내를 **만들지 않았습니다**」 ← 우리의 선택에 대한 주장
- `docent.none` = 「이 관광지에는 오디오 가이드가 **없습니다**」 ← 그 장소에 대한 주장

스냅샷 조회가 실패해도 둘 다 그대로 나왔다. `kind === 'error'`면 `SnapshotProblem`으로 넘긴다.
`kind === 'missing'`은 그대로 — 그건 진짜 부재다.

## 10. 제보 날짜에 아무 경계가 없었다

`z.iso.date()`는 형식만 본다. `2099-01-01`이 통과하고, 관광지 화면은 `occurred_on`을 그대로 찍는다 —
**「2099-01-01 목격」이 사실로 발행된다.** 모바일 날짜 선택기에서 연도 한 글자 잘못 누르면 된다.

서버가 미래와 1년 초과 과거를 거절하고(요청마다 평가한다 — 부팅 때 굳힌 경계는 매시간 달력에서
멀어진다), 입력에 `max`를 걸었다.

```
POST /api/report  occurredOn=2099-01-01
400  occurredOn must be within the last year and not in the future
```

**그리고 제보 제출이 조용히 실패하고 있었다.** `fetch`는 네트워크가 없으면 resolve가 아니라 reject한다.
`catch`가 없어서 거부가 그대로 빠져나갔다 — 버튼의 회색이 풀리고, 아무 말도 없고, 방문자는 아무것도
하지 않은 폼을 보고 있었다. `catch`를 달아 다른 실패와 같은 문구로 보낸다.

## 11. 화면에서 고친 것

**내부 코드가 공개 화면에 찍혀 있었다.** 조건 선택 체크박스 옆의 `P1A`·`P1B`·`P2A`·`P2B`·`P3`,
항목 표의 `wheelchair`·`elevator`, 축 제목 옆의 `ENTRY`·`FACILITY`. 전부 스펙 문서의 행 번호다.
모든 방문자가 통과해야 하는 화면에 문서의 정리 번호를 찍어 둔 것이라 지웠다.

**한글이 고정폭 서체로 조판돼 있었다.** `.evidence__provenance`, 관광지 목록의 도시·유산 줄, 상세
화면의 지정명칭 줄, 도슨트 배지, 언어 전환. 고정폭 스택에는 한글 글리프가 없어서 시스템 서체로
떨어지는데, 자간은 라틴 기준으로 남는다 — 단어마다 틈이 벌어져 **깨진 글자처럼 보인다.** 본문 서체로
바꾸고, 고정폭은 **기계 토큰에만** 조각 단위로 남겼다 — 필드명, 파일 경로, 날짜.

**출처 줄에 90자짜리 URL이 링크도 아닌 채로 스물두 번 찍혀 있었다.** 한 줄이 다섯 줄로 감겼고,
상세 화면에서 가장 긴 요소였다. 이제 URL은 `href`로 가고 옆에 적힌 설명이 링크 문구가 된다.
상세 화면 높이 11,535px → 10,978px.

**그 밖의 문구**

| 자리 | 전 | 후 |
|---|---|---|
| 계산 표의 A 행 | `A 시설 목록` — **여섯 축의 가중합인데 「시설」이라 부르고 있었다.** 같은 표에 「편의시설」 축이 따로 있다 | `A 항목 점수` |
| 상세 화면 요약행 | `정보 없음 │ 정보 없음 17건 / 22건` — 값이 제 이름표를 되풀이했다 | `정보 없음 │ 17건 / 22건 (…)` |
| 「주의」 사유 | `내게 중요한 31개 중 10개만 압니다` — 조건을 하나도 안 골랐을 때도 「내게 중요한」이었다 | `판단에 필요한 31개 항목 가운데 10개만 확인됐습니다` |
| 신뢰도 인수 | `커버리지 0.32 × 신선도 1.00` | `확인된 비율 0.32 × 최신성 1.00` |
| 경로 안내 근거 | `… · desk · 2026-09-02` — enum 값이 그대로 | `… · 공개 자료 검토 · 2026-09-02` |
| 최소 규칙 안내 | `휠체어 이용 기준으로 계산합니다` — **휴식 한계로 고른 페르소나이지 Layer B가 최소를 취하는 그 사람이 아니다** | 페르소나를 지목하지 않는다 |
| 「✕ 점자블록」 | 상태 없이 항목 이름만 | `✕ 이용 불가: 점자블록` |
| 코스 화면 | 눈썹 「코스」 + h1 「코스」 + 카드 눈썹 「코스」 | h1 하나 |
| 출처 화면 표 캡션 | h1과 같은 문장 | 표가 무엇인지 |
| 출처 화면 정직성 목록 | 제목이 「KWCAG 2.2 자체 점검」 — **목록 항목 중 하나를 목록 전체의 이름으로 쓰고 있었다** | 「이 서비스가 스스로 밝히는 것」, 자체 점검은 항목으로 |
| 갭 리포트 절 제목 | `항목 수`, `우선순위` — **열 이름표를 절 제목으로 썼다** | `관광지별 채움률`, `개선 우선순위` |
| 첫 화면 탭 제목 | `조건 고르기` — **사이트 이름이 없는 유일한 화면.** 제목 템플릿은 자식 세그먼트에만 걸리는데 이 페이지는 같은 세그먼트다 | `조건 고르기 · 모두의 백제` |

**갭 리포트가 80건 중 40건만 보여주면서 그 말을 안 했다.** 게다가 40번째 줄은 **우선순위가 같은 48건
한가운데**였다 — 41번과 40번이 같은 값인데 한쪽만 잘렸다. 순위 열은 1부터 40까지 찍혀서 없는 순서를
주장하고 있었다. 순위 열을 지우고(정렬돼 있고 우선순위 값이 옆에 있다), 몇 건 중 몇 건인지와 CSV에
전부 있다는 것을 적었다.

**사진 17장의 대체 텍스트가 전부 같은 세 글자였다.** 「공산성」이 열일곱 번. 갤러리 기록에 제목이
없으면 관광지 이름으로 되돌아갔기 때문이다. 무엇이 찍혔는지 쓰는 것은 우리에게 없는 정보이고
(아무도 안 봤고, 안 본 것을 쓰는 것이 이 서비스가 도처에서 거부하는 바로 그것이다), 번호를 붙였다 —
`공산성 사진 3`. 관광지 이름과 똑같은 캡션은 지운다.

**영문 화면에 선언되지 않은 한국어.** `unescoComponentNote`가 `lang` 없이 영문 페이지에 그대로
나왔다 — 영어 음성이 한글을 음소로 읽는다. `lang="ko"`.

**내비게이션에 현재 위치 표시가 없었다.** 다섯 개가 전부 똑같이 생겨서 스크린 리더 사용자가 자기
위치를 알 방법이 없었다. `aria-current="page"`와 밑줄.

## 12. 굳힌 것 — 결함은 아니지만 얇았던 자리

- **보안 헤더가 하나도 없었다.** CSP도, `nosniff`도, `Referrer-Policy`도, 프레임 보호도 없고,
  `X-Powered-By: Next.js`는 나가고 있었다(실측). 이 사이트는 **방문자가 쓴 글을 화면에 렌더한다.**
  CSP는 실제 재고를 그대로 적었다 — 서체는 자체 제공, 분석 스크립트 없음, 지도 SDK 없음, 외부
  이미지는 KTO 두 호스트뿐, 런타임 연결은 Supabase뿐. `Permissions-Policy`로 위치·카메라·마이크를
  끈 것은 **처리방침이 글로 말하는 것을 브라우저가 강제하게 한 것**이다.
- **`(admin)`과 `(print)`에 오류 경계가 없었다.** 자기 루트 레이아웃을 가진 라우트 그룹은
  자기 `error.tsx`를 갖거나 못 갖거나다. 환경변수가 빠진 배포에서 `createServerClient()`가 던지면
  운영자가 Next 기본 화면 — 영어, 서식 없음, `lang` 없음 — 을 본다. `(site)`가 이미 막아 둔 바로
  그 실패다.
- **`/api/reports?poi=`가 슬러그를 검증하지 않았다.** 주입은 아니다(supabase-js가 파라미터로
  보낸다). 다른 모든 입구가 `POI_SLUGS`를 확인하는데 여기만 안 했다.
- **`verifiedAt`에 형태 검사가 없었다.** 주석은 옆 필드(`ktoModifiedAt`)에 붙어 있고, 신선도 산술이
  읽는 것은 이 필드다. 14자리 KTO 스탬프가 통과하면 `Date.parse`가 NaN을 주고 그 사실이
  **영원히 가장 오래된 구간에 앉는다.** `z.iso.date()`.
- **GPX 좌표에 유한성 검사가 없었다.** 옆의 이름은 이스케이프하면서 숫자는 그대로 속성에 넣었다.
  `lat="NaN"`은 모든 파서가 거절하는데, 방문자는 지도 앱이 파일을 거절할 때 그걸 안다.
- **제보 화면의 `revalidate = 3600`이 죽어 있었다.** `searchParams`를 읽으므로 완전 동적이다 —
  프리렌더 매니페스트의 어느 목록에도 없다. 이 저장소는 다른 모든 곳에서 캐시 의도를 정확히
  적는다.
