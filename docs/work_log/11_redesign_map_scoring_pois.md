# 11 — 점수 모델 v6, 지도, 관광지 확장, 화면 재설계

앞 회차(10)까지는 배포된 것을 다시 재어 보는 작업이었다. 이 회차는 **재어 보니 틀린 것을 고친** 작업이다. 네 덩어리가 서로 물려 있다.

1. 점수 모델 v6 — 라벨 네 개 중 하나가 산술적으로 나올 수 없었다.
2. 지도 — DEC-2의 기본값(지도 없음)을 뒤집고 네이버 지도를 붙였다.
3. 관광지 6곳 → 13곳, 그리고 그것을 가능하게 한 분류(`placeRole`).
4. 화면 재설계 — 「AI가 만든 티」의 실체를 찾아서 걷어냈다.

먼저 발견한 생산 장애 두 건은 §1에 따로 적는다. 나머지와 성격이 다르다.

## 1. 배포된 채로 망가져 있던 것 두 건

### 1.1 도슨트 오디오가 한 번도 재생된 적이 없다

`next.config.ts`의 Content-Security-Policy가 이렇게 적혀 있었다.

```
media-src 'self' https://tong.visitkorea.or.kr https://cdn.visitkorea.or.kr
```

두 호스트는 **사진**이 오는 곳이다. Odii 오디오는 `https://sfj608538-sfj608538.ktcdn.co.kr/file/audio/56/*.mp3` 에서 온다. 저장된 103건이 전부 그 호스트다. 자막 트랙은 `data:text/vtt` URL이고 이것도 목록에 없었다.

그래서 브라우저는 mp3를 **요청조차 하지 않았다.** 그리고 이것이 조용했던 이유가 중요하다 — CSP가 막은 `<audio>`는 코드가 볼 수 있는 형태의 error를 쏘지 않는다. `DocentPlayer`의 `onError`는 한 번도 실행되지 않았고, ESLint의 `jsx-a11y/media-has-caption`은 `<track>` **요소**가 있는지만 보므로 내내 통과했다. 화면에는 멀쩡한 재생 막대가 있었다.

고친 방법은 호스트를 한 줄 추가하는 것이 아니다. 원인은 **CSP를 데이터가 아니라 짐작으로 썼다**는 것이므로, 목록 자체를 한 곳에 두고 수집 단계가 그 목록에 대고 검사하게 했다.

- `src/config/media-hosts.ts` — `AUDIO_HOSTS` 한 곳.
- `next.config.ts`가 이 상수로 `media-src`를 만든다.
- `scripts/ingest.ts`의 `checkedAudioUrl()`이 목록 밖 호스트를 만나면 **수집을 멈춘다.** 경고로 두면 야간 cron 로그에서 그대로 묻히고, 그 침묵이 바로 이 버그였다.

검증은 태그 개수가 아니라 실제 디코드로 했다 — 헤드리스 브라우저에서 `loadedmetadata` 대기 후 `duration = 124.667938`, CSP 차단 0건.

### 1.2 인쇄용 여행 기록의 반복 푸터가 인쇄되지 않았다

`globals.css`에 같은 선택자가 두 번 있었다. `@media print` 안에서 `display: block`, 파일 뒤쪽에서 `display: none`. 특성도 같고 레이어도 같으므로 **뒤에 오는 쪽이 이긴다.** 인쇄에서도 `none`이었다. `@page`의 아래쪽 여백 28mm는 그리지도 않는 것을 위해 비워 둔 자리였다.

뒤쪽 규칙을 `@media screen`으로 감쌌다.

## 2. 점수 모델 v6 — 라벨 하나가 산술적으로 불가능했다

### 2.1 증상과 원인

화면의 관광지가 **전부 「주의 필요」** 였다. 조건을 무엇으로 바꿔도 그랬다.

실제 스냅샷으로 재어 보니 원인이 분명했다.

| 조건 | 점수 범위 | 라벨 |
|---|---|---|
| 조건 미선택 | 44 ~ 61 | 6곳 전부 주의 |
| 휠체어 | 44 ~ 62 | 6곳 전부 주의 |
| 시니어 | 44 ~ 62 | 6곳 전부 주의 |
| 유아차 | 44 ~ 62 | 6곳 전부 주의 |

Layer A는 0.499~0.668, Layer B는 0.86~0.93. 곱의 최댓값이 **0.62**, 즉 62점이다. 「방문 가능」 기준선은 **75점**이다. 이 데이터에서는 어떤 입력으로도 넘을 수 없다.

원인은 같은 결함을 **세 번 청구**한 것이었다.

1. `unknown`에 0.35를 주고 분모에 남겨 둬서 → 점수를 깎고,
2. `coverage < 0.65`면 라벨을 「주의」로 덮어써서 → 등급을 깎고,
3. `evidenceConfidence`에 또 반영해서 → 신뢰도를 깎았다.

한국관광공사 무장애 항목은 시설이 **있을 때만** 채워진다. 그래서 어느 관광지든 33개 중 10~16개만 알려져 있고, 위 세 규칙이 겹치는 순간 점수는 구조적으로 60점대에 갇힌다.

### 2.2 고친 규칙

스펙이 이미 정해 둔 규칙을 그대로 확장했다 — **「오래된 데이터는 점수가 아니라 신뢰도를 낮춘다」(DEC-9)**. 없는 데이터에도 같은 규칙을 적용한다.

- `unknown`은 `not_applicable`과 똑같이 **모든 분모에서 빠진다.** 점수는 「확인된 항목만 놓고 볼 때 이 사람에게 얼마나 맞는가」를 답한다.
- 얼마나 확인했는지는 옆의 **확인율**이 답한다.
- 그 사람이 **의지하는 항목**이 확인된 것들 안에 있는지가 라벨을 정한다.

라벨 규칙:

```
1) 기준 항목 중 하나라도 이용 불가 확인  → 대체추천 (점수 ≤ 49)
2) 어느 한 조건의 기준 항목 절반 초과 미확인 → 정보없음
3) 기준 항목 중 하나라도 미확인            → 주의
4) 그 외, 점수 ≥ 75                        → 방문가능
5) 그 외                                   → 주의
```

`coverage < 0.65` 상한(구 4b)은 **삭제**했다. 규칙 3이 이미 같은 질문에 더 정확히 답하고 있었고, 그 임계값은 실제 데이터가 도달하지 못하는 위치에 있었다.

### 2.3 조건을 안 고른 경우 — `GENERAL_VERDICT_CODES`

P0(조건 미선택)에는 정의상 「기준 항목」이 없다. 규칙 3·4가 판단할 대상이 없다는 뜻이다.

전에는 P0의 관련 항목을 **33개 전부**로 뒀다. 그러면 「방문 가능」이 수어 안내와 점자 홍보물까지 포함한 주장이 되고, 그건 아무것도 고르지 않은 사람에게 물어본 적 없는 것이다.

대신 **둘 이상의 조건이 결정적이라고 보는 항목 네 개**를 P0의 기준으로 쓴다 — 접근로, 출입통로, 엘리베이터, 장애인 화장실. 손으로 고른 목록이 아니라 페르소나 행렬에서 나오는 집합이고, `assertPersonaMatrix()`가 선언과 행렬이 어긋나면 테스트를 깨뜨린다.

### 2.4 바뀐 뒤 실제 값 (관광지 13곳, 조건 미선택)

```
백제문화단지        100 방문 가능   확인 11/31
국립공주박물관       98 방문 가능   확인 15/31
백제역사문화관      100 주의       확인  8/31  확인 필요: 장애인 화장실
부여 나성          100 주의       확인  7/31  확인 필요: 출입통로, 엘리베이터
무령왕릉과 왕릉원     94 주의       확인 16/31  확인 필요: 엘리베이터
국립부여박물관       86 주의       확인 16/31  확인 필요: 엘리베이터
정림사지            82 주의       확인 14/31  확인 필요: 출입통로
공산성              71 주의       확인 10/31  확인 필요: 엘리베이터
부소산성            68 주의       확인 13/30
구드래조각공원        — 정보 없음   확인 10/31
서동공원과 궁남지     49 다른 곳 권장 확인 11/31  이용 불가: 출입통로
```

네 라벨이 전부 나온다. 「주의」마다 **무엇을 확인해야 하는지**가 붙는다. 시각장애 조건에서는 부소산성이 점자블록 부재 확인으로 **대체추천**이 된다.

### 2.5 점수가 100인 곳을 어떻게 다루는가

확인된 6개가 전부 이용 가능이면 점수는 100이 된다. 이건 「완벽하다」가 아니라 「확인한 것 중에는 걸리는 게 없다」는 뜻이고, 그 차이가 화면에서 보여야 한다.

- 목록 카드: `적합도 100` 과 `확인 11/31` 을 **나란히**, 둘 다 세는 대상을 말하는 단어를 달고.
- 상세 화면: 숫자 위에 「확인된 11개 항목 기준」.
- 「정보 없음」이면 점수는 여전히 감춘다.

### 2.6 테스트

골든 25건 재생성, 속성 테스트 2건 교체·3건 추가.

- 삭제: `coverage-cap`, `coverage-boundary`, `coverage-boundary-capped` — 존재하지 않는 규칙을 검사하던 것. 끄지 않고 **지웠다**.
- 추가: `low-coverage-criticals-known` 쌍 — 그 사람이 의지하지 않는 항목이 미확인이면 확인율과 신뢰도만 내려가고 점수·라벨은 그대로임을 고정한다. 상한이 되살아나면 깨진다.
- 추가: `general-verdict-reachable` / `general-verdict-one-unknown` — **이 회차의 결함 자체에 대한 회귀 시험.** v5에서는 어떤 입력으로도 방문가능이 나오지 않았다.
- 추가: unknown이 분모에서 빠지는지, 전부 미확인인 축이 가중치 합에서 빠지고 나머지가 1.00으로 다시 정규화되는지.

또 함께 지운 것: `layer-c-guard.json`, `layer-c-cap.json`, `no-certifications.json` — v5에서 규칙과 함께 지웠어야 할 고아 골든 파일 3개.

## 3. 지도 — DEC-2를 뒤집었다

### 3.1 제공사 결정

네이버 지도 v3. 구글 지도도 키가 있었고 **지금 바로 렌더됐지만** 네이버로 갔다.

| | 네이버 | 구글 |
|---|---|---|
| 국내 지명·POI | 최상 | 쓸 만함 (TMap Mobility 데이터) |
| 지금 인증 | **실패** (URL 미등록) | 정상 |
| 국내 길찾기 API | 있음 | 한국에서 막혀 있음 |
| CSP 확장 폭 | 3개 호스트 | 4개 호스트 + 구글 서체 |
| 서체 | 영향 없음 | `fonts.googleapis.com` 다시 열림 — D-6의 자체 호스팅 결정과 충돌 |

구글이 당장 된다는 것은 채택 사유가 못 된다. 네이버의 실패는 SDK 결함이 아니라 **NCP 애플리케이션에 서비스 URL이 등록돼 있지 않은 것**이고, 그건 콘솔에서 2분이면 끝나는 소유자 작업이다.

**아직 안 된 일:** NCP 콘솔 → AI·NAVER API → Application → `modu-baekje` → Web 서비스 URL 에 `http://localhost:3000` 과 `https://modu-baekje.vercel.app` 등록. 그때까지 지도 자리에는 스펙이 정해 둔 문장이 뜬다 — 「지도를 불러오지 못했습니다. 위 목록으로 모든 기능을 이용할 수 있습니다.」

### 3.2 접근성 설계

`07_screens.md` S2와 `08_accessibility_legal.md` §1.2가 정한 것을 그대로 옮겼다.

- **목록이 먼저, 지도는 그 아래.** 탭 없음. 목록을 감추는 수단(`hidden`/`display:none`/`aria-hidden`) 일절 없음.
- **드래그·핀치 전용 기능 없음.** 확대·축소·상하좌우 이동이 전부 `<button>`이고, 그 버튼들은 **타일 면 바깥**에 있다.
- 제공사의 확대/지도유형/축척 위젯은 껐다. 접근 가능한 이름 없이 오는 제공사 DOM이고, 위 버튼이 그 자리를 대신한다. 로고와 저작자 표기는 약관상 남긴다.
- **마커는 실제 DOM.** 색·기호·이름 세 가지가 모두 판정을 나른다. 목록이 점수를 감추는 「정보 없음」에서는 마커도 감춘다.
- 마커와 목록은 **같은 계산 결과**를 쓴다 — `PlaceList`가 이미 채점한 항목을 그대로 넘긴다. 따로 계산했다면 조건을 바꾼 뒤 지도와 목록이 다른 판정을 보여줄 수 있다.

### 3.3 실패 상태

`navermap_authFailure` 하나로는 부족하다. 인증 검사는 **스크립트 로드와 지도 생성이 끝난 뒤** 돌아오므로, 로드 promise를 reject해 봐야 이미 resolve된 뒤다. 그 사이 화면에는 네이버가 그린 한국어 오류 타일이 깔린다.

그래서 `naver.ts`에 구독자 목록을 두고, 답이 오면 모든 지도에 알린다. 실패 뒤에 구독한 쪽에는 즉시 알린다. 상태는 `loading → ready` / `script_error` / `auth_error` 셋이고, 세 실패 모두 같은 문장으로 수렴한다.

### 3.4 CSP — 문서가 아니라 측정으로 썼다

실제로 관찰한 요청은 이랬다.

- 키 검사가 **JSONP**다. `oapi.map.naver.com/v3/auth?...&callback=...` → `connect-src`가 아니라 `script-src`.
- 스타일 매니페스트도 JSONP다. `nrbe.map.naver.net/styles/basic.json?...&callback=...` → 이 호스트는 **script source이자 image source**다.
- `static.naver.net` — 스프라이트와 드래그 커서.

스킴은 일부러 안 붙였다. 스킴 없는 host-source는 페이지 자신의 스킴을 따르므로, `next dev`의 http는 되고 배포된 https 페이지는 http를 계속 거부한다.

**`kr-col-ext.nelo.navercorp.com`은 일부러 뺐다.** NELO(네이버 오류 수집기)이고, 막아 둔 채로 타일·마커·컨트롤이 전부 정상 동작하는 것을 확인했다. 콘솔 경고를 지우자고 telemetry 엔드포인트를 열면 그건 처리방침에 적어야 하는 데이터 흐름이 하나 늘어나는 것이다.

### 3.5 처리방침·출처

D-5가 「지도를 넣으면 그때 한 줄을 추가한다」고 적어 뒀는데, 한 줄로는 안 됐다.

- `/privacy` §5 처리 위탁에 네이버클라우드를 넣고, **무엇이 전달되는지** 적었다 — 접속 IP, 브라우저 종류, 요청 시각, 어느 화면에서 요청했는지. 제보 내용과 익명 식별자는 지도 쪽으로 가지 않는다는 것도.
- §6 국외 이전에 국내 사업자임을 적었다.
- 「지도 기능은 이번 범위에 없다」는 문장을 지우고, NELO 차단 사실로 바꿨다.
- `/credits` 자산표에 한 줄 추가.

## 4. 관광지 6곳 → 13곳

### 4.1 먼저 화면이 거짓말을 하게 돼 있었다

데이터만 넣으면 안 되는 이유가 있었다. 목록과 상세가 `isUnescoComponent` **불리언 하나**로 두 문장 중 하나를 찍고 있었다 — 「구성유산」 아니면 「구성유산 인접 시설」.

여섯 곳(구성유산 4 + 그 옆 박물관 2)일 때는 참이었다. 백제문화단지를 넣는 순간 거짓이 된다. **구성유산이 아니라고 해서 구성유산 옆에 있는 것은 아니다.**

`placeRole` 세 값으로 바꿨다.

- `unesco_component` — 유네스코 백제역사유적지구 구성유산
- `baekje_museum` — 백제 유물 박물관

## 5. 화면 재설계 — 「AI 티」의 실체

두 갈래로 따로 진단했고 같은 결론이 나왔다. 초록색이 하나뿐이라서도, 명조체가 없어서도 아니었다.

> **스펙의 항목 하나하나를 같은 시각 부품으로 한 줄씩 옮긴 흔적.**

셀 수 있는 형태로:

- `.card`(회색 슬랩)가 **21곳**. 판정, 사용법, 범례, 계산 내역, 긴급 연락처가 전부 같은 상자.
- `<Eyebrow>`(등폭 대문자 자간 벌린 금색 라벨 + 오른쪽으로 빠지는 선)가 **29곳**. 그중 여섯 화면에서는 바로 아래 제목과 **같은 단어**였다 — 「갭 리포트」 위에 「갭 리포트」.
- 임의 글자 크기 `text-[…rem]`가 서로 다른 값 **23종, 113곳**. 그중 여섯 개는 자기가 덮어쓰는 `.subhead`보다 작았다. 한 파일에 선언하고 다른 모든 파일에서 부정하는 것은 스케일이 아니다.
- 사진 **0장**. 공산성 한 곳만 해도 라이선스 정리된 사진 17장을 들고 있으면서 목록에 한 장도 안 썼다.
- 가운뎃점으로 이어 붙인 메타 문자열, `01 / 02 / 03` 금색 등폭 번호.

### 5.1 한 것

- **`.eyebrow`와 `<Eyebrow>` 삭제.** 제목 노릇을 하던 자리는 진짜 `<h2>`가 됐고(`aria-labelledby` 대상이므로 없애면 안 된다), 장식이던 자리는 지웠다. 섹션의 경계는 라벨이 아니라 `.section-head`의 선이 긋는다.
- **6단계 글자 스케일** `--text-xs/sm/base/md/lg` + 클래스 `.t-xs .t-sm .t-md .t-lg`. 임의값 113곳을 전부 여기로 접었다. 클래스라서 grep이 된다.
- **`.card`를 역할별로 쪼갰다.** `.verdict`(판정 — 사이트에서 유일하게 큰 목소리를 허용한 요소), `.record`(선으로 나눈 목록 행, 배경 없음), `.tile`(사진 + 판정 + 근거 요약이 한 줄에 읽히는 관광지 카드).
- **사진을 쓴다.** 목록은 서버가 고른 한 장, 상세는 제목 옆에 한 장. **배경으로 깔지 않는다** — 사진 위 글자는 대비비를 지킬 수 없고 이 빌드는 대비 검사에서 떨어진다. KOGL 3유형은 자르지 않고 `contain`으로 맞춘다.
- **판정 블록의 순서를 뒤집었다.** 전에는 2.1rem 점수가 맨 앞이었다. 지금은 라벨 → **무엇을 근거로 한 판정인지** → 확인해야 할 항목 → 세 숫자(적합도·확인율·신뢰도) → 조건. 큰 숫자를 앞세우면 정밀한 측정처럼 읽히는데, 이건 채워진 칸들의 평균이다.
- **넓은 화면에 할 일을 줬다.** `.page-split` — 본문 + 15~18rem 레일. 홈의 레일은 장식이 아니라 **측정값**이다(관광지 수, 항목 수, 확인된 항목 수). 그 숫자가 곧 이 서비스의 주장이다.
- **갭 리포트 채움률 표.** 숫자 열의 제목이 `text-align: start`, 값이 `end`였다. 「한국관광공사 확인」이 283px 상자의 왼쪽 끝, 한 자리 숫자가 오른쪽 끝. 제목과 열이 한 덩어리로 안 읽혔다. 제목을 값과 같은 쪽으로 붙이고, 숫자 열은 `inline-size: 1%`로 내용만큼만 차지하게 했다.

### 5.2 안 한 것, 그리고 왜

Codex 검토가 잡아낸 함정이 있다 — **명조체 + 금박 + 전면 히어로 이미지도 똑같이 흔한 AI 문화유산 템플릿이다.** 「일반적인 SaaS」를 「일반적인 유산 랜딩페이지」로 바꾸는 데 그칠 수 있다.

그래서 잘라냈다.

| 안 한 것 | 이유 |
|---|---|
| 제목용 명조체 추가 | x-height가 작고 획이 가늘다. 서브셋 92개가 또 붙고, 디자인 문제의 원인도 아니었다 |
| 금동대향로 금색·청동색 팔레트 확장 | 금색 토큰은 이미 있다. 판정 색과 충돌하고 가짜 유산 장식이 되기 쉽다 |
| 모든 카드를 1px 선 블록으로 | 저시력 사용자에게 저대비 1px 선은 묶음 경계가 되지 못한다. 판정 블록은 채운 면으로 남겼다 |
| 상세 화면 전면 히어로 | 접근성 판정과 근거를 아래로 민다. 이 화면의 주인공은 사진이 아니다 |
| 넓은 화면의 빈 공간 채우기 | 빈 공간은 줄 길이를 지킨다. 기능이 있을 때만 쓴다 |

지킨 것: 17px 기본 크기, 40rem 본문 폭, 근거·출처 노출, 명시적 「모름」 상태, 44px 클릭 영역, 3px 초점 테두리, `prefers-reduced-motion`, 판정 배지의 색+기호+글자 삼중.

## 6. 문구

두 규칙으로 나눴다.

- **원문 증거는 건드리지 않는다.** 한국관광공사 원문, API 필드명, 출처, 확인일 — 이 화면의 존재 이유다.
- **화면 문구는 고친다.** 제목, 설명, 버튼, 빈 상태, 안내문.

고친 것 중 성격이 다른 것들만 적는다.

- **`「확인됨」이 두 뜻으로 쓰였다.`** `common.status.supported`(시설이 **있다**)와 갭 리포트의 「한국관광공사 확인」(누가 **검증했다**)이 같은 단어였다. 영문은 `Available`/`Confirmed by KTO`로 갈라져 있었고 한국어만 뭉개져 있었다. 상태 쪽을 **「이용 가능」**으로 바꿨다.
- **내부 회계 규칙을 방문자에게 설명하던 문장들.** 대표적으로 `gapReport.fillNote`의 「**인계 성과**로 읽을 수 있는 것은…」 — 「인계 성과」는 한국어에 없는 말이다. `causeNote`의 「…이 열의 **존재 이유**입니다」는 raison d'être 직역.
- **용어 통일.** 축/분야 → 축. 예측 혼잡도/집중률 → 예측 혼잡도. 파생 항목 → 우리가 더한 항목.
- **`content/safety-directory.json`의 문체.** 한 문자열 안에서 명사 파편 → 완결문 → 명사 파편으로 세 번 바뀌던 것들을 합쇼체로 폈다. 「야간콜제」처럼 설명 없는 전문어는 풀었다.
- **중복 삭제.** 시설 7건의 `sourceNote`가 「직선거리이며 실제 이동거리가 아닙니다」를 반복하고 있었다. 바로 위 섹션 안내문이 이미 같은 말을 한다 — 한 화면에 최대 3번 나왔다.

e2e에 하드코딩돼 있던 화면 문자열은 메시지 파일에서 읽도록 바꿨다. 문구를 고쳤다고 「요소가 있는가」를 묻는 테스트가 깨지면 안 된다.

## 7. 코드 감사에서 나온 나머지

- **제보 날짜가 UTC로 찍혔다.** `created_at`은 `timestamptz`이고 PostgREST가 UTC로 직렬화한다. KST 09시 이전에 올라온 제보는 **하루 전 날짜**로 보였다. 관리자 화면은 시간대 표시 없는 UTC 벽시계라 9시간 어긋났다. `Asia/Seoul`로 포맷한다.
- **관리자 화면이 전체 합계와 현재 페이지 개수를 한 줄에 섞었다.** 「전체 300건 · 숨김 3건」에서 3은 이 페이지의 3이었다.
- **공개 오류 화면이 자기 설정 안내를 노출했다.** `result.message.split(':')[0]`이 「어느 스냅샷인지만」 남기려는 코드였는데, 콜론이 없는 메시지 하나가 있었다 — 환경변수 이름과 `MODU_DATA_SOURCE=fixtures` 우회 방법까지 그대로. 스냅샷 키를 결과 타입의 필드로 올렸다.
- **코스 화면이 체류 배수 옆에 엉뚱한 사람을 적었다.** 배수는 **최대 `stayMultiplier`**로 고르고, 이름은 **최소 `restLimitMinutes`**로 골랐다. 서로 다른 속성이다. 휠체어+유아차면 「영유아 동반 가족 기준 ×1.25」가 나왔고 1.25는 휠체어 값이다.
- **수집기가 `validate-content.ts`를 import 부수효과로 통째로 실행했다.** 그 파일은 모듈이 아니라 프로그램이고 실패 시 `process.exit(1)` 한다. 상수를 `content-schema.ts`로 옮겼다.
- **`lastMonthYm()`이 UTC였다.** cron이 19:00 UTC = KST 다음날 04:00이라, 한국 기준 매월 1일 실행은 UTC로 전달 말일이고 거기서 한 달을 더 빼서 **두 달 전**을 요청했다.
- **여행 기록이 라벨을 값으로 찍었다** — 「방문함 | 방문함」.
- **`script-src 'unsafe-eval'`이 무조건이었다.** React Refresh의 것이고 `next dev`에서만 필요하다. 개발 환경에서만 붙인다.
- `RouteExports`의 다운로드 두 가지 함정(`URL.revokeObjectURL` 즉시 호출, 문서에 붙이지 않은 앵커) — `DiaryEditor`가 고쳐 놓고 주석까지 남긴 것을 그대로 옮겼다.
- 실패를 삼키던 클릭 핸들러 2곳(제보 신고, 관리자 클립보드 복사).
- `?note=a&note=b` 같은 주소가 제보 화면을 실패로 보이게 하던 것.
- `SpeechSynthesisUtterance`에 `onerror`가 없어 버튼이 「멈추기」에 붙박이던 것.

6. **`pnpm probe` 재실행** — 08회차 이후 안 했다.

## 9. 배포 순서 (반드시 이 순서)

`placeRole`이 스냅샷 스키마의 **필수 필드**가 됐다. 배포된 코드와 데이터베이스의 스냅샷이 잠깐 어긋나는 구간을 피할 수 없다.

```
1. 코드 먼저 배포한다 (push → Vercel)
2. 배포가 끝나면 즉시 pnpm ingest
3. /ko/places 에서 13곳과 판정을 확인한다
```

2번 전까지 화면에는 「데이터를 불러오지 못했습니다」가 뜬다. 구 스냅샷에는 `placeRole`이 없고 새 코드의 Zod가 그것을 요구하기 때문이다. 반대 순서로 하면 구 코드가 신 스냅샷을 거부하므로 같은 구간이 생기고, 그쪽은 수집이 끝난 뒤에도 배포가 끝날 때까지 이어진다.

`/api/report`가 받는 slug 목록은 **번들된** `content/pois.json`에서 나온다. 수집을 먼저 하면 새 관광지가 화면에는 보이는데 그 관광지 제보는 `unknown place`로 거절된다 — 이것도 코드 먼저여야 하는 이유다.

### 실제로 밟은 순서와, 그 과정에서 하나 더 나온 것

배포 → 수집 → 확인 순으로 했고, 3번에서 걸렸다. 수집은 「ok cache invalidated」를 찍었는데 배포본은 계속 옛 스냅샷을 내보내고 있었다.

원인은 코드가 아니라 로컬 환경변수다. 수집기는 `NEXT_PUBLIC_SITE_URL`로 무효화를 부르고, 로컬 `.env.local`은 `http://localhost:3000`을 가리키고 있었다. **개발 서버의 캐시를 지운 것이다.** 로그 줄은 어느 쪽을 지웠는지 말하지 않았으므로 성공으로 읽혔다.

10회차의 「`{"ok":true}`를 주면서 아무것도 안 했다」와 **다른 버그이고 같은 모양**이다. 그래서 같은 방식으로 고쳤다 — 이제 무효화한 호스트를 찍는다.

```
ok       cache invalidated on localhost:3000
ok       cache invalidated on modu-baekje.vercel.app
```

배포본은 `/api/revalidate`를 직접 불러 갱신했고, 그 다음 확인은 통과했다.

### 배포 확인 (2026-09-15, `f392c6d`)

```
20개 경로: 200 ×18 · 307 ×1 (/) · 404 ×1 (의도)
/ko/places  가로 넘침 0 · 사진 13장 중 13장 디코드 · 콘솔 오류 0
도슨트 오디오 실제 디코드: duration 124.667938
```

**아직 남은 콘솔 조건:** 배포본에는 `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`가 없어 지도가 네트워크 요청 자체를 하지 않는다. 그래서 콘솔 오류가 0인 것이고, 지도 자리에는 실패 문구가 뜬다. Vercel 환경변수에 키를 넣고 NCP에 URL을 등록하면 그때부터 타일이 뜬다.

## 10. 지도가 인증된 뒤 — 브라우저로 직접 만져 본 회차

NCP 콘솔에 URL이 등록되면서 지도가 실제로 그려졌고, 그때부터 보이는 것들이 있었다.

### 10.1 검사 하나가 헛돌고 있었다

`.map-canvas`를 axe에서 제외하는 것이 마커까지 검사에서 빼는 것 아니냐는 지적이 있었다. **재어 보니 그렇지 않았다** — 제외한 스캔과 제외하지 않은 스캔이 둘 다 위반 0건이다. 네이버가 캔버스 안에 넣는 DOM(로고, 저작자 표기)도 통과한다.

그래도 제외는 남겼다. 그 DOM은 우리 커밋 없이 바뀔 수 있고, 제3자 마크업이 빌드를 깨는 것은 게이트가 할 일이 아니다. 대신 **우리가 소유한 것만 직접 검사하는 시험**을 따로 넣었다 — 마커마다 실제 `<a>`인지, 접근 가능한 이름이 목록 행과 같은 이름으로 시작하는지, 24px를 넘는지.

여기서 한 번 더 걸렸다. 그 시험이 **처음에는 아무것도 검사하지 않고 통과했다.** Playwright가 `http://127.0.0.1:3100`에서 스위트를 띄우는데 그 origin이 NCP에 등록돼 있지 않아 지도가 뜨지 않았고, 시험은 「지도가 안 뜬 경우」 분기로 빠져 초록이 됐다. 마커 이름을 일부러 깨뜨려도 통과했다.

두 가지를 고쳤다.

- `playwright.config.ts`의 origin을 `localhost:3100`으로 통일했다. `127.0.0.1`과 `localhost`는 Referer를 보는 쪽에게 서로 다른 origin이다 — 직접 확인했다.
- 시험이 세 상태를 구분한다. 마커가 있으면 전부 검사하고, 키가 없으면 검사하지 않았다고 주석을 남기고, **키가 있는데 인증이 거부되면 실패한다.** 마지막 상태가 「통과했지만 아무것도 안 본」 상태이고, 그것이 방금 벌어진 일이다.

깨뜨려서 확인했다 — 마커 이름 앞 두 글자를 지우니 `marker 0: "문화단지 — 방문 가능 100"`으로 빨갛게 떨어진다.

### 10.2 axe가 데스크톱 폭에서만 돌고 있었다

갭 리포트를 390px로 열었더니 관광지 이름이 **한 음절씩 세로로** 쌓여 있었다. `.data-table`이 `inline-size: 100%`라 폭이 모자라면 줄어들고, 숫자 열은 내용 폭을 지키므로 남는 것이 전부 첫 열에서 빠진다 — 390px에서 첫 열이 20px였다.

`min-inline-size: 38rem`을 줘서 좁은 화면에서는 표가 상자 안에서 **가로로 스크롤**하게 했다. 그런데 스크롤되는 상자는 키보드로 접근할 수 없으면 wcag21a 위반이고, **데스크톱 폭에서는 표가 스크롤되지 않으므로 기존 스캔이 구조적으로 볼 수 없는 결함**이었다.

그래서 `.scroll-x` 네 곳에 `tabIndex`와 이름을 붙이고, **390px axe 패스를 스위트에 추가**했다. 이것도 깨뜨려서 확인했다 — `tabIndex`를 하나 떼면 `scrollable-region-focusable (serious)`로 떨어진다.

### 10.3 그 밖에 직접 만져 보고 고친 것

- **지도가 레터박스였다.** 공주와 부여는 남북으로 40km 떨어져 있어서, 가로로 넓은 상자에 둘을 맞추면 양옆에 도 하나씩이 들어온다. 높이를 `clamp(20rem, 52vw, 32rem)`으로 올렸다.
- **관광지 상세의 자기 자신 마커가 회색 물음표였다.** 판정 없음 색과 기호를 그대로 쓰고 있었으니, 읽고 있는 관광지가 「정보 없음」이라고 말한 셈이다. 자기 자신은 강조색 원, 주변 시설은 검정 사각형으로 갈랐다. 판정을 나르지 않는 마커는 판정 색도 판정 기호도 빌리지 않는다.
- **좌표가 같은 두 곳이 겹쳤다.** 백제역사문화관은 백제문화단지 안에 있어 소수점 일곱 자리까지 같다. 마커 `zIndex`를 목록 순서로 줘서 목록이 앞에 두는 쪽이 위로 오게 했다.
- **한글이 단어 가운데서 줄바꿈됐다.** 「공주·부여 무장애 정보 갭 리포트」가 390px에서 「무장」/「애」로 갈렸다. `word-break: keep-all`. CJK에만 적용되므로 영문 화면은 그대로다.
- **제보 화면에 레일을 붙였다.** 「바로 공개되고 운영자가 미리 읽지 않는다 / 판정 항목과 섞이지 않는다 / 점수에 안 들어간다 / 신고하면 90일 뒤 삭제된다」 — 폼 위 한 문장에 눌려 있던 것을 옆으로 폈다. 위 경고문은 가장 중요한 한 문장만 남겼다.
- **「{persona} 기준으로」가 조건 미선택일 때 「조건 미선택 — 일반 방문 기준 기준으로」가 됐다.** 영문도 문장 가운데 절이 박혔다. 조건은 목록 맨 위에 이미 한 번 적히므로 이 문장에서는 뺐다.
- **가로로 스크롤되는 표에 스크롤 그림자**를 넣었다. 끝난 것처럼 보이는 표와 더 있는 표를 구분해 준다. 스크립트 없이 배경 그러데이션 네 개.

### 10.4 직접 눌러 본 것

버튼을 실제로 눌러 확인했다 — 지도 확대 2회에 마커 간격이 `546→310`, `693→897`로 벌어지고, 왼쪽 이동에 `310→430`으로 움직인다. 마커 13개가 탭 순서 안에 있고 목록 **뒤에** 온다(첫 마커가 55번째 초점). 조건에서 휠체어를 고르면 목록 순서와 라벨이 바뀐다. 도슨트 오디오는 `duration 124.667938`로 디코드된다. CSV는 `무장애정보-갭리포트.csv`로 내려온다. 빈 제보 폼을 올리면 「무엇이 문제인지 하나 골라 주세요.」가 뜬다.

### 10.6 배포본에서만 나오는 결함 하나 — 제공사가 스킴마다 다른 호스트를 쓴다

지도 키가 배포본에도 들어간 뒤 브라우저로 열어 보니 **마커 13개가 회색 사각형 위에 떠 있었다.** 타일이 하나도 없었다.

콘솔이 원인을 그대로 말해 줬다.

```
Loading the script 'https://nrbe.pstatic.net/styles/basic.json?...' violates ... script-src
Loading the image 'https://ssl.pstatic.net/static/maps/mantle/1x/openhand.cur' violates ... img-src
```

개발 서버는 http라서 SDK가 `nrbe.map.naver.net`·`static.naver.net`을 부른다. 배포본은 https라서 **같은 것을 `nrbe.pstatic.net`·`ssl.pstatic.net`에서 가져온다.** CSP를 개발 세션에서 본 것만으로 썼으니 로컬은 통과하고 배포본만 막힌 것이다.

네 호스트를 전부 적었다. 그리고 이건 `curl`로는 절대 안 잡힌다 — 캔버스는 하이드레이션 뒤에 생기므로 HTML에는 `map-canvas`가 없고, 실제로 HTML만 보고 「배포본에 지도가 아직 없다」고 한 번 잘못 읽었다. 배포 뒤 브라우저로 여는 절차를 `docs/guide/05_operations.md`에 명령까지 적어 넣었다.
