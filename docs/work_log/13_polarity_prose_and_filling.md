# 13 — 극성 두 건, 대중교통을 항목에서 빼기, 그리고 빈칸 채우기

앞 회차(12)는 화면에서 사라지던 판정을 되찾았다. 이 회차는 **판정 자체가 거꾸로 나오던 자리**를 고치고, **비어 있던 칸 25개를 채웠다.** 그리고 채우려다 **가짜 출처 하나를 걸러냈다.**

세 덩어리다.

1. **`resolveStatus()`의 극성 버그** — 「턱이 없어 휠체어 접근 가능함」이 **이용 불가**로 나갔다. 장벽 사전에 머리 명사 `턱`이 없었다.
2. **`대중교통`을 항목에서 빼고 원문으로 내린 것** — 하나의 이름이 서로 다른 네 가지 질문을 뭉뚱그리고 있었다.
3. **빈칸 채우기 25건** — 새로 들어온 7곳의 확인된 항목이 61개에서 85개로 늘었다. 조사가 가져온 39건 중 14건은 **출처를 검증하다 버렸다**(§4.3).

조사는 세 갈래로 나눠 동시에 돌렸다(부여 4곳 / 공주·궁남지 3곳 / 안전시설 좌표 7곳). 검토도 세 갈래였다(데이터 감사 / 코드 리뷰 / 한국어 문안). 판단이 갈리는 것은 Codex와 따로 의논했다(§6).

## 1. 「턱이 없어」가 이용 불가로 나가고 있었다

### 1.1 증상

`서동공원과 궁남지`의 출입구 판정이 **이용 불가**였다. 그 옆에 같이 찍히던 근거 문장은 이랬다.

```
주 출입구는 턱이 없어 휠체어 접근 가능함     → 이용 불가
```

문장이 「가능함」으로 끝나는데 판정은 「불가」다. 같은 문장형이 `무령왕릉과 왕릉원`에도 있었지만, 그쪽은 손으로 넣은 확인 사실이 덮고 있어서 화면에 드러나지 않았다.

### 1.2 원인 — 머리 명사가 목록에 없었다

`src/domain/capabilities.ts`의 `BARRIER_NOUN`은 **복합어 `문턱`만** 들고 있었고, **머리 명사 `턱`이 없었다.**

KTO는 둘 다 쓴다. 그래서 「턱이 없어」에는 `없어`가 붙을 장벽이 없었고, 부정만 남아 같은 함수 아래쪽의 문장 전체 규칙으로 흘러갔다. 그 규칙이 `unsupported`를 돌려준다.

고친 뒤:

```ts
const BARRIER_NOUN = /(단차|턱(?!없)|계단|장애물|급경사|경사(?!로)|돌길|자갈|비포장|협소|좁음)/g;
```

`턱`은 `문턱`·`경사턱`·`단차턱` 안에서도 잡히고, 셋 다 같은 장벽이다.

### 1.3 부작용 하나 — `턱없이`는 다른 낱말이다

`턱`을 그대로 넣었더니 Codex가 바로 짚었다. **「턱없이」는 「엘리베이터」와 아무 상관이 없는 부사**다(「턱없이 부족한」 = 한참 모자란). 그리고 편의시설 이야기에 실제로 쓰인다.

재어 봤다. 고치기 전 상태로:

```
턱없이 부족한 편의시설   →  access_route / entrance_passage / path_continuity 모두 supported
```

**부족하다는 문장이 「이용 가능」으로 발행된다.** 부정어 `없이`가 「턱이 없다」로 읽혀서다.

처음에는 어미 둘만 막았다(`(?!없[이는])`). **그것도 샜다** — 코드 리뷰가 세 가지를 더 찾아왔고 재현됐다.

```
편의시설이 턱없어 불편함  →  supported      ← 「한참 모자라다」가 「이용 가능」
편의시설 턱없음          →  supported
주차면이 턱없다          →  unknown
```

어간 전체를 막는다: `턱(?!없)`. 대가는 띄어쓰기 없이 쓴 `턱없음`(단차 없음의 뜻)이 장벽으로 읽혀 `unsupported`가 되는 것인데, **틀리는 방향이 안전한 쪽**이고 KTO가 실제로 쓰는 `턱 없음`·`턱이 없어`는 그대로 잡힌다.

회귀 시험 5건을 넣었다. 전망을 지우면 전부 빨개진다 — 확인했다.

## 2. 한 번 고쳤다가 되돌린 것

### 2.1 그때 본 증상

```
대중교통 이용가능 : 사기소 정류장.저상버스 없음.   → 이용 불가
```

한 문장 안에 「이용가능」과 「없음」이 같이 있는데 판정은 뒤쪽 하나만 보고 내려간다. 같은 함수에서 **부정만 문장 전체를 읽는다**는 것이 원인처럼 보였고, 그래서 국소화했다 — 부정 옆에 부정되지 않은 존재 주장이 있으면 `unknown`.

### 2.2 왜 되돌렸나

**틀린 고침이었다.** 이유가 둘이다.

첫째, 이 증상은 §3에서 `publictransport`를 항목에서 빼는 순간 **이 함수에 도달할 수 없게 됐다.** `buildAccessibility`는 `ktoField`가 있는 항목만 돌린다. 고칠 대상이 사라졌다.

둘째, 국소화가 **멀쩡한 문장들을 망가뜨린다.** KTO가 확인된 부재를 적는 가장 흔한 방식이 대체 수단을 같은 문장에 붙이는 것이기 때문이다.

```
장애인 화장실 없음. 인근 공중화장실 이용 가능.   →  unsupported 가 unknown 으로
엘리베이터는 없으나 1층만 관람 가능              →  같음
휠체어 대여 없음. 유아차는 대여 가능.            →  같음
```

셋 다 **확인된 부재**인데 「확인 필요」가 된다. 09번 §1이 이미 적어 둔 실패 — 「확인된 부재를 모름으로 읽으면 휠체어 이용자를 못 들어가는 건물로 보낸다」 — 가 그대로 돌아온다.

**같은 증상을 두 번 고쳤고, 두 번째가 반창고였다.** 부정 폴백은 문장 전체로 되돌렸고, 그 세 문장을 회귀 시험으로 박아 뒀다.

### 2.3 전수 재계산

저장된 403건을 전부 새 함수로 다시 풀었다. **바뀐 것은 정확히 1건**이다.

```
gungnamji  entrance_passage  unsupported → supported
```

이 한 건이 **말뭉치에 하나뿐이던 「다른 곳 권장」을 「주의 필요」로 바꾼다.** 「다른 곳 권장」 라벨이 도달 불가능해지지 않는지도 확인했다 — 부소산성이 시각장애 조건에서 `braille_block` 이용 불가로 여전히 나온다.

### 2.4 고치지 않은 것 하나

`CONDITIONAL`도 문장 전체를 읽는다. 그래서:

```
장애인 화장실 없음. 일부 주차구역 이용 가능   →  partial
```

뒤 절의 「일부」가 앞 절의 **확인된 부재**를 「일부 가능」으로 만든다. 부정 버그와 같은 뿌리다.

**노출량을 재어 봤다: 실제 문장 48개 중 0개**가 조건과 부정을 같이 갖고 있다. 그리고 `CONDITIONAL`은 「동절기 미운영」처럼 **문장 전체를 정당하게 한정하는** 경우가 있어서, 창을 좁히면 그쪽이 깨진다. 이번 회차 범위 밖으로 두고 여기에 적는다. 말뭉치가 13곳을 넘어 늘면 다시 재야 한다.

## 3. `대중교통`은 항목이 될 수 없다

### 3.1 왜 뺐나

KTO의 `publictransport`는 **길 안내 문장**이다.

```
논산역에서 902번 버스 이용 부여시외버스터미널 하차
대중교통 이용가능 : 사기소 정류장.저상버스 없음.
```

이 하나의 이름이 서로 다른 네 가지 질문을 뭉뚱그린다.

1. 정류장이 있는가
2. 버스로 도착할 수 있는가
3. 휠체어로 탈 수 있는가
4. 정류장에서 입구까지 갈 수 있는가

어떤 판정도 이 넷을 동시에 답하지 못한다. 실측도 같은 말을 한다 — 실제 값 8개를 `resolveStatus()`에 넣으면 **6개가 모름, 1개가 가능, 1개가 거꾸로**였다.

### 3.2 무엇으로 바꿨나

점수에서 빼고, **원문 그대로 「기타 안내」에 한국어 제목을 붙여** 싣는다. `KTO_ETC_FIELDS`를 `KTO_PROSE_FIELDS`로 바꾸고 `publictransport`를 넣었다.

```ts
export const KTO_PROSE_FIELDS = [
  'publictransport',
  'handicapetc',
  'blindhandicapetc',
  'hearinghandicapetc',
  'infantsfamilyetc',
] as const;
```

제목은 `messages/{ko,en}.json`의 `place.proseLabel.*`에 있다 — 대중교통 안내 / 지체장애 / 시각장애 / 청각장애 / 영유아 동반. 제목이 없으면 화면에 `detailWithTour2.publictransport`라는 필드 이름이 그대로 찍혔다. 제목 자체는 「누구 얘기인지」만 말한다 — 바로 위 절 제목이 이미 「기타 안내」이므로 항목마다 「그 밖의 안내」를 또 붙이면 같은 말을 두 번 한다.

### 3.3 이 필드들은 지금까지 **한 번도 수집된 적이 없다**

같은 자리를 파다가 나온 것이다. `KTO_ETC_FIELDS`는 `scripts/ingest.ts`에서 **import되어 `console.log` 한 줄에만 쓰이고 있었다.**

```
*etc fields (...) are carried on pois[].etcNotes, never scored
```

`etcNotes`를 만드는 코드는 없었다. 네 개의 `*etc` 필드는 `detailWithTour2`에 실려 오는데 그 호출은 `accessibility` 단계에 있고, `etcNotes`는 `pois` 단계에서 만들어진다. **단계가 어긋나 수집 코드 자체가 존재하지 않았고, 로그는 하고 있다고 말하고 있었다.** 거짓 로그 줄은 지웠다.

지금은 4곳에서 원문 6건이 실린다(0건 → 6건).

### 3.4 같은 응답을 두 번 읽지 않는다

`pois`와 `accessibility`가 각각 `detailWithTour2`를 부르면 **하나의 출처를 서로 다른 두 순간에 읽는다.** 화면은 문장과 판정을 나란히 하나의 주장으로 찍으므로, 둘이 다른 순간의 것이면 안 된다. 회차마다 하나의 응답을 공유한다.

```ts
const barrierFreeByContentId = new Map<string, Promise<KtoResult<DetailWithTour2Item>>>();
```

부수적으로 호출은 13 → 26이 아니라 13으로 유지된다(하루 1,000건 한도의 1.3%였다).

## 4. 빈칸 채우기

### 4.1 왜 새로 들어온 7곳만 비어 있었나

11회차에서 관광지를 6곳 → 13곳으로 늘렸다. 그때 늘어난 것은 **KTO가 주는 것**뿐이고, 손으로 확인한 것은 따라가지 않았다.

```
content/curated-facts.json   54건 — 전부 원래 6곳, 새 7곳은 0건
content/facilities.json      20건 — 같은 분포
content/routes/              gongsanseong.json, busosanseong.json 두 개뿐
```

원래 6곳이 두툼해 보였던 이유는 열린관광 웹사이트가 아니라 **지자체·박물관 홈페이지를 사람이 읽었기 때문**이다. 확인 삼아 열린관광 웹과 API를 나란히 긁어 봤다 — 고마나루 웹 2건 = API 2건, 백제문화단지 웹 8건 = API 8건. 웹이 더 주는 것은 거의 없다.

### 4.2 무엇을 넣었나

세 갈래 조사에서 돌아온 것 중 **출처 문장과 URL을 다시 열어 확인한 것만** 넣었다. 25건이다.

| 장소 | 넣은 항목 |
|---|---|
| 궁남지 | 9 |
| 부여왕릉원 | 6 |
| 백제문화단지 | 5 |
| 백제역사문화관 | 3 |
| 구드래조각공원 | 1 |
| 부여 나성 | 1 |
| 고마나루 | 0 |

안전시설 28건(응급실·자동심장충격기·화장실·주차·장애인콜택시)과 궁남지의 **열린관광지 지정**(2018, 문체부·한국관광공사)도 함께 넣었다. 부여군에서 지정된 곳은 궁남지 한 곳이다.

### 4.3 조사가 가져온 39건 중 14건을 버렸다

**가장 중요한 것부터.** 조사 한 갈래가 `korean.visitkorea.or.kr`(대한민국 구석구석)의 무장애 픽토그램을 브라우저로 렌더링해 값을 읽어 왔다. 렌더링한 값은 페이지에 실제로 그렇게 찍힌다 — 그런데 **그 「없음」은 주장이 아니라 기본값**이다.

증명은 KTO 자신의 API가 해 준다. 같은 장소를 `KorWithService2/detailWithTour2`로 직접 물었다.

```
구드래조각공원 (126699)
  braileblock = 점자블록 있음(주차장 진입로 및 화장실 입구 등 일부 점형블록 설치)
  구석구석 페이지가 같은 장소에 찍는 것 →  「시각장애인 편의서비스 없음」

고마나루 (2035859)
  돌아오는 필드가 route · restroom · braileblock  세 개뿐
  elevator · parking · wheelchair · stroller · lactationroom · exit  →  아예 없다
  구석구석 페이지는 그 여섯 개에 전부 「없음」을 찍는다
```

**값이 있는 필드 위에도 「없음」을 찍는다.** 이 페이지의 「없음」은 「확인된 부재」가 아니라 「이 자리에 줄 것이 없음」이다. 여기서 뽑은 9건을 전부 버리고 `unknown`으로 되돌렸다.

| 버린 것 | 되돌린 값 |
|---|---|
| 고마나루 — 출입구 `supported` | KTO에 `exit` 필드 자체가 없다. **없는 근거 위의 긍정 판정**이었다 |
| 고마나루 — 엘리베이터·주차·휠체어·유아차·수유실 `unsupported` | 같은 기본값 블록 |
| 구드래 — 휠체어·엘리베이터·유아차 `unsupported` | 같은 기본값 블록 |

이 프로젝트가 자기 코드에 적어 둔 규칙 그대로다 — **「출처가 없으면 모름이지, 없음이 아니다」**. 그래서 **고마나루는 이번 회차에 한 건도 넣지 못했다.** 확인율이 6/30 그대로다. 그게 지금 아는 전부다.

**참고로 이 함정은 `access.visitkorea.or.kr`(열린관광)에는 없다.** 그쪽은 서버가 값을 내려준다. 걸린 것은 `korean.visitkorea.or.kr` 쪽이다.

나머지 버린 5건:

- **구드래의 출입구·통로·점자 3건** — KTO의 무장애 기록(126699) `exit` 필드에 **부소산성 문장이 섞여 있다**(「낙화암과 고란사 접근은 돌계단과 단차로 접근 불가능함」). 두 조사가 독립적으로 같은 오염을 짚었다. 오염된 필드에서 뽑은 것은 전부 버렸다.
- **백제역사문화관의 수유실·휴게실** — 공식 가이드맵 이미지에는 둘 다 있다. 그런데 **같은 기관의 현재 배치도**(`sub050201.html`)는 1층 목록에 둘 다 적지 않는다. 한쪽이 낡았는데 어느 쪽인지 모른다.
- **백제문화단지의 점자블록** — 부여군 표의 「시각장애인 편의 서비스(**점자블록 등**) - 있음」은 **묶음이 있다**는 말이지 점자블록이 있다는 말이 아니다. 음성 안내일 수도 있다. (반대 방향인 부여왕릉원의 「묶음 없음 → 점자블록 없음」은 성립하므로 남겼다.)
- **구드래의 그늘** — 인용문은 「분수대 및 등나무 쉼터 **옆에** 붉은색 도서 부스를 설치」다. 쉼터는 위치를 가리키는 지명으로만 나온다. 더위를 피할 곳을 찾는 사람에게 무인도서관 이야기를 보여 주게 된다.
- **고마나루의 점자블록 「없음」** — 위와 같은 기본값 블록이고, KTO API는 오늘도 「점자블록 있음(화장실경사로)」을 준다.
- **궁남지의 유아용 보조의자** — 출처가 말하는 것은 「영유아거치대」다. 가장 가까운 항목이지만 같은 물건이 아니다.
- **궁남지의 점자블록 「없음」** — 부여군 점검표의 묶음 답변인데, 같은 군이 낸 열린관광지 조성내역이 촉지음성안내판과 점자 가이드북을 적고 있다.

**등급을 낮춘 것 하나.** 백제문화단지의 관람동선은 `supported`로 왔지만, 출처가 「전체 면적 3,300여㎡ **대부분**을 휠체어로 돌아볼 수 있어」라고 적고 「간간이 아쉬운 점이 보이기도」라고 덧붙인다. `partial`로 내리고 그 두 문장을 근거에 넣었다.

**같이 고친 것 넷.** 자동심장충격기 두 행이 **정림사지의 전화번호**(041-832-2721)를 달고 있었다 — 부여왕릉원 매표소는 041-830-2890이다. 부여나성의 오디오 가이드 출처 URL이 「NO PAGE」였다. 건양대 부여병원 행의 「365일 24시간 연중 무휴」와 공주의료원 행의 「지역응급의료기관」은 인용한 페이지에 없는 문장이었다. 부여왕릉원의 해설사 안내는 두 공식 출처가 10인/20인으로 어긋나는데 한쪽만 싣고 있었다 — 둘 다 적었다.

### 4.4 확인율이 올랐다 — 그런데 두 가지 이유로 올랐다

**이 둘을 섞어서 말하면 안 된다.**

```
커밋된 기준선            403칸 · 정보 없음 267 (66.3%)
대중교통을 항목에서 뺀 뒤   390칸 · 정보 없음 254 (65.1%)   ← 분모가 줄어든 것이다
확인 사실 25건을 넣은 뒤    390칸 · 정보 없음 230 (59.0%)   ← 이쪽이 실제로 늘어난 정보다
```

가운데 줄은 **정보가 늘어난 것이 아니다.** 항목이 31개에서 30개가 되면서 13칸이 분모에서 빠졌고, 그 13칸이 전부 「정보 없음」이었기 때문에 비율이 좋아 보이는 것뿐이다.

장소별로는 이렇다.

부여왕릉원        8 → 14
백제역사문화관     8 → 11
구드래조각공원    10 → 11
부여 나성         7 →  8
고마나루          6 →  6   ← 한 건도 못 넣었다. 이유는 §4.3

## 6. Codex와 갈라진 것

### 6.1 되돌린 고침 하나 — 반창고였다

§2에서 부정 폴백을 국소화했다. 코드 리뷰가 그것을 무너뜨렸고, 실측해 보니 맞았다.

```
장애인 화장실 없음. 인근 공중화장실 이용 가능.   →  unsupported 였던 것이 unknown
엘리베이터는 없으나 1층만 관람 가능              →  같음
휠체어 대여 없음. 유아차는 대여 가능.            →  같음
```

KTO가 **확인된 부재를 적는 가장 흔한 방식이 대체 수단을 같은 문장에 붙이는 것**이다. 국소화하면 그게 전부 「확인 필요」가 된다. 09번 §1이 이미 적어 둔 실패다.

그리고 국소화를 정당화하던 유일한 문장은 §3에서 `publictransport`를 항목에서 빼는 순간 이 함수에 **도달할 수 없게 됐다** — `buildAccessibility`는 `ktoField`가 있는 항목만 돌린다. 같은 증상을 두 번 고쳤고 두 번째가 반창고였다. 되돌렸다. 자세한 것은 `02_spec_corrections.md` W.

같은 리뷰가 `턱(?!없[이는])`도 깼다 — 「턱없어·턱없음·턱없다」가 남아 있어서 `편의시설이 턱없어 불편함`이 다시 `supported`였다. 어간 전체를 막았다.

### 6.2 「다른 곳 권장」 하나 — 판단이 필요하다

확인 사실을 넣자 **네 곳이 「주의」에서 「다른 곳 권장」으로 내려갔다.** 네 곳 모두 막은 항목이 **엘리베이터 하나**였다.

그중 둘(고마나루·구드래)은 §4.3에서 **근거가 가짜였음이 드러나** 사라졌다. 하나(궁남지)는 아래 방식으로 풀었다. **남은 것은 부여왕릉원 하나다.**

```
                     접근로      출입구      엘리베이터   화장실      →  판정
부여왕릉원           supported  supported  unsupported supported     대체추천
```

출처는 부여군이 내는 편의시설 표다 — 항목마다 있음/없음이 섞여 있는 **실제 서식**이고, 「장애인 전용 엘리베이터 - 없음」이라 적혀 있다. 직접 읽어 확인했다. **사실은 참이다.** 문제는 판정이다.

**그리고 이 구조는 유인을 거꾸로 만든다.** 어제까지 이 곳은 「아무것도 모른다」는 이유로 「주의」였다. 확인했더니 나빠졌다. 아무도 안 본 장소가 확인한 장소보다 위에 온다.

**궁남지는 고쳤다.** 한국관광공사가 이곳의 **관람동선 전체를 평평한 흙길**이라고 적고, 900m 무장애 동선 조성내역이 따로 있다. 안내하는 동선에 층을 오르내릴 구간이 없다는 것이 **출처에 적혀 있으므로** 엘리베이터를 필수 조건으로 보지 않는다(`absenceKind: not_applicable`, 부소산성이 이미 쓰는 방식 — `docs/guide/04_decisions.md` §1에서 결정된 것이다). 「설비가 없다」는 문장은 화면에 그대로 남는다.

**부여왕릉원에는 그 문장이 없다.** 관람동선은 `partial`이고(능 앞까지 올라가는 길은 경사가 급하다), 아트뮤지엄이라는 건물이 따로 있는데 층수를 적은 공식 페이지가 없다. 「엘리베이터가 없다」에서 「층을 오르내릴 구간이 없다」를 끌어내는 것은 이 프로젝트가 금지하는 추론이다.

#### 원인과 진짜 고침 — 결정이 필요한 것

- **원인.** 조건을 고르지 않은 방문자의 판정은 `GENERAL_VERDICT_CODES` 네 항목 위에서 내려진다: `access_route` `entrance_passage` `elevator` `restroom`. 이 중 셋은 **결과**(갈 수 있는가·들어갈 수 있는가·쓸 수 있는가)인데 `elevator`만 **수단**이다. 층이 없는 곳에서는 필요하지 않은 수단을, 어디서나 필요한 결과처럼 세고 있다.
- **진짜 고침.** 네 번째 자리를 `path_continuity`(관람동선 이용 가능성)로 바꾼다. 재어 본 결과, 「다른 곳 권장」이 0곳이 되고 대신 관람동선을 확인하지 않은 곳들이 「주의」로 내려온다 — 정직한 방향이다.
- **왜 이번에 안 했나.** 13곳 중 **8곳의 라벨이 움직인다.** 그리고 `06_suitability.md` §4.2의 **「파생 항목은 절대 critical이 될 수 없다」**를 뒤집어야 한다 — `path_continuity`는 `ktoField`가 없는 파생 항목이고 `assertPersonaMatrix()`가 이것을 막는다. 그 규칙이 있는 이유도 실측이다: 「이걸 critical로 두면 거의 모든 관광지가 모든 사용자에게 '정보없음'이 된다. 기존 스펙이 정확히 이 상태였다.」 지금은 13곳 중 7곳에 값이 있어서 그렇게 되지 않지만, **그 7곳은 사람이 손으로 적었기 때문에** 있는 것이다. 규칙 하나(필수 항목이 `partial`이면 라벨 상한 `주의`)도 새로 필요하고 골든 파일 30개를 다시 뜬다. **점수 모델 v7이고, 이번 회차 요청 범위 밖이다.**
- **지금 상태가 가리는 것과 가리지 않는 것.** 부여왕릉원 카드에는 라벨 옆에 **「엘리베이터 이용 불가」가 그대로 찍힌다.** 방문자는 왜 그 판정이 나왔는지 보고 스스로 판단할 수 있다. 가리는 것은 없다. 다만 **판정이 과할 수 있다** — 야외 고분군이고, 탐방로 자체는 휠체어로 갈 수 있다고 같은 출처가 적는다.

**결정할 것: v7로 가는가, 부여왕릉원에도 궁남지와 같은 예외를 쓰는가(그러려면 동선 근거를 더 찾아야 한다), 지금 상태로 두는가.**

### 6.3 Codex가 함께 짚은 것 둘 — 이번에 안 고쳤다

- **`pickAlternatives`가 「모르는 곳」을 「더 나은 곳」으로 추천할 수 있다.** 라벨 순위만으로 고르는데, `정보없음`은 접근성이 확인된 상태가 아니다. 역인센티브가 추천 단계에도 남아 있다. `src/domain/suitability.ts:238`.
- **부소산성 `elevator` 행의 논증이 약하다.** 「야외 산성이라 건물이 없고」는 「엘리베이터 없음」에서 나오지 않는다. 결론은 유지할 만하지만 근거 문장을 궁남지 행처럼 **동선 근거**로 다시 써야 한다. 이번에 궁남지만 그 형태로 썼다.

## 7. 확인하지 못한 것

- **부여 나성의 좌표가 성벽에서 떨어져 있다.** KTO가 주는 값(36.2583128, 126.9410769)은 OSM에 그려진 북나성 구간에서 1.6km 남쪽이다. 다만 **KTO 자신의 주소(부여읍 동문로142번길 100-11)를 지오코딩하면 429m 거리**로, 염창리 쪽 동나성 구간의 등록 지점이다. 나성은 6km짜리 선형 토성이라 「한 점」이 애초에 없다. KTO의 등록 지점을 그대로 둔다. 이 점 기준으로 2km 안에 자동심장충격기가 없어서 가장 가까운 것을 2.157km로 적었고, 그 사실을 시설 설명에 그대로 썼다.
- **부여왕릉원 아트뮤지엄의 층수** — 부여군·국가유산 어느 페이지도 적지 않는다. §6의 판단이 여기에 걸린다.
- **궁남지와 서동공원이 한 곳인가** — 부여군 스스로 「궁남지(서동공원)」으로 쓰고, 세 등록 기록이 같은 주소(궁남로 52)와 같은 전화(041-830-2880)를 공유한다. 한 곳으로 본다. 다만 부여군의 궁남지사계 페이지는 「서동공원」이라는 말을 한 번도 쓰지 않고, 두 cotId를 잇는 기계 판독 가능한 링크는 없다.
- **운영시간이 두 공식 출처에서 어긋난다.** 충남관광은 궁남지·구드래를 09:00~18:00이라 하고, 부여군은 둘 다 상시 개방이라 한다. 어느 쪽도 항목으로 싣지 않았다.
- **백제문화단지 장애인 주차면수** — 열린관광 기사는 16면, 같은 주소의 백제역사문화관 기록은 36면. 둘 다 KTO다. 단지에 16면을 쓰고 문화관에는 주차 행을 넣지 않았으며, 어긋남을 출처란에 적었다.
