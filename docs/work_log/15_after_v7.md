# 15 — v7이 남긴 뒷일, 그리고 「오염」이라고 잘못 부른 것

14번은 판정의 네 번째 자리를 `elevator`에서 `path_continuity`로 바꿨다. **항목 하나를 critical로 올리면 그 항목을 채우던 모든 경로가 갑자기 판정을 좌우하게 된다.** 이 회차는 그래서 생긴 것들을 닫고, 남아 있던 열린 항목들을 코드와 대조했다.

여섯 덩어리다.

1. **경로 파일이 「확인됨」을 주장할 수 있었다** — v7이 만든 구멍이고, 노출은 0이었다.
2. **조건이 남의 절(節)을 한정하고 있었다** — 13번 §2.4에 적어 두고 안 고쳤던 것.
3. **백제역사문화관 지도 핀이 385m 틀렸다.**
4. **정보안내 축이 빠진 항목을 말하게 했다** — 4번 회차부터 열려 있던 항목.
5. **부여 나성은 「오염」이 아니었다** — 내가 두 가지 다른 문제에 같은 말을 썼다.
6. **문서가 코드보다 낡아 있던 곳 셋.**

---

## 1. 경로 파일이 「확인됨」을 주장할 수 있었다

`scripts/ingest.ts`가 `content/routes/*.json`에서 관람 동선을 이렇게 뽑고 있었다.

```ts
status: hazardSteps === 0 ? 'supported' : 'partial'
```

**항목이 supporting일 때는 무해했다.** v7이 critical로 올리는 순간, **깨끗한 경로 파일 하나가 혼자 「방문 가능」을 만들 수 있게 됐다.**

경로 파일은 **우리가 답사한 한 갈래**를 적은 것이다. 공산성 것은 5단계이고 금서루에서 공북루 방향을 따라간다 — 네 문 중 하나다. 위험 표시가 0이라는 것은 **그 갈래에 걸림돌이 없었다**는 뜻이지, 방문자가 가야 할 모든 지점에 닿는다는 확인이 아니다.

`partial`로 상한을 걸었다.

```ts
// Never 'supported' from route data alone, however clean the walk is.
status: 'partial',
detail: `안내 경로 ${route.steps.length}단계 중 주의 표시 ${hazardSteps}개. 이 경로 밖의 구간은 확인하지 않았다.`,
```

**오늘 바뀐 행은 0개다.** 경로 파일이 있는 두 곳(공산성·부소산성)은 둘 다 확인 사실이 이미 덮고 있고, 둘 다 `partial`이다. 막은 것은 앞으로 경로 파일을 하나 더 넣는 날이다.

## 2. 조건이 남의 절을 한정하고 있었다

13번 §2.4에 적어 두고 「노출 0이라 이번 회차 범위 밖」으로 남겼던 것이다. v7이 이 함수의 출력에 라벨을 걸었으므로 더 미룰 이유가 없어졌다.

### 2.1 증상

```
장애인 화장실 없음. 일부 주차구역 이용 가능      →  partial
```

`restroom` 칸에서 **화장실이 없다고 확인된 문장**이 「일부 가능」으로 나간다. 뒤 절의 `일부`가 앞 절의 부재를 무르게 만든다.

### 2.2 조건은 한 종류가 아니다

좁히기만 하면 될 줄 알았는데 아니었다. **조건은 한정하는 범위가 두 가지다.**

| | 예 | 무엇을 한정하나 |
|---|---|---|
| 문장 전체 | `동절기` `우천 시` `평일만` | 문장이 무슨 말을 하든 그것에 걸린다 |
| 절 하나 | `일부` `제한` `예약 필요` `어려움` `협의` `동반 필요` | 바로 옆에 붙은 것에만 걸린다 |

**앞의 것을 좁히면 안 된다.** 「동절기 미운영」을 절 단위로 읽으면 `미운영`만 남아 **영구 부재로 발행된다.** 겨울에 닫는 곳이 아예 없는 곳이 된다.

그래서 집합을 쪼갰다 — `CONDITIONAL_SENTENCE`와 `CONDITIONAL_LOCAL`.

### 2.3 글자 수로 자르면 안 된다 — 절로 잘라야 한다

처음엔 앞뒤 12자 창으로 국소화했다. 그러자 이게 통과했다.

```
계단 있음. 일부 주차구역 이용 가능      →  여전히 partial
```

`일부`가 `계단`에서 **열두 글자 안에** 있다. 그런데 그 사이에 **마침표가 있다.** 문장 부호 하나 건너편은 다른 시설 이야기다. 그래서 창이 아니라 **절 경계**(`[.。;\n]`)로 자른다.

```ts
const CLAUSE_BOUNDARY = /[.。;\n]/;
```

### 2.4 그런데 좁히기만 했더니 멀쩡한 것 다섯이 깨졌다

```
일부 구간 이용 불가                                    기대 partial → unsupported ✗
사전 문의 후 이용                                       기대 partial → unknown     ✗
예약 필요                                              기대 partial → unknown     ✗
경사로로 이루어져 있으나 흙구간 및 일부구간 접근 어려움      기대 partial → unknown     ✗
경사가 심한 돌길이라 휠체어와 유모차 진입 어려움            기대 partial → unknown     ✗
```

**공통점: 조건이 붙을 대상이 문장 안에 없다.** 「예약 필요」는 그냥 예약이 필요하다는 말이고, 그 자체로 문장 전체를 한정한다. 국소화가 이것들을 갈 곳 없게 만들었다.

그래서 순서도 같이 바꿨다.

```
1. 계절·날씨 조건이 있으면            → partial   (문장 전체)
2. 부정이 있으면
     같은 절에 조건이 있으면          → partial
     없으면                          → unsupported
3. 조건만 있고 부정이 없으면          → partial   ← 붙일 대상이 없는 조건이 여기서 답한다
4. 극성을 못 읽은 장벽이 있으면        → unknown
5. 부정되지 않은 시설 어간이 있으면    → supported
```

**3이 4보다 앞에 와야 한다.** 「경사가 심한 돌길이라 … 진입 어려움」에서 `돌길`은 극성을 못 읽는 장벽인데, **`어려움`이 바로 그 장벽을 설명하고 있는 말**이기 때문이다.

### 2.5 실측

회귀 8건을 넣었다. **문장이 있는 KTO 칸 47개는 판정이 하나도 안 움직였다.**

## 3. 백제역사문화관 지도 핀이 385m 틀렸다

`content/pois.json`에서 이 관광지의 좌표가 **백제문화단지와 1m도 다르지 않았다.**

```
baekje-cultural-land    36.3075705876, 126.9084945941
baekje-history-museum   36.3075713532, 126.9084947394   ← 0m
```

**복사 실수가 아니었다.** `KorService2/detailCommon2`가 `contentId 130875`에 정확히 그 값을 준다. KTO가 주소 「백제문로 455」를 지오코딩한 것이고, 그 주소는 **단지 전체의 주소**다.

실제 건물은 OpenStreetMap `relation/5486569`(이름 백제역사문화관, `building=yes`, `tourism=museum`)이고 **385m 떨어져 있다.** Nominatim으로 그 점을 역조회하면 「백제역사문화관, 455, 백제문로」가 돌아온다.

**왜 중요한가.** 상세 화면이 안전시설 거리를 이렇게 계산한다.

```ts
distanceMeters(poi.coord, facility.coord)
```

그래서 **지도 핀과 응급실·자동심장충격기·화장실 거리가 전부 385m씩 어긋나 있었다.** 좌표를 건물로 옮겼고, `pois.json`의 `source` 칸에 KTO 값을 쓰지 않은 이유를 적었다.

## 4. 정보안내 축이 빠진 항목을 말한다

`04_open_items.md` §3.3이 4번 회차부터 열려 있던 것이다.

`audio_guide`(오디오 가이드)가 `sign_guide`(수어 안내)와 `video_caption`(자막 영상) **사이에** 놓여 있다. 그 묶음은 접근성 기능 목록으로 읽히고, **음성 해설이 포함된 것처럼 읽힌다.** 아니다 — 오디오 가이드는 전시 해설이지, 눈앞에 무엇이 있는지 말해 주는 기능이 아니다.

**카탈로그에 아예 없는 항목은 `unknown`보다 나쁘다.** 「모른다」는 화면에 적히지만, 없는 항목은 **물어본 적조차 없다는 사실이 아무 데도 안 적힌다.**

정보안내 축 제목 바로 아래에 한 줄을 넣었다.

> 음성 해설(무엇이 보이는지 말로 설명해 주는 것)은 아래 목록에 없습니다. 오디오 가이드는 전시 해설이라 같은 것이 아니고, 이 서비스는 아직 음성 해설을 조사하지 않았습니다.

항목을 늘리는 (a)안은 안 했다 — 13곳의 값을 채울 출처가 없다.

## 5. 부여 나성은 「오염」이 아니었다

내가 **서로 다른 두 문제에 같은 말을 썼다.** 바로잡는다.

### 5.1 KTO가 나성에 주는 것 전부

`contentId 250259`, 네 줄이 전부다.

```
route        출입구까지 평지로 되어 있음_무장애 편의시설
wheelchair   대여 가능(1대 / 왕릉원 매표소)
restroom     장애인 화장실 있음
braileblock  점자블록 있음(고분군 화장실)_시각장애인 편의시설
```

### 5.2 왜 남의 이름이 아닌가

**부여왕릉원이 곧 능산리고분군이다** — 2021-09-17 관보 고시로 이름이 바뀌었고, `pois.json`에 이미 적혀 있다. 「고분군 화장실」은 다른 관광지가 아니라 왕릉원의 화장실이다.

그리고 **부여군 자신이 나성을 왕릉원으로 안내한다.** 부여군 세계유산 나성 페이지를 직접 열어 확인했다.

```
위치      충남 부여군 부여읍 능산리 산15-1
이용문의  부여왕릉원 매표소 : 041-830-2890
운영기간  연중무휴
```

**나성에는 자기 매표소가 없다.** 「휠체어는 왕릉원 매표소에서 빌린다」는 틀린 문장이 아니라 **정확한 안내**다.

### 5.3 구드래와 나란히 놓으면 차이가 분명하다

```
구드래조각공원   기록에 「낙화암과 고란사」
                 → 부소산성에 있다. 2km 떨어져 있고 매표소도 입구도 다르다
                 → 진짜 오염

부여 나성        기록에 「왕릉원 매표소」, 「고분군 화장실」
                 → 나성을 보려면 그 매표소로 들어간다. 부여군이 그렇게 안내한다
                 → 오염이 아니라 시설 공유
```

### 5.4 대신 진짜 문제가 따로 있다 — 좌표다

```
우리 나성 핀        36.2583, 126.9411   ← KTO 좌표, 염창리 쪽 동나성 구간
부여왕릉원 매표소    36.2771, 126.9437
거리                2,108 m
```

**핀과 시설이 서로 다른 곳을 가리킨다.** 방문자가 지도를 보고 찍힌 곳으로 가면, 우리가 휠체어를 빌릴 수 있다고 적은 매표소에서 2.1km 떨어진 곳에 도착한다.

KTO 자신이 갈라져 있다 — 좌표는 염창리, 시설 문장은 왕릉원. 부여군은 위치를 능산리라고 한다. **세 값 중 둘이 왕릉원 쪽이다.**

작은 것 하나 더: **휠체어 1대가 두 곳에 발행된다**(나성 「1대/왕릉원 매표소」, 왕릉원 「1대, 매표소」). 같은 한 대다.

### 5.5 결정 — A, 그대로 둔다

소유자 판단이다. 근거는 이렇다.

- 네 항목 다 **참**이고, 화면에 「왕릉원 매표소」가 원문 그대로 찍혀서 방문자가 어디인지 읽을 수 있다.
- 손으로 「정보 없음」으로 덮는 것(B안)은 **참이고 쓸모 있는 정보를 버린다.** 어긋난 것은 문장이 아니라 좌표다. 증상을 지우고 원인을 남기는 쪽이다.
- 핀을 능산리 구간으로 옮기는 것(C안)이 원인을 고치는 쪽인데, **지금은 못 한다** — 「능산리 산15-1」은 산 지번이라 지오코딩이 안 된다(시도함, 결과 0건). 이 프로젝트는 좌표를 **독립된 두 조회가 일치할 때만** 쓴다.

**남은 항목으로 올린다:** 능산리 나성 구간의 검증 가능한 좌표를 구하면 C로 닫는다. 국가유산청 도면이나 OSM의 해당 성벽 구간이 후보다.

## 6. 문서가 코드보다 낡아 있던 곳 셋

열린 항목을 코드와 대조하다 나온 것이다. **셋 다 코드가 아니라 문서를 고쳤다.**

- **`04_open_items.md` §3.2** — 「Chrome은 `@page` 마진 박스를 구현하지 않아 페이지 번호를 인쇄할 수 없다」. **Chromium 131부터 된다.** 12번에서 이미 `@bottom-right { content: counter(page) " / " counter(pages) }`로 찍고 있다.
- **§3.4** — 인쇄되는 여행 기록이 `/en`에서도 한국어라던 것. `buildDiaryDocument(…, locale)`이 로케일을 받는다. 고쳐져 있다.
- **§4의 「남은 판단 하나」** — 관리자 신고 목록에 페이지 넘기기가 없다던 것. `PAGE_SIZE = 50`, 이전/다음 링크, **「신고 안 된 것만」 보기**, 필터 전체 기준 건수(`scopedCount`)까지 들어 있다.

같은 표의 **결정 1(부소산성 엘리베이터)**도 아직 ✅였는데, 14번에서 철회한 것이라 사유를 달았다.

## 7. 배포하다 잡은 것 — 로컬 ingest는 프로덕션 캐시를 못 비운다

`pnpm ingest`를 로컬에서 돌리면 마지막에 이 경고가 나온다.

```
warn  cache invalidation failed for localhost:3000; its pages refresh on their own within the hour
```

`.env.local`의 `NEXT_PUBLIC_SITE_URL`이 `localhost:3000`이라서 `revalidate()`가 로컬을 친다. **데이터베이스는 갱신되는데 프로덕션 캐시는 그대로다.**

실제로 겪었다 — 상세 화면은 배포로 새로 그려져서 맞는데 **목록 카드만 낡은 판정을 보여줬다.** 국립공주박물관이 「확인 필요: 관람 동선」으로 남아 있었다.

```
NEXT_PUBLIC_SITE_URL=https://www.modubaekje.com pnpm ingest
→ ok       cache invalidated on www.modubaekje.com
```

**야간 GitHub Actions는 해당 없다** — 시크릿에 실제 주소가 들어 있다. 사람이 로컬에서 실 ingest를 돌릴 때만 생긴다.
