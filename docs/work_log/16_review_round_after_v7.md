# 16 — 세 갈래 검토와 코덱스 페어가 찾은 것

15번이 v7의 뒷일을 닫았다. 이 회차는 **이미 배포된 것을 전부 다시 의심한 회차**다. 코드 검토 3갈래(도메인·수집/API·화면), 브라우저로 15개 화면 전수 조회(1280px·390px), 한국어·영어 문안 검토 2갈래, 그리고 **코덱스와의 검토 페어**를 붙였다.

**가장 중요한 결과 한 줄:** 한국어 문장을 판정으로 바꾸는 `resolveStatus()`가 **양쪽 방향으로 다 틀리고 있었다.** 계단이 있다고 적힌 문장이 「이용 가능」으로, 경사가 완만하다고 적힌 문장이 「이용 불가」로 나갔다.

---

## 1. 판정기(resolveStatus)가 틀린 방향 두 가지

### 1.1 남의 부정을 장벽에 가져다 붙였다

```
계단 있고 난간 없음      →  supported   (access_route, critical)
계단 옆 난간 없음        →  supported
계단에 손잡이 없음       →  supported
```

`계단` 뒤 여덟 글자 창 안에 `없음`이 있으면 계단의 부재로 읽었다. 그 `없음`은 **난간**의 것이다. 창은 다음 명사를 넘어가면 안 된다.

글자 창을 **토큰 주사**로 바꿨다. 조사는 넘어가고, 표지를 단 첫 토큰이 답하고, 표지 없는 내용어에서 멈춘다.

### 1.2 `만` 한 글자가 「완만」 안에서 터졌다

```
경사가 완만함                    →  unsupported → 대체추천, 점수 상한 49
경사가 완만하여 휠체어 이동 가능    →  unsupported
단차 5cm 미만                    →  unsupported
```

`PRESENT_NEARBY`에 들어 있던 맨 `만`이 **완만**·**미만** 안쪽에 걸렸다. 배타 조사 `만`은 토큰 머리에만 온다 — `/^(으로|로)?만/`으로 고정했다.

### 1.3 「확인 필요」가 확인된 부재를 무르게 했다

```
엘리베이터 없음. 리프트 설치 여부 확인 필요   →  unknown
장애인 화장실 없음(위치 확인 필요)            →  unknown
```

`NEEDS_CHECKING`이 모든 규칙 위에 있었다. 이 파일의 주석과 회귀 테스트 이름(`a facility negation is never softened to unknown`)이 **금지한다고 적어 둔 바로 그 동작**이다. 부정 규칙 **아래**, 긍정 규칙 **위**로 옮겼다.

### 1.4 코덱스가 찾은 것 — 내가 고치면서 새로 만든 것 여섯

고쳐 놓고 페어에 넣었더니 여섯 개가 돌아왔다. 전부 실행해 확인했다.

| 문장 | 내가 만든 답 | 맞는 답 | 원인 |
|---|---|---|---|
| `나무계단으로만 접근 가능` | supported | unsupported | **나무**의 `무`를 부정 접두사로 읽음 |
| `단차 없음(휠체어진입불가)` | supported | unsupported | 괄호 안을 토큰째 삼켜서 지움 |
| `단차가 아예 없음` | unsupported | supported | `아예`가 부사 목록에 없어 주사가 멈춤 |
| `계단이 있는지 확인 필요` | unsupported | unknown | `있는지`를 단정으로 읽음 |
| `휠체어 대여 불가 여부 확인 필요` | unsupported | unknown | 질문을 답으로 읽음 |
| `무단차가 아닌 출입구` | supported | unsupported | `아닌`에 `아니`가 **없다** — 음절이 `닌`이다 |

마지막 것이 특히 중요하다. `NEGATION`에 `아니`를 넣어도 `아닌`·`아님`은 안 걸린다. 한국어는 음절을 통째로 쓰므로 `아[니닌님녀]`여야 한다.

같은 페어가 원래부터 틀려 있던 것도 둘 찾았다.

```
계단 손잡이없음   →  supported    (표지가 토큰 한가운데 있었다)
계단 옆 문 없음   →  supported    (한 글자라고 다 조사는 아니다 — 문은 명사다)
계단 많지 않음   →  supported    (많지 않다는 없다가 아니다)
```

조사와 부사를 **닫힌 집합**으로 바꿨다. 길이로는 `옆`과 `이`를, `거의`와 `난간`을 구분할 수 없다.

### 1.5 「거의 없음」은 「없음」이 아니다

```
단차 별로 없음        →  partial   (was supported)
단차가 거의 없는 편입니다 →  partial
```

거의 없다는 것은 없다는 것이 아니고, 그 차이가 문턱을 넘는 바퀴와 못 넘는 바퀴다. 완충 부사(`거의`·`별로`·`다소`…)를 지나온 부재는 「일부 가능」에서 멈춘다. `전혀`·`아예`는 절대어라 그대로 「이용 가능」이다.

### 1.6 실측

- 회귀 테스트 78 → **111건**. 위의 모든 문장이 들어 있다.
- 돌연변이 검사: 상수 하나씩 되돌리면 전부 빨간불이 된다.
- **실제 KTO 문장 41개 중 판정이 움직인 것은 1개**, 구드래조각공원 `entrance_passage`뿐이다. 그 한 줄은 KTO 기록이 부소산성 문장으로 채워져 있는 것이라([15번 §5](./15_after_v7.md)) 손으로 「정보 없음」 덮고 이유를 적었다.

## 2. 수집이 자기 침묵을 발행할 수 있었던 경로 셋

### 2.1 재시도를 다 쓴 `resultCode 05`가 「접촉함」으로 기록됐다

`RETRYABLE_RESULT_CODES`(02·04·05·21·99)를 세 번 받고 포기하면 `gatewayReached`가 올라갔다. 그러면 `requireGatewayWasReachable()`이 조용하고, 단계는 **빈 응답으로 만든 스냅샷을 좋은 것 위에 발행한다.** 바로 위 주석이 「503을 세 번 받은 게이트웨이는 데이터에 대해 아무 말도 안 한 것」이라고 적어 놓고 있었다.

재시도를 다 쓴 실패는 이제 전부 unreachable이다.

### 2.2 200으로 돌아온 읽을 수 없는 본문도 「접촉함」이었다 *(코덱스)*

게이트웨이 자체의 HTML 안내 페이지가 200으로 오면 `transport/xml-body`가 되고, 200은 재시도 대상이 아니라 그 자리에서 「접촉」으로 기록됐다. **transport 계열 코드는 답이 아니다** — 본문을 못 읽은 것이다. 03(행 없음)이나 30(키 오류)은 답이고, 그 둘은 그대로 접촉이다.

### 2.3 뒤 페이지가 totalCount를 0으로 지웠다 *(코덱스)*

1페이지가 `totalCount: 500`, 2페이지가 `resultCode 03`(빈 본문, totalCount 0)이면 마지막 값이 덮어써서 짧은 순회가 **완전한 것으로 보고됐다.** 본 것 중 최댓값을 쓴다.

같은 자리에 있던 것 하나 더: `truncated`가 페이지 상한으로 끝났을 때만 켜졌다. 빈 페이지로 끝나 totalCount에 못 미친 순회는 「다 읽었다」고 보고했다 — `listBarrierFreeSync`가 「목록에 없음」을 「미등록」으로 읽어도 되는지 판단하는 그 깃발이다.

### 2.4 Odii 테마 목록이 잘려도 발행했다 *(코덱스)*

경고 한 줄 찍고 **짧아진 스냅샷을 온전한 것 위에 발행**했다. 열거가 곧 탐색 수단이므로, 잘린 목록은 존재하는 이야기를 떨어뜨린다. 이제 중단한다.

### 2.5 파생 항목이 오늘 날짜를 찍었다

`push()`가 값이 있으면 무조건 `seoulToday()`를 박았다. 6월에 걸은 경로가 매일 밤 「오늘 확인」으로 다시 발행되고 `computeFreshness`가 영원히 만점 구간을 준다. 자기 `checkedAt`이 있는 것은 그것을 쓴다 — 경로, 휴게 시설(집합이므로 가장 오래된 것), 그리고 **혼잡도·기상 특보·기상 예보**(코덱스가 짚었다: `--only=accessibility`로 저장된 context에 대해 돌리면 옛 관측이 오늘 것이 된다).

### 2.6 `detailInfo2` 실패가 로그에도 안 남았다

`primaryCalls`에 없어서 `abortOnBadAnswer`도 `warn`도 지나쳤다. 일일 할당량 코드(22)를 받아도 수집이 계속됐고, 장애인 편의시설 문단이 조용히 사라졌다.

## 3. 「없다」와 「못 읽었다」가 같은 빈 배열이었다

`orEmpty()`가 `kind: 'missing'`과 `kind: 'error'`를 똑같이 `[]`로 바꿨다. 화면은 그 배열을 **존재 여부**에 쓴다 — 경로 행이 없으면 「경로 안내 보기」 버튼이 없고, 도슨트 행이 없으면 오디오가 없다. 즉 Postgres 오류 하나가 **「이 관광지는 경로 안내가 없습니다」를 발행**했다. 이 모듈 주석이 스스로 첫 번째 책임이라고 적어 둔 구분이다.

`optionalRows()`가 `{ rows, unavailable }`을 돌려주고, 네 화면이 「이 화면의 일부를 불러오지 못했습니다」를 띄운다. 내부 메시지(Postgres 오류·Zod 이슈)는 이제 한 곳에서 서버 로그로 나간다 — 전에는 어디에도 안 남았다.

코덱스가 그중 세 곳이 깃발을 다시 버리고 있다고 짚었다. 첫 화면(관광지 읽기 실패 시 「대상 관광지 0」), 인쇄 화면, 상세 화면의 context. 첫 두 곳과 context를 마저 붙였다.

## 4. 화면과 코드

- **중복 landmark** — 갭 리포트에서 표의 스크롤 영역이 같은 이름의 section 안에 겹쳐 있었고, 오디오 해설 화면은 **「대본」이라는 이름의 landmark를 이야기 수만큼** 발행했다. axe `landmark-unique` 위반. 스크롤 영역은 표 캡션 이름을 쓰고, 대본은 landmark를 그만뒀다.
  - **이 규칙은 e2e 검사에 없었다**(코덱스). axe의 `best-practice` 태그라 WCAG 태그 목록이 닿지 않는다. 2차 주사를 붙였고, 되돌려서 빨간불이 되는 것을 확인했다.
- **비활성 버튼이 포커스를 떨어뜨렸다** — 경로 「다음」을 마지막 단계에서 누르면 그 버튼이 `disabled`가 되어 포커스가 `<body>`로 간다. `aria-disabled` + 핸들러 상한.
- **`.btn`에 비활성 스타일이 아예 없었다** — 눌러도 아무 일이 없는데 살아 있는 버튼과 픽셀 단위로 같았다.
- **제보 신고에 눈에 보이는 결과가 없었다** — 라이브 리전에만 알렸다. 버튼이 말을 바꾸도록 했다(코덱스: span으로 바꾸면 포커스가 또 떨어진다).
- **기기 음성이 바뀐 대본을 계속 읽었다** — 「쉬운 글」로 바꿔도 `DocentPlayer`가 언마운트되지 않아 정리가 안 돌았다.
- **「쉬운 글」이 조용히 원문으로 떨어졌다** — 스위치가 모든 이야기에 쉬운 글이 있다고 주장했다. 없는 이야기는 그렇게 말한다.
- **빈 목록에서 지도 중심이 NaN** — `Math.min(...[])`은 `Infinity`다.
- **지도가 조건 바꿀 때마다 시야를 되돌렸다** — 핀 배열이 점수 순이라 같은 좌표가 다시 정렬되면 서명이 바뀌었다(코덱스). 좌표 집합을 정렬해 비교한다.
- **표 오른쪽에 흰 띠** — `.scroll-x`의 가장자리 그림자 마스크가 `--color-paper` 고정이라 surface 위 카드에서 표를 잘라 보이게 했다. 마스크가 바탕을 따라간다.
- `seoulToday()`를 SSR되는 클라이언트 컴포넌트 렌더 중에 호출(자정을 걸치면 hydration 불일치), 관리자 `?page=` 무제한, 이미지 프록시가 선언된 길이만 믿고 본문을 통째로 버퍼링.

## 5. 문안 — 같은 것을 여러 이름으로 부르고 있었다

### 5.1 `unknown` 하나에 이름이 넷이었다

상세 화면 한 장에 「⚠ 확인 필요: 관람 동선」과 「관람 동선 ? 정보 없음」이 같이 있었다. 목록은 「16개 미확인」, 갭 리포트는 「상태 미확인」.

**화면에 보이는 상태어는 「정보 없음」 하나**로 고정하고, 행동은 뒤에 붙인다 — 「정보 없음, 방문 전 확인 필요」.

### 5.2 영어가 구분을 무너뜨리고 있었다

`unsupported`의 영어가 **"Not available"**이었다. 영어에서 그 말은 **자료가 없다**는 뜻이다. 즉 「확인했고 이용할 수 없다」를 뜻해야 하는 유일한 라벨이, 그것과 절대 헷갈리면 안 되는 쪽으로 읽혔다. 바로 윗줄 `notApplicable`은 "Not applicable"이고 둘 다 N/A로 줄어든다. `gap.ts`의 같은 표에 달린 주석이 **이 충돌을 그대로 적어 놓고** 그대로 두고 있었다.

`Can be used / Partly usable / Cannot be used / No information`.

CSV와 화면이 한 목록이라는 것을 비교하는 검사를 붙였고, **오늘 데이터에서 바로 빨간불이 났다** — 한국어 CSV가 `supported`를 「확인됨」이라 쓰고 있었다(나머지 셋은 이용 축인데 이것만 확인 축).

### 5.3 「condition」이 세 가지를 가리켰다

방문자의 조건(`Your conditions`), `partial` 상태(`Conditions apply`), 그리고 제보 화면(`Report a condition` — 영어로는 「질병을 신고하라」로 읽힌다). `suitability.ts`가 `context` 축 이름을 "Situation"으로 바꾸며 이미 이 충돌을 한 번 피했는데, 한 곳에만 적용돼 있었다.

### 5.4 화면에 없는 것을 가리켰다

- `home.howTo[2]`가 「이 점수가 나온 계산」을 펼치라고 했다. 실제 버튼은 **「이 판정이 나온 계산 보기」**다.
- `place.reportsDisclaimer`가 「**위** 판정에 들어간 항목」, `place.safetyNote`가 「**아래** 거리는」이라 했다. 둘 다 반대다.
- 인증 기록이 「**6곳** 중 유일」이라 했다. 13곳이고, 열린관광지는 둘이다.
- credits가 「24개 항목」이라 했다. 23개다.
- credits가 화면 문구를 **의역해서** 인용했다. 대조하라고 있는 페이지다.

### 5.5 조사가 깨지고 있었다

```
휠체어 이용에게 권하는 이동 시간은 25분까지이니
낯선 곳이 힘든 아이와 함께에게 권하는 이동 시간은 15분까지이니
```

페르소나 라벨이 문장 안에 그대로 꽂혔다. 라벨을 `choiceKo`의 명사형으로 맞추고(`시각장애` → `눈이 잘 안 보임`), 문장은 「」로 감쌌다. 첫 화면이 장애 범주를 안 부르려고 애쓰는데 그다음 화면부터 계속 「시각장애 기준」이라 부르던 것도 이걸로 같이 닫혔다.

### 5.6 1인칭과 3인칭이 어긋났다

「누구와 **함께** 가시나요?」 아래에 「휠체어를 이용해요」가 있었다. 이 서비스의 1순위 독자가 자기 자리를 못 찾는다. 「어떤 조건으로 보시겠어요?」 / 「본인 또는 함께 가는 사람의 조건」.

### 5.7 「도움이 가장 많이 필요한 분 기준」은 계산과 다르다

`Math.min(...fits)`는 **이곳이 가장 맞지 않는 조건**을 고른다. 사람의 속성이 아니라 장소와 조건의 짝에 대한 값이다.

### 5.8 영어 상세 화면에 설명이 한 글자도 없었다

13곳 전부 `i18n.en.overview`가 `null`이다. KTO 영문 서비스가 행은 주고 본문은 안 준다. 그런데 화면의 대체 경로가 **행 단위**(`poi.i18n[locale] ?? poi.i18n.ko`)라, 영어 행이 객체로 존재하는 한 절대 안 넘어갔다. 코드 주석은 넘어간다고 적혀 있었다. 필드 단위로 바꾸고, 한국어로 넘어갈 때는 `lang="ko"`와 함께 그렇다고 적는다.

### 5.9 기타

`기상 특보 ✓ 양호`(특보가 양호할 수는 없다) → `이상 없음`. 마크다운 `**`가 화면에 리터럴로 찍히던 곳. 백제문화단지 면적 3,300㎡(1000배 차이로 보이고 출처로 검증 못 함 — 숫자를 뺐다). 인용 안 원문 오타 처리 방식이 항목마다 달랐던 것. 「+12」처럼 단위 없는 꼬리.

### 5.10 근거가 안 되는 근거로 「이용 가능」을 주던 곳

구드래조각공원 `rest_seating`이 2018년 군보 산문 — 「공원에 마련된 의자에 한참 앉아…」 — 하나로 「이용 가능」이었다. 의자가 있다는 말은 되지만 높이·등받이·휠체어가 설 자리·거기까지 가는 길은 아무 말도 안 한다. 같은 항목의 궁남지는 시설 문장을 쓴다. 「정보 없음」으로 내리고 이유를 적었다.

## 6. 검사 자체가 못 잡던 것

- **i18n 검사가 네임스페이스를 안 봤다.** `common.andMore`가 양쪽 파일에 다 있으면 키 집합 검사는 통과하고, 컴포넌트가 `places.andMore`로 읽으면 화면에 키 이름이 찍힌다. 브라우저 순회에서 `MISSING_MESSAGE`로 잡혔다 — **검사가 아니라 브라우저가 잡았다.** 파일마다 번역기 변수와 네임스페이스를 읽어 모든 리터럴 키를 대조하는 검사를 붙였다(코덱스 지적대로 한 파일에 같은 이름의 번역기가 둘일 수 있으므로 집합으로 모은다).
- **CSV와 화면의 상태어 대조**가 없었다. 붙이자마자 빨간불(§5.2).
- **`landmark-unique`가 e2e 태그 밖**이었다(§4).
- **골든 파일의 critical 표**가 손으로 베낀 사본인데 아무도 대조하지 않았다. `MATRIX` 한 줄을 고치면 coverage 케이스가 조용히 다른 것을 재게 된다.
- **`NEARBY_WINDOW`가 어느 값이어도 초록불**이었다. 상수를 없앴다 — 토큰 규칙이 실제 경계다.
- **미확인 항목의 최신성 구간(0.75)**을 밟는 테스트가 없었다.
- e2e가 문구를 하드코딩해 세 곳이 문안 수정으로 깨졌다. 메시지 파일에서 읽도록 바꿨다 — 그 테스트들이 확인하는 것은 문구가 아니라 요소의 존재다.

## 8. 남은 것 — 사람이 정할 것 하나

### 대여 항목이 「가져온 사람」에게도 critical이다

`MATRIX`에서 `wheelchair`는 P1a에, `stroller`는 P3에 **critical**이다. 그런데 그 두 조건의 문구는 「휠체어를 **이용해요**」, 「유아차와 **함께** 가요」 — 이미 가지고 있다는 뜻이다. 대여가 없다고 확인되면 **가져온 사람에게도 「다른 곳 권장」**이 나간다.

실측: **서동공원과 궁남지 / 유아차 동반 → 대체추천, 유일한 차단 항목이 `stroller`.** 근거는 「유모차 대여 여부 - 없음」이다.

v7이 엘리베이터에 대해 편 논리와 같은 모양이다 — 대여는 **수단**이고, 방문자는 이미 **결과**를 가지고 있다. 다만 이것을 고치면 13곳의 발행된 판정이 움직이고 `docs/spec/06_suitability.md` §4.3 표가 바뀐다. **공개되는 판정을 바꾸는 일이라 결정으로 올린다.** 권고는 둘 다 `C` → `S`다.

### 그 밖에 코덱스가 남긴, 이번에 안 고친 것

- `휠체어 대여 안 합니다` → `supported`, `휠체어 대여 예정` → `supported`. `NEGATION`이 `안 합니다`를 모르고, 맨 `대여`가 긍정 근거로 충분하며, 「예정」을 읽는 규칙이 없다. **HEAD에서도 틀려 있었다.**
- `path_continuity`가 경로 파일만 있으면 `partial`을 낸다. 항목의 계약은 「모든 필요 지점이 조건부로 도달 가능」인데, 파일 자신의 문장은 「이 경로 밖은 확인하지 않았다」이다. 그건 `unknown`이다.
- 기상 항목에 유효기간이 없다. 보존된 스냅샷은 90일까지 만점 구간으로 「특보 없음」을 계속 말한다.
- 쉬운 글이 **관광지·로케일** 단위로만 조회돼, 한 장소의 모든 이야기가 같은 쉬운 글을 받는다. 지금은 쉬운 글이 하나도 없어 잠복 상태다.
- `경사가 완만하여 휠체어 이동 가능` → `unknown`. 코덱스는 `supported`여야 한다고 본다. 모호한 장벽이 긍정 판정을 막는 규칙은 `계단으로만 이동 가능`을 막으려고 일부러 넣은 것이라 그대로 뒀다 — **의견이 갈린 채로 남긴다.**
